# 申请表信息字段

按软著申请表表单顺序（与 SKILL.md 一致，字段顺序不可打乱）：

1. 软件取得方式（原始取得/继受取得，默认原始取得）
2. 软件全称（必填）
3. 软件简称（可选）
4. 版本号
5. 权利范围（全部权利/部分权利，默认全部权利）
6. 软件分类（应用软件/嵌入式软件/中间件/操作系统）
7. 软件说明（原创/修改（含翻译软件、合成软件），默认原创）
8. 开发方式（单独开发/合作开发/委托开发/下达任务开发）
9. 开发完成日期（指软件开发者将该软件全部固定在某种有形物体上的日期，YYYY-MM-DD）
10. 发表状态（未发表/已发表，默认未发表）
11. 著作权人（单位名称和统一社会信用代码证书号）
12. 开发的硬件环境（指开发登记软件的计算机硬件或专用设备，≤50字符）
13. 运行的硬件环境（指运行登记软件的计算机硬件或专用设备，≤50字符）
14. 开发该软件的操作系统（指开发登记软件的操作系统及版本，≤50字符）
15. 软件开发环境 / 开发工具（指开发登记软件的开发环境或开发工具，≤50字符，格式：开发环境: xxx/开发工具: xxx）
16. 该软件的运行平台 / 操作系统（指运行登记软件的操作系统及版本，≤50字符）
17. 软件运行支撑环境 / 支持软件（指运行登记软件的支撑环境或支持软件，≤50字符）
18. 编程语言（从列表选择开发登记软件用到的所有编程语言）
19. 源程序量（指登记软件源程序的总行数或者总条数，纯数字不含"行"字）
20. 开发目的（不超过50字）
21. 面向领域 / 行业（登记软件面向或适用的行业或领域，≤50字）
22. 软件的主要功能（全面、准确、概括地描述登记软件的主要功能，不超1300字、不少于500字）
23. 软件的技术特点（准确描述登记软件的技术特点，不超100字）

## 字段来源与填写口径

- 软件取得方式：原始取得/继受取得，默认原始取得。用户未指定时用原始取得。
- 软件全称：必填，必须显式确认；正式资料文件名、代码 Word 页眉、操作手册标题和正文中的软件名称均以申请表信息中的"软件全称"为准。
- 软件简称：可选；如有常用简称则填写。
- 版本号：必须显式确认；如果项目配置中的版本号小于 V1.0，需提醒用户软著首次提交通常写 V1.0，并让用户确认填写 V1.0 还是项目当前版本号。
- 权利范围：全部权利/部分权利，默认全部权利。
- 软件分类：应用软件/嵌入式软件/中间件/操作系统，默认选"应用软件"。注意选项是"操作系统"，不是"系统软件"。
- 软件说明：默认"原创"。修改（含翻译软件、合成软件）需用户确认。
- 开发方式：单独开发/合作开发/委托开发/下达任务开发，多个著作权人单位时通常为合作开发，需要用户确认。
- 开发完成日期：指软件开发者将该软件全部固定在某种有形物体上的日期，必须使用 YYYY-MM-DD 格式。
- 发表状态：默认未发表；已发表需附首次发表日期。未发表时首次发表日期留空。
- 著作权人：必须同时填写单位名称和统一社会信用代码证书号，不能只写单位名称。多单位格式如“单位A，统一社会信用代码：代码1、单位B，统一社会信用代码：代码2”，生成合作开发协议时按顿号/分号拆分单位块并去掉信用代码提取纯单位名。
- 开发该软件的操作系统：≤50字符，填写实际开发电脑的操作系统版本。
- 软件开发环境 / 开发工具：≤50字符，格式 `开发环境: <OS>/开发工具: <IDE>`，例如 `开发环境: Windows 11/开发工具: Visual Studio Code`；不要填写 React、Next.js、Vite、TypeScript 等技术栈。
- 该软件的运行平台 / 操作系统：≤50字符，填写软件运行所在的操作系统或浏览器环境。
- 软件运行支撑环境 / 支持软件：≤50字符，直接列出运行依赖（如 Node.js、npm、浏览器），不加格式前缀。
- 开发的硬件环境：≤50字符，优先读取当前电脑 CPU、内存、硬盘配置作为建议值。
- 运行的硬件环境：≤50字符，默认可沿用开发硬件建议值，也可按实际运行设备填写。
- 编程语言：从列表选择开发登记软件用到的所有编程语言；应包含项目用到的所有编程语言，包括前端语言如 JavaScript/HTML/CSS、后端语言如 Java/Python/Go/PHP、数据库语言如 SQL 等。
- 源程序量：只填纯数字（不含"行"字），指登记软件全部源程序的总行数（非仅代码材料抽取行数）。
- 开发目的：不超过50字，用一句话说明软件开发目的，不能只写软件名称。
- 面向领域 / 行业：不超过50字。
- 软件的主要功能：全面、准确、概括地描述，不超1300字、不少于500字。
- 软件的技术特点：不超过100字，准确描述技术架构和关键技术。

## 一致性要求

- 软件全称和版本号必须与代码材料、操作手册一致。
- 正式代码 Word 页眉软件名称必须与申请表信息中的"软件全称"一致，生成 Word 时以申请表软件全称为准。
- 正式代码 Word 页眉版本号必须与申请表信息中的"版本号"一致，生成 Word 时以申请表版本号为准。
- 主要功能必须来自当前项目，不得沿用范本中的旧项目描述。
- `待用户确认` 字段在正式输出前应尽量替换为确认值；如仍存在，必须写入生成报告。
- `申请表信息.md` 必须严格按上述 1~23 的字段顺序排列，不得自行增删或打乱顺序。
