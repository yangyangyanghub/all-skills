# 土地执法业务表（多阶段审核）统计 · 子类型 B

本技能处理**业务表**——县级填报后从业务系统导出的工作表（大运河排查、专项整治、变更调查等），以「状态(系统) + 审核阶段(系统) + 打回状态(系统)」为主轴跟踪流程进度。**没有**"图斑状态/拆分状态/整改情况"列。

> ⚠️ **子类型识别**：若源表入口是「图斑状态+拆分状态」，不是业务表，应改用 **`land-law-enforcement-stats-weipian`** 子技能（卫片检索明细表）。

## 一、状态机映射

### 1.1 `状态(系统)` 列

| 编号 | 文字 | 含义 |
|:---:|------|------|
| 1 | 未处理 | 线索下发到系统，县级还没人接 |
| 2 | 未提交 | 县级已开始处理，但未提交 |
| 4 | 已提交 | 县级已提交，等待市级审核 |
| 10 | 已审核 | 流程已走到审核结束或被审核动作触及 |

### 1.2 `审核阶段(系统)` 列（**主轴**）

| 编号 | 文字 | 含义 |
|:---:|------|------|
| 101.0 | 审核结束 | 流程终态，可视为通过 |
| 90.0 | 已打回 | 任意环节被打回 |
| 95.0 | 市级待审核 | 县级已提交，市级还没审 |
| 97.0 | 省级待审核 | 市级已过，省厅待审 |

### 1.3 `打回状态(系统)` 列

| 编号 | 文字 | 含义 |
|:---:|------|------|
| 0.0 | 市级待审核 | 还没被打回 |
| 1.0 | 已打回 | 已被打回 |

> 空白值(NaN) 表示该阶段字段未触发——通常 `审核阶段=NaN` 时 `状态(系统)` 才有值。

## 二、业务判定规则

| 业务概念 | 判定条件 | 公式 |
|---------|---------|------|
| 县级填报 | 县级已开始走流程 | `审核阶段 ∈ {101, 90, 95, 97}` |
| 市级已审核 | 市级已做出动作（含打回） | `审核阶段 ∈ {101, 90, 97}` |
| 省级退回 | 省级打回但市级未撤回 | `审核阶段 == 95 且 打回状态 == 1.0` |
| 审核结束 | 通过终态 | `审核阶段 == 101` |

```python
县级填报 = 审核结束(101) + 已打回(90) + 市级待审核(95) + 省级待审核(97)
市级已审核 = 审核结束(101) + 已打回(90) + 省级待审核(97)
省级退回 = 审核阶段=市级待审核(95) 且 打回状态=已打回(1.0)
```

### 2.1 变更调查日报规则（v1.4 特化）

| 业务概念 | 判定 |
|---------|------|
| 流转 | 县级行政区名称非空 |
| 处置 | 仅审核阶段=101.0 审核结束 |
| 在途 | 已打回(90) + 市级待审核(95) |
| 已填报 | 审核结束(101) + 已打回(90) + 市级待审核(95) + **省级待审核(97)** |
| 未填报 | 总线索 - 已填报 |
| 填报率 | 已填报 ÷ 总线索数 |
| 差错率 | 已打回 ÷ 已填报（分母 0 时留空，不写 0） |
| 公式 | 总线索 = 审核结束 + 已打回 + 市级待审核 + 省级待审核 + 未填报 |
| 县分组 | **行政区名称**列（不是县级行政区名称） |
| 排序 | 按未填报降序（找欠账最多县先催） |

> 🔴 **2026-09-11 修正**：97 省级待审核**属于已填报**（县级已填、市级已过、等省级审）。旧版「未填报 = 总 - 101 - 90 - 95」**把 97 误算进了未填报**（是"多算"，不是"漏算"），导致未填报虚高 1（09-11 肥乡区踩中）。修正后 97 归入已填报，未填报 = 总 - (101+90+95+97)。
>
> 同时修正**假校验**：旧版未填报由减法得出，再拿加法校验恒等成立，等于没校验。现改为按各阶段实际计数求和比对总数，不一致会打印异常县行。

> 🔴 **口径定档（洋哥 2026-09-11 拍板）**：「已填报」**仅计审核阶段 ∈ {101, 90, 95, 97}**，**不含**「状态(系统)=4 已提交但审核阶段为空」的图斑——这类图斑**计入未填报**。
>
> 背景：09-11 数据有 58 宗「状态=4 已提交、审核阶段空」，实证 64% 已填核实认定意见（状态=1/2 仅 2.4%），语义上像"已填报"，但洋哥定档**仍按审核阶段口径**，保持与历史报告一致。若改为含状态=4，全市填报率会从 13.5% 跳到 19.1%（鸡泽县 2.4%→90.5%）。**未经洋哥确认，不得改回含状态=4 口径。**

### 2.2 状态文字转换（写 Excel 必转）

源数据是数字，**直接写 Excel 会让用户看懵**，输出前必须转文字：

```python
STATE_TEXT = {1: '未处理', 2: '未提交', 4: '已提交', 10: '已审核'}
SEND_BACK_TEXT = {0.0: '市级待审核', 1.0: '已打回'}
```

**优先以「审核阶段(系统)」语义为准**——`状态=10` 涵盖太广，叠加 `审核阶段` 才能区分「已审核-审核结束」「已审核-已打回」等子态。

### 2.3 「是否通过审核」判定

| 审核阶段 | 是否通过 | 文字 |
|---------|:---:|------|
| 101.0（审核结束） | ✓ | 通过 |
| 90.0（已打回） | ✗ | 未通过 |
| 95.0（市级待审核） | ? | 未通过 |
| 97.0（省级待审核） | ? | 市级已过、省级待审（**不算完成整改**） |
| NaN（未提交/已提交/未处理） | — | 待填报 |

> **2026-09-07 修订（洋哥定档）**：业务表的"完成整改"**只看 101 审核结束**，97 省级待审核虽然在「是否通过」语义上算"✓"，但**业务上不视为完成**——省级还没最终审核，不能算"已整改完成"。如果 97 阶段市级已通过 + 省级已通过，自然会进入 101。**判定公式**：`完成整改 = 审核阶段 == 101`。

## 四、地类映射规则（v1.4 重要）

**与「三调用地代码名称对照表」(旧表) 不一致的，以旧表为准**——洋哥 2026-09-03 定档。

- 旧表（`D:\Desktop\三调用地代码名称对照表.xlsx`）作为权威基础（80 项）
- 旧表没有的代码（如 `0602C` 矿产资源开采用地、`0602K` 矿产资源勘查用地）才用更正版补充
- 不覆盖旧表已有项

```python
# 规则：旧表优先 + 更正版仅补充缺失
code_map = 旧表(80项)
for 更正版新增代码 in (0602C, 0602K):
    if code not in code_map: code_map[code] = name  # 只补不覆盖
```

**踩坑记录**：
- 源表用 H 后缀编码（05H1/08H2/0810A）+ 旧 4 位（0307/0508/09），是**过时编码体系**；更正版是纯数字 4 位新国标

- 源表 `09` 特殊用地 = 更正版 `09 → 0901-0906` 拆分，但**源表数据是 09，映射用 09 = 特殊用地**（旧表）

## 五、执行流程

```
1. 读取 Excel，子类型识别
   ├─ 含「状态(系统)」「审核阶段(系统)」→ 业务表流程
   └─ 含「图斑状态」→ 转 weipian 子技能

2. 状态文字转换（1.1-1.3）
3. 业务判定（二 业务判定规则）
4. 逐县汇总 / 图斑明细（三 输出格式）
5. 排序（未填报降序 / 县级填报→是否通过→县→乡镇）
6. 样式（3.3）
7. 输出文件到原文件同目录
```

> 🔴 **STOP · 子类型识别歧义时强制确认**：若列名既无「图斑状态」也无「状态(系统)」（识别失败），**禁止自行假设**，必须先问用户：①这是什么类型表 ②入口字段是哪列 ③业务判定规则。识别错了会整套统计报废，宁可多问一次。

### 5.1 失败模式 fallback（if-then 三段式）

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 脚本读 Excel 报 KeyError（列名缺失） | 打印源表所有列名，对照 1.1-1.3 映射表核对入口字段是否拼写一致（如 `状态(系统)` vs `状态（系统）` 全半角）| 截图列名给用户确认，暂不输出 |
| 写 Excel 报 PermissionError（WPS/Excel 打开着目标文件） | 提示用户关闭 WPS/Excel 再跑 | 换用带时间戳的新文件名（`_YYYY-MM-DD`）避免锁文件 |
| 输出文件被旧同名文件覆盖风险 | 改前**必须备份**源文件 `_backup_YYYY-MM-DD` 后缀 | 备份失败则中止并告知，不覆盖 |
| 地类代码匹配不到（出现 `xxx (?)`）| 查询旧表+更正版对照表；确认是全半角/大小写问题 | 把未匹配代码清单给用户，人工补对照表 |
| 某县聚合字段全 0 | 检查是否用错分组列（应`行政区名称`非`县级行政区名称`）| 打印该县原始行，人工核对 |

## 六、实战案例

### 6.1 大运河排查（2026-09-03）

134 个图斑，3 县（大名93/魏30/馆陶11）。89 条审核阶段空（未填报），35=101，8=90，2=95。输出 2 Sheet，文件名 `大运河排查图斑清单_2026-09-03.xlsx`。

**踩坑**：一批次用 9 位短编号(130425027)，源表混 9/13 位——匹配**字符串全等**，不能截断；改源表前**必须备份** `_backup_YYYY-MM-DD` 后缀。

### 6.2 变更调查日报（2026-09-03）

860 个图斑，17 县（邯郸 18 区县中除广平）。状态机：未处理247/未提交466/已提交110/已审核37。审核阶段：13 审核结束 + 24 市级待审核 + 66 已打回。**行政区名称 860 全非空**（用这个分组，不是县级行政区名称）。

**日常更新流程**：①新源 xlsx 覆盖到原路径 → ②跑脚本生成新日期文件名日报 → ③历史日报不删（按日期归档）→ ④WPS/Excel 打开日报后必须关闭，否则跑会被锁（PermissionError）。

## 七、注意事项

| 错误 | 正确 |
|------|------|
| 看到 Sheet 名"图斑列表"就当卫片表 | 必须看入口字段：`图斑状态`=A / `状态(系统)`=B |
| `状态(系统)=10` 直接写 Excel | 转文字，叠加 `审核阶段` 区分子态 |
| `打回状态=0.0` 写 Excel | 转文字 `市级待审核`（空白保持空白） |
| 只看 `审核阶段=101` 计数 | 县级填报应含 90/95/97（101+90+95+97） |
| 按面积降序 | 业务表按 `县级填报→是否通过→县→乡镇→阶段` 排 |
| 整列覆盖 | 按图斑编号逐条匹配，仅改目标列 |
