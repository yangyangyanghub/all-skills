## Step 1 — Framework Design

**Deliverable**: Framework-level design document (no per-page details yet)。
Step 1 结束必须获得用户明确确认（门控），才可进 Step 2。门控**必须用 question 工具 组件实现**（文案含默认兜底说明「30秒内未选择默认方案1」），**禁止用纯文本提问代替**。

### 1.1 Basic Info & Learner Profile（基本信息 + 学情画像）

学科、主题、年级、课时时长。用户已明确给出则直接使用；否则主动询问。

**学情画像（硬规约 #16，v1.4.1 新增）**——「联系学生经验」原则的落地起点：

- AI 按**年级 + 学科**，从 [`experience-anchors.md`](experience-anchors.md) 经验域库**自动生成**「学生经验域清单 + 情感激发候选 3~5 个」，**不询问用户**（最小必要付出原则）；
- 门控确认时，将学情画像与框架设计**一并**请用户确认/替换——老师只做选择题，不做填空题；
- 输出格式：

| 项 | 内容 |
|----|------|
| 学生经验域 | 3~5 个具体领域（如：手游抽卡机制 / 短视频推荐 / 校运会排名 / 快递柜取件） |
| 情感激发候选 | 3~5 个（如：抽卡不出货的懊恼 → 概率公平性问题） |
| 避开项 | 过时热梗、区域限定内容、敏感争议话题（按经验域库选用规则） |

- 用途：① 前测题干情境（§1.3.1 要素④）；② 每页经验锚点（§1.2/§2.1）；③ 举例与巩固题情境（§1.3.2）；④ 前沿连接的切入点（§2.1.2）。

### 1.2 Knowledge Modules & Page Plan

- 拆 **3–6 个知识模块**；每模块 = 讲授页 + 中测（「讲一段测一段」）。
- **全 10–18 页**；仿真页 **1–3 个**（每个关键概念最多 1 个仿真，3 个以上拖慢课时）。
- 测验页：1 前测 + N 中测 + 1 后测。中测数量**按需**（1 课时通常 1–2 个、2 课时 2–3 个），**不是每模块必配**。相邻测验严禁连排（见 1.3.0）。
- 输出**页面列表表格**：#、type、module、功能简述、**经验锚点**、**动画**（yes/no，讲授页标注揭示步数预估）。

Page types: `cover`, `pre-test`, `teach`, `sim`, `mid-test`, `post-test`, `summary`。

### 1.2.1 经验-情感主线设计（硬规约 #16）

全课件一张「动机线」表——把「联系经验、激发情感」从零散技巧变成可审核的设计主线：

| 模块 | 引入现象/经验锚点 | 认知冲突或情感触发器 | 知识落点 | 前沿/真实世界连接（编织处） |
|------|------------------|---------------------|---------|---------------------------|
| M1 | 学生可感知的具体事物/现象/事件 | 让学生直觉出错或惊奇的问题 | 本模块核心概念 | 引入处 / 讲解处 / 总结处（三选一或组合） |
| M2 | … | … | … | … |

规则：

- **每模块必须有 1 个引入现象**：从学生可感知的事物/现象/事件出发，禁止模块开头直接抛定义/公式；
- 每个认知冲突/悬念必须在**当模块内解开**（情感服务认知，禁只煽情不解惑）；
- **前沿连接采用编织式**（2026-10-12 定案）——融入**引入**（以真实应用/新闻钩住注意）、**讲解**（"这个性质正是 XX 产品/现象背后的原理"，一句带过）、或**总结**（"从这里放眼：前沿与你未来的选择"），**禁止做成独立页或挂件卡片**；全课件累计 ≥1 处即可，多多益善；
- 前沿内容的数据必须可靠（复用 §2.1 数据准确性规则）。

### 1.3 Quiz System

| Type | Position | Purpose | Style | Count |
|------|----------|---------|-------|-------|
| **前测** | 封面后、新内容前 | 摸底已有经验、暴露前概念。**绝不考未学内容** | "What do you already know about…" | 3–5 |
| **中测** | 每模块后 | 辨析（区分相似概念）+ 初步应用 | 干扰项针对该模块常见误解 | 3–5 each |
| **后测** | 全部内容后、总结前 | 跨模块综合；与前测对照 | 回忆+应用+迁移混合 | 5–8 |

> **⚠ 题型硬规则**：前测/中测/后测**一律只用选择题**（单选/多选，题干用 `.q-type` 徽章标注；多选题须 100% 与答案一致才算对）——连线/配对/分类题不计入任何测验环节，仅用于讲授页末尾的及时巩固（见 1.3.2 规则二）。发布版（提交模式）只有提交后才显示答案与解析。

### 1.3.0 测验分布硬规则

| 规则 | 内容 |
|------|------|
| **① 中测数量按需** | 1 课时通常 1–2 个中测、2 课时 2–3 个；内容少/课时紧就减少，把相近模块合并为一个中测 |
| **② 相邻测验严禁连排** | 任意两个测验页之间**必须至少隔一个讲授页或仿真页**。页面列表中任意两个测验 type 相邻 = 违规 |
| **③ 前测/后测固定位置** | 前测固定封面后（首个讲授页前）；后测固定全部讲授后（总结页前） |
| **④ 违反②的处理** | a) 两者之间补一节讲授/仿真；或 b) 合并/删减一个中测。绝不保留连排 |

**自检**：页面列表中 `pre-test` / `mid-test` / `post-test` 任意两个 type 相邻即违规。

### 1.3.1 前测设计硬规则

前测**唯一目的**是摸清学生已有经验与误解，**绝不**涉及任何本课新知。症状：题干/选项/答案出现本课专属术语（如矩阵课出现「系数方阵」）。

**每道前测题必须满足四要素**：

| # | 要素 | 含义 | 反例（违规） |
|---|------|------|------------|
| ① | **已有经验** | 学本课前就具备的常识/技能/日常经验（不含本课术语） | 用「已知矩阵 A」开头——矩阵是本课新知 |
| ② | **暴露前概念** | 通过选项揭示朴素直觉或常见误解 | 题干暗示正确答案（本课术语写在正确选项里） |
| ③ | **关联本课新知** | 该题调动的已有经验正好是本课某核心概念的「先前锚点」 | 选题与本课完全无关，纯属凑数 |
| ④ | **情境喜闻乐见** | 题干情境取自学情画像的经验域清单，用学生熟悉的事物承载 | 无来由的杜撰情境（如抽象的"小明"）、学生无感的陈旧案例 |

**实战模板（以终为始）**——先列本课核心概念，再反推已有经验：

| 本课核心概念 | 已有经验 | 前测问法（不出现本课术语） |
|-------------|------------------|------------------------|
| 矩阵加法 | 向量/坐标「对应分量相加」 | 「a=(1,2), b=(3,4)，a+b = ?」 |
| 矩阵即「数表」 | 数据排表格的习惯 | 「6 个数要同时记下，怎么排最清楚？」 |
| 乘法不交换 | 函数复合/变换顺序影响结果 | 「g(f(x)) vs f(g(x)) 相同吗？」 |
| 数乘 | 「每个成绩×2」 | 「把成绩表每个分数翻倍，怎么做？」 |

**自检清单（每道题提交前逐条确认）**：

- [ ] 题干**无任何本课术语**（含以此命名的概念）
- [ ] 正确选项**不需本课新知即可选出**
- [ ] 错误选项也是基于已有经验可能选的，不是本课内容预告
- [ ] 每题能说出对应本课哪个核心概念
- [ ] 解析**不用本课术语做前向提示**（用「本节课研究的对象」等中性表述）
- [ ] 题干情境取自**学情画像的经验域**（喜闻乐见、非杜撰）——四要素④

### 1.3.2 题型使用位置硬规则

**规则一：前测/中测/后测一律只用选择题**

连线/配对/分类题难以结构化计分统计，测验环节禁止：

| 选择题型 | 数据格式 | 判定规则 | 题干标注 |
|---------|---------|---------|---------|
| **单选题** | `{ answer: 0, explain: '...' }` | 选中索引 = answer 即正确 | `<span class="q-type">单选题</span>` |
| **多选题** | `{ multi: true, answer: [0,2], explain: '...' }` | 点「确认本题」锁定；**100% 一致才算对** | `<span class="q-type multi">多选题</span>` |

- `.q-type` 徽章必配（样式 quiz-engine.js 自动注入）；多选题 `.opt-confirm` 按钮必配
- 自检：测验页出现 `initMatching` / `initClassification` = 违规

**规则二：连线/配对/分类题仅用于讲授页的及时巩固**

在 teach page 讲解内容之后放**一道**连线/配对/分类题，动手巩固：

| 题型 | 交互 | 实现 |
|------|------|------|
| **连线/配对题** | 点左项→点右项→SVG 连线；对绿错红（线保留可重连）；右侧自动打乱 | `matching-quiz.js` 的 `initMatching()` |
| **分类题** | 拖拽卡片到分类桶（Pointer Events 通用）；对则滑入变绿，错则红框抖动弹回 | 同上 `initClassification()` |

**巩固题内容硬规则（防照抄）**：巩固题内容**不得与该页讲解内容一样**——必须换情境、换例子或部分迁移（讲解用「医疗检测」讲贝叶斯，巩固题改用「垃圾邮件过滤」）。且新情境必须取自经验域库、与讲解例属于**不同经验域**，两者均须在学情画像的经验域清单内。自检：巩固题文字与讲解正文**逐字相同即违规**；新情境不在学情画像经验域内 = 违规。

**动态交互实现要求**（禁止纯静态列表）：
- 统一 **Pointer Events**（`pointerdown/move/up` + `touch-action:none`），禁止只响应 `mousedown` 或纯 click 假交互
- 每题配「重试」按钮；完成时给成功反馈与 `onDone(score, total)` 回调
- 在 `onPageEnter('pN')` 调用初始化（`_initialized` 组件级守卫 + `pageEntered` 页面级守卫，双层冗余防御）
- 引擎自注入 CSS；**用到的课件须在 skeleton `<script>` 引用注释中加 matching-quiz.js 一行**
- 巩固题保持即时反馈（不进结构化统计）；每页 ≤1 道

**规则三：正确答案位置必须打散（防呆，硬规约 #19）**

同一测验（前测 / 各中测 / 后测**各算一个测验**，即 QUIZZES 的每个 key）内，正确答案**不得全部集中在同一选项位置**——典型病症是「全 A」或「全 B」。出题时**主动打散**：把正确项轮换到不同位置；**多选题的正确答案组合也不得每题都含同一位置**。

- **校验（必做）**：出题后跑 `node scripts/quiz-answer-check.js <课件.html>`（或指向工作区目录，递归扫描）——须 `RESULT: PASS`。
  - `FAIL` = 该测验**全部**单选题答案落在同一位置（默认 ≥3 题即判）；`WARN` = 高占比（≥5 题且某位置 ≥80%）或多选题每题均含同一位置。
  - 阈值可调：`--min-q <n>`（触发全集中判定所需最少题数，默认 3）、`--max-ratio <r>`（高占比告警阈值，默认 0.8）。
- **修法**：命中即**逐题打散选项顺序，并同步修改该题 `answer`**（单选题为数字、多选题为数组）。**只改选项显示顺序、不改答案语义集合**，故不影响作答判定、统计与历史数据。
- 自检：任一测验内全部单选题 `answer` 数值相同 = 违规。

**五条图片硬规则**：

> **规则0 · SVG 优先（知识图表类）** — 凡属**知识图表**（概念图/流程图/关系网络/示意图/公式图/带中文标签/需精确排版），**一律内联 SVG 手绘，不用 AI 生图**。理由：中文精确、零成本、自包含、布局可控。仅当需要写实/艺术感（实景/人物/复杂光影/真实场景）才走 AI 生图。

> **规则A · AI 生图统一走 image-service** — 勾选「AI 生图」后**不再询问引擎**，直接调用本机 **image-service 技能**：写实/场景图用 `core/text_to_image.py`（支持 10 种比例、参考图风格）；含中文文字的图生成后用 `core/image_to_text.py -m ocr` 校验文字。方案表「生图引擎」列统一填 `image-service`（不得留空、不得写其他引擎名）。

> **规则B · 图文混排布局** — 有图有文页面**禁止图片堆底部**：宽幅信息图→紧跟相关段落全宽居中；4:3 机制图/肖像→与文字浮动并排；每图配 caption；移动端 ≤768px 浮动图自动降级全宽堆叠。CSS/HTML 见 §2.3.3。

> **规则C · 图片文字纯中文** — AI 生成图片内所有文字必须 100% 纯中文，杜绝任何英文（含装饰性英文）。唯一例外：英语课（中英对照教学）。执行：① 提示词显式声明；② 生成后逐图检查英文残留，发现即重生成；③ 与规则0/规则A 并行不冲突。

> **规则D · 知识理解图必须是信息图（AI 生图路径）** — 图文结合、图像精美准确、文字精简（忌大段文字/纯文字海报）。① 提示词末尾必须显式声明 "All text in the image must be in Simplified Chinese. No English text."；② 与规则C 关系：C 约束呈现语言，D 约束提示词声明与图形态；③ 与规则0 边界：知识图表仍首选 SVG（规则0 优先于规则D）。

### 2.1.1 引入页设计硬规则（硬规约 #16）

引入 = 封面后的首个讲授页（模块 1 的首页），必须满足三要素：

1. **可感知现象**：学生每周接触到的具体事物/场景（大图或白描描述），取自学情画像经验域；
2. **认知冲突问题**：一个让学生直觉出错或惊奇的问题（前测已暴露的前概念在此正式登场）；
3. **知识预告悬念**：一句话指向本课要解决的真正问题（不出现本课新术语）。

禁止：定义/公式/术语表开头；无来由的虚构叙事开头。现象导入篇幅 ≤30% 当页，随即进入知识本身——**经验是入口，知识是目的地**（红线①，防"讲故事"异化）。

### 2.1.2 前沿连接（编织式，硬规约 #16）

- **形态（2026-10-12 用户定案）**：前沿连接**不是独立页或挂件卡片**，而是编织进既有环节的一段内容——
  - **引入处**：以真实应用/科技新闻钩住注意（"你每天用的 XX，背后是这节课的原理"）；
  - **讲解处**：知识成型后一句带过（"这个性质正是 XX 产品/现象背后的原理"）；
  - **总结处**：放眼延伸（"从这里出发：前沿进展与你未来的专业/职业选择"）。
- **数量**：全课件累计 ≥1 处，置于 §1.2.1 动机线表的「前沿/真实世界连接」列规划位置；
- **选材**：学生可感知的前沿（新闻/产品/职业/赛事/开源项目），优先选持续性强的应用而非速朽消息；
- **数据**：前沿内容的事实数字须有可靠来源（复用 §2.1 数据准确性规则——前沿页最易翻车）。

### 2.1.3 知识应用真实化（硬规约 #16）

- **后测 ≥1 道真实情境迁移题**：用本课知识解释生活现象 / 做估算 / 辨别新闻中的数据（与前测的"经验摸底"首尾呼应）；
- **仿真场景优先取真实系统**（导航、推荐、支付、疫情传播、赛事排名……）而非抽象数表；
- **应用任务句式**：「用本课知识解释/评估你身边的 ___」——把"做题"变成"解释学生的世界"。

### 2.3 Image Source Options — 图片来源弹窗（硬规约 #18）

> 课件一旦需要图像（非知识图表类），**必须用 question 工具弹窗**让用户选定来源——**禁止静默默认**。单阶段**复选（`multiple: true`）**允许的图像来源类别，**可多选、允许混用**（如"实景用网络图、图表用 SVG、写实用 AI 生图"）。
> **不进弹窗（两条恒例外）**：① 知识图表类（概念图/流程图/关系网络/示意图/公式图/带中文标签/需精确排版）**恒走内联 SVG（规则0）**；② 数学模型图恒走 Canvas。二者零成本、不占选项。

**勾选允许的来源类别（multiple: true，可多选）**：

| 复选框 | 名称 | 零成本？ | 适用范围 / 代价 | 前置条件 |
|:--:|------|:--:|------|---------|
| ☑ | **搜索网络图片** | ✅ | 真实照片/真实场景（CC0），无生成自由度 | 无 |
| ☑ | **内联 SVG 手绘（inline SVG）** | ✅ | 矢量、自包含、中文精确；**不支持写实/艺术/场景图** | 无 |
| ☑ | **AI 生图** | ❌ | 生成写实/艺术/场景图；走 **image-service** 技能 | `config/settings.json` 已配置（见 §2.3.1） |

- **默认兜底**：未选/取消/「继续」/「全自动」→ **三项全允许**，须声明。
- **混用分派**：勾多个类别时按图分派（真实照片→网络搜图；知识图表→内联 SVG（规则0）；写实/艺术场景→AI 生图；网络搜图失败→回落 AI 生图）。
- **术语澄清（易混）**：**「内联 SVG」= 在 HTML 里用 `<svg>` 标签手绘矢量图**（复选框二）；**不是 Canvas**。Canvas（`<canvas>`+JS）在本技能中特指**可交互数学模型图**（§1.5 五类图片的 b 类）；两者是不同技术，勿混称「canvas 画 svg」。
- 选定后输出确认：`📍 图片来源：<所勾类别，逗号分隔>；AI 生图走 image-service`，并说明费用（若有）。
- Prompt 模板与写作规则见 [`templates/infographic-generator.js`](templates/infographic-generator.js)。

#### 2.3.1 AI 生图路径 · image-service 技能（唯一引擎）

**调用本机 image-service 技能**（OpenCode 技能目录 `.opencode/skills/image-service/`），配置在 `config/settings.json`（API 地址+密钥，装技能时已配置）。执行前自检配置存在（**不回显密钥值**）：

```bash
python -c "import json,sys; c=json.load(open(r'.opencode/skills/image-service/config/settings.json',encoding='utf-8')); print('IMAGE_CFG_OK' if c.get('api_key') or c.get('apiKey') else 'IMAGE_CFG_MISSING')"
```

若未配置 → 引导用户编辑 `config/settings.json` 填入 OpenAI 兼容图像 API 的地址与密钥（**密钥只存该配置文件，严禁写进课件 HTML / 课件内 JS / 任何随课件分发的文件**）。

**生成方式**（产物落课件 `deploy/img/`，中文提示词直接写中文）：

```bash
# 写实/场景/艺术图 — core 文生图（比例 10 种可选）
python .opencode/skills/image-service/core/text_to_image.py "<中文描述>" -r 16:9 -o deploy/img/xxx.png

# 知识理解图需信息图形态（规则D）— 信息图场景（20布局×17风格）
python .opencode/skills/image-service/scenes/infographic/zlab_infographic.py -l {布局} -s {风格} -n "<标题>" -c "<内容>" -o deploy/img/xxx.png
```

- **含中文文字的图**：提示词追加 `guides/text-rendering.md` 的文字清晰后缀；生成后用 `core/image_to_text.py -m ocr` 校验图内文字，不符即用 `core/image_to_image.py` 迭代修复（正好落实"逐图验证"硬要求）。
- **每次生图直接全部生成，不做小样先行**（除非用户要求先看样张）。
- **三坑**：① Windows 下路径用正斜杠或原始字符串传参；② OCR 校验不过先改提示词重生成，勿反复图生图叠加伪影；③ 并发上限 ≤8 张，多图建议串行保风格一致。

> **Verify each image**: 数值、箭头方向、文字准确。错了就重生成——绝不上线「差不多」的图。

#### 2.3.3 图文混排布局 — 硬规则

| 图片形态 | 布局方式 | 说明 |
|----------|----------|------|
| 宽幅信息图（16:9） | **全宽居中**（`class="page-img"`） | 紧跟对应段落之后 |
| 4:3机制图/示意图/肖像 | **浮动并排**（`.fig.float-l/r`） | 文字环绕，边读边看 |
| 任何图片 | 配 **caption** | 图文对照 |

可复用 CSS 已内置于 [`courseware-skeleton.html`](templates/courseware-skeleton.html)「图文混排」区块（`.clearfix`/`.fig`/`.page-img`/`.img-caption` + 移动端降级），从骨架复制即自动获得。

```html
<div class="clearfix">
  <div class="fig float-r">
    <img src="img/xxx.jpg" alt="图片内容简述">
    <p class="caption">图片说明文字</p>
  </div>
  <p class="teach-text">环绕正文段落…</p>
</div>
```

布局参考：实验/流程信息图→宽图全宽居中；机制示意图→浮动并排配 4-5 条文字；肖像→左浮 30-35% 右配简介；概念对照图→浮动并排右配辨析卡片。

**嵌入后自检**：① 图片与对应文字并排/相邻（非堆底）？② 每图有 caption？③ 移动端浮动图降级全宽正常？
