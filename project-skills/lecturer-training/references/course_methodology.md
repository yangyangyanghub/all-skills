# 讲师训练营课程方法论

## 何时读取

当任务涉及课程定位、主题制定、课程大纲、材料筛选、教学脚本、讲师训练或课程评审时读取本文件。本文件只基于本地讲师训练营 Markdown 语料摘要提炼，不补充外部理论。

## 1. 认知起点与终点

课程设计的第一步不是确定知识点，而是确定认知改变。

| 设计项 | 说明 | 产出 |
|---|---|---|
| 起点认知 | 学员现在如何理解这个问题，常见误区是什么 | 旧判断、旧习惯、旧解释 |
| 终点认知 | 学员听完后应该如何重新理解、判断或行动 | 新判断、新动作、新标准 |
| 中间阻力 | 学员为什么不会自然抵达终点 | 误解、经验惯性、信息缺口、信心不足 |
| 抵达证据 | 如何判断学员已经改变 | 能说出区别、能做选择、能完成练习 |

### 判断标准

好课程的目标不是「让学员知道某个概念」，而是「让学员面对某个场景时，能换一种判断方式」。

不够好的目标：

- 了解课程设计方法。
- 掌握讲师表达技巧。
- 学习如何找材料。

更可用的目标：

- 能把一个知识主题改写成一张认知改变地图。
- 能把资料堆砌的大纲改成一条学员可跟随的路线。
- 能判断一个案例是否真的推动认知台阶。

## 2. 知识角色

语料摘要中的核心判断是：知识不是课程的全部，知识是学员要攀登的山；讲师不是搬运知识的人，而是带路的人；课程结构不是目录，而是路线。

| 元素 | 错误用法 | 正确角色 |
|---|---|---|
| 知识 | 逐条讲完、越全越好 | 山体：提供高度和方向 |
| 讲师 | 证明自己懂很多 | 向导：判断路线、控制坡度、提醒风险 |
| 结构 | 章节目录 | 路线：从起点走到终点 |
| 材料 | 故事、案例、金句装饰 | 台阶：让学员完成一次判断变化 |
| 互动 | 热场和活跃气氛 | 路标：确认学员是否跟上 |

## 3. 挑战设计

课程要从场景和挑战进入，而不是从概念进入。推荐结构是「场景 + 挑战 + 解决方案」。

### 挑战的三个条件

| 条件 | 判断问题 | 不合格信号 |
|---|---|---|
| 真实 | 学员是否遇到过或即将遇到 | 只有讲师觉得重要 |
| 有阻力 | 学员靠常识是否会失败 | 一听就会，没有张力 |
| 可解决 | 课程能否给出具体走法 | 只制造焦虑，没有方法 |

### 挑战设计公式

```markdown
当你在【真实场景】中遇到【具体任务】时，通常会按【旧做法】处理。
但这个做法会导致【具体问题】。
这节课要带你学会用【新方法】解决【关键挑战】。
```

### 挑战分层

| 层级 | 作用 | 示例写法 |
|---|---|---|
| 总挑战 | 支撑整节课 | 如何把一堆知识材料变成能改变认知的一节课？ |
| 章节挑战 | 支撑一个模块 | 如何判断一个材料是台阶还是装饰？ |
| 练习挑战 | 触发学员动作 | 请把这个概念改写成一个真实场景问题。 |

## 4. 路线设计

路线设计要回答：学员从哪里出发，先过哪个坡，再过哪个坡，在哪里容易掉队，最后如何确认抵达。

### 路线四段式

| 阶段 | 课程功能 | 讲师要做的事 |
|---|---|---|
| 入山 | 暴露旧认知和真实挑战 | 用场景问题开场，让学员意识到旧做法不够用 |
| 第一坡 | 建立新框架 | 给出核心模型，例如「课程是认知改变」 |
| 第二坡 | 用材料练习模型 | 让学员筛材料、排路线、做不是而是建模 |
| 登顶 | 迁移到自己的课 | 让学员产出课程定位卡或路线大纲 |

### 坡度控制

- 每一段只解决一个认知难点。
- 抽象概念后必须接一个可操作练习。
- 材料数量服从路线需要，不以丰富为目标。
- 如果学员还没承认旧认知有问题，不要急着给新方法。

## 5. 材料选择

语料摘要强调「感官材料是认知步骤」。材料不是越多越好，而是要能让学员看见、听见、比较、操作，从而跨过认知台阶。

### 材料筛选表

| 筛选维度 | 保留 | 改写 | 剔除 |
|---|---|---|---|
| 是否服务挑战 | 直接帮助学员理解挑战 | 需要补场景才能成立 | 与挑战无关 |
| 是否推动判断 | 能让学员做比较或选择 | 只有故事性，需要加问题 | 只好听、不改变判断 |
| 是否可感知 | 能被看见、听见、比较、操作 | 需要改成图、表、动作或问题 | 只有抽象口号 |
| 是否可迁移 | 学员能套用到自己的课 | 需要补使用步骤 | 只适合原故事 |

### 材料改写方法

1. 给材料加场景：说明它发生在什么任务中。
2. 给材料加问题：让学员先判断，再看讲师怎么拆。
3. 给材料加对比：呈现旧做法和新做法的差别。
4. 给材料加动作：让学员排序、归类、拼图、改写或复盘。

## 6. 解决方案建模

解决方案必须具体，不能停留在「要重视」「要提升」「要做好」。语料摘要给出的可复用方向包括排序、拼图、递进、人物角色等方法。

| 方法 | 用途 | 课程里的用法 |
|---|---|---|
| 排序法 | 帮学员建立先后顺序 | 把材料、步骤、问题按课程路线重排 |
| 拼图法 | 帮学员看见整体结构 | 把场景、挑战、材料、练习拼成课程模块 |
| 递进法 | 控制学习坡度 | 从旧认知暴露到新模型，再到迁移练习 |
| 人物角色法 | 让抽象知识落到对象 | 明确讲师、学员、案例人物各自承担什么功能 |

### 建模输出要求

一个可用模型至少包含：

- 名称：让讲师和学员能记住。
- 使用场景：什么时候用。
- 操作步骤：先做什么，再做什么。
- 判断标准：做到什么程度算有效。
- 反例：什么做法看似相似但无效。

## 7. 课程结构模式

### 7.1 场景挑战型

适用于问题导向课程、企业内训、经验萃取。

```markdown
1. 开场：呈现一个真实任务和常见失败做法。
2. 挑战：指出旧认知为什么不够用。
3. 模型：给出新判断框架。
4. 材料：用案例或练习验证模型。
5. 迁移：让学员套用到自己的场景。
```

### 7.2 登山路线型

适用于知识复杂、材料多、需要重构大纲的课程。

```markdown
1. 起点：学员现在在哪里。
2. 第一坡：先改变哪个判断。
3. 第二坡：再补哪个能力。
4. 风险点：学员在哪里最容易误解。
5. 登顶：学员最终能完成什么输出。
```

### 7.3 不是而是型

适用于纠偏课程、认知升级课程、讲师表达训练。

```markdown
1. 不是：点出旧认知或表面做法。
2. 而是：提出新认知或本质做法。
3. 为什么：解释差别带来的结果变化。
4. 怎么做：给出具体动作。
5. 练一下：让学员改写自己的表达或方案。
```

### 7.4 3000 字专业知识讲清型

适用于短讲稿、微课、专业知识分享。

```markdown
1. 300 字：用场景和挑战开场。
2. 600 字：说明旧做法的问题。
3. 900 字：提出新模型和关键步骤。
4. 800 字：用材料、案例或练习展开。
5. 400 字：总结迁移方法和行动提示。
```

## 8. 课程评审标准

| 维度 | 好课程 | 风险信号 |
|---|---|---|
| 认知改变 | 起点、终点、阻力清楚 | 只有知识点，没有改变路径 |
| 挑战 | 真实、有阻力、可解决 | 开场只是背景介绍 |
| 路线 | 每段都有台阶功能 | 目录像资料分类 |
| 材料 | 每个材料推动判断 | 故事很多但不改变认知 |
| 方案 | 步骤具体，可练习 | 只给原则，不给做法 |
| 表达 | 有语言势能和转场 | 平铺直叙，缺少张力 |

## 9. 使用边界

- 以上方法来自本地语料摘要的归纳，不代表源材料的逐字摘录。
- 不能把示例句写成源文件原话。
- 用户没有提供真实案例时，只能生成结构、假设场景或练习题，不能编造事实经历。
