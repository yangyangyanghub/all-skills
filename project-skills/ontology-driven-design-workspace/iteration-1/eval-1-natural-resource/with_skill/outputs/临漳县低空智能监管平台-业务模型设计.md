# 临漳县低空智能监管平台 — 业务模型设计

> **文档定位**：可直接写入技术方案的业务建模章节，基于运营本体方法论（Ontology-Driven Design），用"对象 + 链接 + 操作 + 权限"四件套统一描述平台业务模型。
>
> **设计原则**：建模现实世界的监管业务，而非数据库表结构；AI 只做辅助发现线索，属性研判靠空间套合；问题闭环比展示大屏更重要。

---

## 一、对象类型（Object Types）

平台业务中涉及的现实实体和事件，分为**身份对象**（长期存在的实体）和**事件对象**（业务流转中产生的记录）。

### 1.1 身份对象

| 对象 | 说明 | 关键属性 | 可编辑 |
|------|------|---------|--------|
| **设备** | 无人机一机一档，平台最小执行单元 | 设备编号（主键，`LZ-UAV-{行政区划码}-{类别码}-{流水号}`）、外部ID映射（民航登记号/厂商序列号）、设备类型（多旋翼/固定翼/垂起）、所属单位、在线状态、最后维保日期 | 否（由设备管理系统同步） |
| **飞手** | 持证操作人员 | 人员ID（主键）、姓名、执照编号、执照等级、所属单位、联系方式、有效期 | 部分（人员信息可维护） |
| **地块/宗地** | 权属与地类最小空间单元 | 宗地编号（主键）、行政区代码、所在乡镇、所在村、地类编码、面积、权利人、权属来源 | 否（来源自然资源确权/三调数据） |
| **管理图层** | 套合研判用的空间管控数据集合 | 图层编号（主键）、图层类型（地类图斑/永久基本农田/生态红线/城镇开发边界/审批红线/国土空间规划）、数据版本、更新时间、数据来源 | 否（来源各业务科室） |
| **处置单位** | 承担核查/整改责任的组织 | 单位编码（主键）、单位名称、单位类型（乡镇政府/执法大队/自然资源所/农业农村局）、负责人、联系方式、管辖乡镇 | 部分 |

### 1.2 事件对象

| 对象 | 说明 | 关键属性 | 可编辑 |
|------|------|---------|--------|
| **任务** | 巡查或核查飞行任务 | 任务编号（主键）、任务类型（定期巡查/专项核查/应急飞行）、关联设备、关联飞手、计划航线、计划时间、实际起降时间、飞行状态（待执行/执行中/已完成/异常中止）、飞行时长、覆盖面积 | 部分（执行状态由系统自动流转） |
| **成果资产** | 飞行产出的原始数据 | 成果ID（主键）、关联任务、关联设备、数据类型（正射影像/倾斜摄影/视频/航迹点云）、采集时间、空间范围（bbox）、存储路径、数据大小、质量标记 | 否（系统自动入库） |
| **图斑/线索** | 变化检测发现的疑似变化区域 | 图斑ID（主键）、关联成果、空间几何（GeoJSON/WKT）、中心坐标、面积（㎡）、地类编码、AI识别类型（新增建筑/挖土/堆填/毁田等）、AI置信度、影像时相、套合结果摘要、研判状态（待套合/待研判/已认定/已排除） | 部分（研判状态流转、套合结果自动写入） |
| **问题台账** | 经认定后的正式监管问题 | 问题编号（主键）、关联图斑、问题类型（违法占地/违规建设/破坏耕地/超审批范围/设施农用地违规等）、涉及地块、责任主体、所在乡镇、严重程度（一般/较重/严重）、当前状态（待派发/处置中/待复核/已销号/已归档）、派发时间、整改期限、销号时间 | 是（闭环流转核心） |
| **操作日志** | 每个业务动作的审计记录 | 日志ID（主键）、关联对象、操作类型、操作人、操作时间、操作前状态、操作后状态、操作参数快照、备注 | 否（系统自动写入，不可修改） |

## 二、链接类型（Link Types）

对象之间的业务关系，每条链接双向有语义。

### 2.1 核心链接

| 链接名称 | 两端对象 | 正向语义 | 反向语义 | 基数 |
|---------|---------|---------|---------|------|
| **执行** | 任务 ↔ 设备 | 任务使用设备 | 设备执行任务 | N:1（一个任务用一台设备，一台设备可执行多个任务） |
| **操控** | 任务 ↔ 飞手 | 任务由飞手操控 | 飞手参与任务 | N:1 |
| **产出** | 任务 ↔ 成果资产 | 任务产出成果 | 成果来自任务 | 1:N |
| **发现** | 成果资产 ↔ 图斑 | 成果包含图斑 | 图斑来自成果 | 1:N |
| **认定** | 图斑 ↔ 问题台账 | 图斑转为问题 | 问题源于图斑 | N:1（多个图斑可合并为一个问题，一个问题可拆分多个图斑） |
| **坐落** | 问题台账 ↔ 地块/宗地 | 问题位于地块 | 地块存在问题 | N:M（一个问题可跨多个地块，一个地块可有多个问题） |
| **套合** | 图斑 ↔ 管理图层 | 图斑套合图层获取属性 | 图层被图斑叠加分析 | M:N |
| **管辖** | 问题台账 ↔ 处置单位 | 问题归属处置单位 | 单位负责处置问题 | N:1 |
| **归属** | 设备 ↔ 处置单位 | 设备隶属单位 | 单位拥有设备 | N:1 |

### 2.2 套合对象详表

套合是属性研判的核心手段，图斑与以下管理图层叠加后输出判断结论：

| 套合对象 | 套合目的 | 输出判断 |
|---------|---------|---------|
| 地类图斑（三调/年度变更） | 判断占用地类 | 耕地/建设用地/林地/园地/未利用地 |
| 永久基本农田 | 判断是否触碰底线 | 是否占用永久基本农田（是/否） |
| 国土空间规划 | 判断是否符合规划用途 | 是否符合规划管控要求 |
| 城镇开发边界 | 判断建设管控范围 | 集中建设区内/边界外 |
| 生态保护红线 | 判断生态约束 | 是否压占生态保护红线（是/否） |
| 审批红线 | 判断合法审批依据 | 未批先建/超范围建设/少批多占/合法 |
| 权属/宗地 | 判断责任主体 | 关联乡镇/村/单位/权利人 |

## 三、操作类型（Action Types）

操作是模型的灵魂——描述对象上能发生什么业务动作，以及每个动作的参数、验证、副作用、权限和审计要求。

### 3.1 闭环主流程操作

```
影像采集 → 智能识别 → 疑似图斑 → 自动套合 → 属性研判 → 派发 → 核查 → 整改 → 复核 → 销号归档
```

| 操作 | 触发对象 | 参数 | 验证规则 | 副作用 | 执行权限 | 审计记录 |
|------|---------|------|---------|--------|---------|---------|
| **创建任务** | 设备 | 任务类型、计划航线、计划时间、指定飞手 | 设备在线且未过期、飞手执照有效 | 创建任务对象、设备状态→已分配 | 监管中心、飞手所属单位 | 创建人/时间/参数 |
| **上传成果** | 任务 | 数据类型、文件、空间范围 | 任务状态为执行中或已完成 | 创建成果资产对象、关联任务 | 飞手、系统自动 | 上传人/时间/数据摘要 |
| **AI识别** | 成果资产 | 识别模型版本、阈值参数 | 成果质量标记为合格 | 创建图斑对象、写入AI识别类型和置信度 | 系统自动 | 模型版本/参数/识别数量 |
| **自动套合** | 图斑 | 套合图层列表、缓冲区设置 | 图斑已有AI识别结果 | 写入套合结果（地类/规划/红线/审批/权属） | 系统自动 | 套合图层版本/结果摘要 |
| **属性研判** | 图斑 | 研判结论（认定/排除）、研判说明 | 套合结果已写入 | 图斑状态→已认定或已排除；认定时创建问题台账 | 监管中心研判员 | 研判人/时间/结论/依据 |
| **派发** | 问题台账 | 处置单位、处置时限、处置要求 | 问题状态为待派发 | 问题状态→处置中、创建核查任务、通知处置单位 | 监管中心 | 派发人/时间/处置单位/时限 |
| **核查上报** | 问题台账 | 核查照片、核查说明、现场情况 | 问题状态为处置中、已派发 | 写入核查记录、问题状态→待整改或待复核（视情况） | 处置单位核查人员 | 核查人/时间/现场情况/照片 |
| **整改上报** | 问题台账 | 整改照片、整改说明、整改完成时间 | 问题状态为待整改 | 问题状态→待复核 | 处置单位/责任主体 | 整改人/时间/整改内容/照片 |
| **复核** | 问题台账 | 复核影像、复核结论（通过/不通过）、复核说明 | 问题状态为待复核、必须有整改上报记录 | 通过→问题状态→已销号；不通过→退回整改（问题状态→处置中） | 监管中心 | 复核人/时间/结论/影像 |
| **销号归档** | 问题台账 | 归档说明 | 问题状态为已销号（复核通过） | 问题状态→已归档、生成台账记录、锁定不可再编辑 | 监管中心负责人 | 归档人/时间/完整处置链 |

### 3.2 辅助操作

| 操作 | 触发对象 | 参数 | 验证规则 | 副作用 | 执行权限 | 审计记录 |
|------|---------|------|---------|--------|---------|---------|
| **排除图斑** | 图斑 | 排除原因 | 图斑状态为待研判 | 图斑状态→已排除、不生成问题 | 监管中心研判员 | 排除人/时间/原因 |
| **退回整改** | 问题台账 | 退回原因、整改要求 | 复核结论为不通过 | 问题状态→处置中、通知处置单位 | 监管中心 | 退回人/时间/原因 |
| **催办** | 问题台账 | 催办说明 | 问题状态为处置中且超过时限 | 发送催办通知（短信/系统消息） | 监管中心 | 催办人/时间 |
| **变更** | 任意业务对象 | 变更字段、变更值、变更原因 | 对象存在且有编辑权限 | 写入变更记录、更新对象属性 | 按角色授权 | 变更人/时间/前后值 |
| **导出台账** | 问题台账（批量） | 筛选条件、导出格式 | 用户有查看权限 | 生成导出文件 | 监管中心、局领导 | 导出人/时间/范围 |

| 角色 | 说明 | 典型人员 |

## 五、闭环流程（业务流转）

### 5.1 主流程状态机

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                          问题台账状态流转                                         │
│                                                                                 │
│  [待派发] ──派发──→ [处置中] ──核查上报──→ [待整改] ──整改上报──→ [待复核]         │
│      ↑                  ↑                                      │                │
│      │                  │                                  复核通过              │
│      │                  │                                      ↓                │
│      │                  ←──── 复核不通过（退回整改）──── [已销号] ──归档──→ [已归档] │
│      │                                                                         │
│      └──── 复核不通过（退回整改）──────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 5.2 全流程阶段说明

| 阶段 | 输入 | 处理 | 输出 | 责任方 |
|------|------|------|------|--------|
| **① 影像采集** | 飞行计划、设备、飞手 | 无人机按航线飞行，采集正射影像/视频 | 原始影像数据 | 监管中心操作员 + 飞手 |
| **② 智能识别** | 原始影像 | AI变化检测模型比对前后时相影像 | 疑似变化图斑（含坐标、面积、AI分类、置信度） | 系统自动 |
| **③ 自动套合** | 疑似图斑 + 管理图层 | 空间叠加分析：地类、永农、红线、规划、审批、权属 | 套合结果（地类属性、是否触碰底线、审批情况、责任主体） | 系统自动 |
| **④ 属性研判** | 图斑 + 套合结果 | 研判员综合套合结果判断：认定（生成问题）或排除 | 认定后的问题台账 或 排除记录 | 监管中心研判员 |
| **⑤ 派发** | 问题台账 | 监管中心负责人指定处置单位、时限、要求 | 处置任务、通知 | 监管中心负责人 |
| **⑥ 核查** | 处置任务 | 处置单位派人到现场核实，拍照记录 | 核查报告（现场照片、情况说明） | 处置单位核查员 |
| **⑦ 整改** | 核查报告 | 责任主体按要求整改（拆除/复耕/补办手续等） | 整改证据（整改前后对比照片、说明） | 处置单位/责任主体 |
| **⑧ 复核** | 整改证据 | 监管中心安排低空飞行复核或现场复核 | 复核结论（通过/不通过） | 监管中心负责人 |
| **⑨ 销号归档** | 复核通过的问题 | 问题关闭，生成完整处置档案 | 归档台账（含全链条记录） | 监管中心负责人 |

### 5.3 异常流程

| 异常场景 | 处理方式 | 状态变化 |
|---------|---------|---------|
| 复核不通过 | 退回处置单位重新整改，附退回原因 | 待复核 → 处置中 |
| 超期未处置 | 系统自动催办，超期 7 天升级至局领导 | 状态不变，触发催办通知 |
| 图斑排除后重新认定 | 研判员可撤销排除，重新进入套合研判 | 已排除 → 待套合 |
| 设备异常中止 | 任务标记异常中止，已采集成果保留 | 执行中 → 异常中止 |
| 问题跨辖区 | 由监管中心协调指定牵头处置单位 | 待派发 → 处置中（多单位协同） |

## 六、场景覆盖矩阵

本模型覆盖临漳县 5 类典型监管场景：

| 场景 | 发现方式 | 套合重点 | 问题类型 | 闭环特点 |
|------|---------|---------|---------|---------|
| 耕地保护监管 | 卫星变化 + 低空巡查 + 田长制线索 | 占耕/占永农/非农化非粮化 | 违法占地、破坏耕地 | 需判断是否触碰永农底线 |
| 违法用地监管 | 新增变化图斑 + 举报 | 审批/超范围/符合规划 | 未批先建、少批多占 | 需比对审批红线 |
| 设施农用地监管 | 低空影像 + 备案数据 | 超备案/变用途/硬化 | 设施农用地违规 | 需比对备案信息 |
| 建设项目批后监管 | 红线叠加影像 + 进度巡查 | 按范围建设/超红线/闲置 | 超红线建设、批而未用 | 需多时相对比进度 |
| 违建房监管 | 低空巡查 + 变化检测 | 地类/规划/审批/权属 | 违法建筑 | 拆除后需低空复核确认 |

---

## 七、表达边界

本模型在设计中遵守以下表达原则：

1. **低空巡查是手段，不是目的**：平台主角是自然资源监管体系，低空无人机是数据采集手段之一
2. **AI 辅助，不替代判断**：AI 识别结果仅作为"辅助发现线索"，属性研判和违法认定必须经过人工确认
3. **空间套合比 AI 模型更重要**：判断一块地是否违法，靠的是与地类、规划、审批、权属等管理数据的叠加分析
4. **闭环优先于展示**：设备底账和问题闭环是平台建设重点，展示型大屏不是优先建设内容
5. **场景贴合地方实际**：临漳县无矿山资源，不设矿山监管场景
