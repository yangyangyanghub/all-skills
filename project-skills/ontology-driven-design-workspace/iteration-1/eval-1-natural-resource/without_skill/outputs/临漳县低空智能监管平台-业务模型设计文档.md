## 一、模型总览

### 1.1 建模思路

本平台的核心业务是：**利用低空无人机巡查手段，对县域自然资源（土地、矿产、林业等）进行动态监管，实现"发现→核查→处置→销号"的全流程闭环管理**。

建模采用 **"对象 + 链接 + 操作 + 权限"** 四层结构：

| 层次 | 回答的问题 | 本文对应章节 |
|------|-----------|-------------|
| **对象（Object）** | 系统里有哪些"名词"？ | 第二章 |
| **链接（Link）** | 对象之间怎么关联？ | 第三章 |
| **操作（Action）** | 用户能对对象做什么？ | 第四章 |
| **权限（Permission）** | 谁能做什么？ | 第五章 |

### 1.2 业务闭环概览

```
┌─────────────────────────────────────────────────────────────────────┐
│                        业务闭环流程                                   │
│                                                                     │
│   设备巡查 ──► 图斑识别 ──► 问题核查 ──► 工单派发 ──► 整改处置       │
│      ▲                                              │               │
│      │                                              ▼               │
│      │              归档统计 ◄── 销号确认 ◄── 复核验收               │
│      └──────────────────────────────────────────────┘               │
│                        （不通过则退回整改）                            │
└─────────────────────────────────────────────────────────────────────┘
```

## 二、对象类型表

### 2.1 核心对象一览

| 对象类型 | 英文标识 | 说明 | 关键属性 |
|---------|---------|------|---------|
| **设备** | `Device` | 低空巡查设备（无人机、机巢等） | 设备编号、设备类型、所属组织、状态、最后维护时间 |
| **飞行任务** | `FlightTask` | 设备执行的巡查飞行计划 | 任务编号、任务名称、计划航线、飞行区域、计划时间、实际时间、状态 |
| **图斑** | `Patch` | 遥感影像或AI识别出的地表变化区域 | 图斑编号、所属任务、空间范围(GeoJSON)、类型、面积、发现时间、置信度 |
| **问题** | `Issue` | 经核查确认的违法违规问题 | 问题编号、关联图斑、问题类型、严重程度、发现人、发现时间、状态 |
| **工单** | `WorkOrder` | 问题处置的工作流转单据 | 工单编号、关联问题、当前环节、派发时间、责任人、时限、状态 |
| **人员** | `Person` | 系统使用者 | 姓名、手机号、所属组织、角色、状态 |
| **组织** | `Organization` | 部门/单位 | 组织名称、组织编码、上级组织、组织类型、负责人 |

## 三、链接类型表

### 3.1 链接关系一览

| 源对象 | 链接类型 | 目标对象 | 基数 | 说明 |
|--------|---------|---------|------|------|
| Device | `executes` | FlightTask | 1:N | 一台设备可执行多个飞行任务 |
| Organization | `owns` | Device | 1:N | 一个组织拥有多台设备 |
| FlightTask | `produces` | Patch | 1:N | 一次飞行任务可识别多个图斑 |
| Person | `pilots` | FlightTask | 1:N | 一名飞手可执行多个任务 |
| Patch | `confirmed_as` | Issue | 1:1 | 一个图斑核查后最多形成一个问题 |
| Issue | `generates` | WorkOrder | 1:N | 一个问题可生成多个工单（退回重派场景） |
| WorkOrder | `assigned_to` | Person | N:1 | 一个工单分配给一个责任人 |
| Person | `belongs_to` | Organization | N:1 | 一个人属于一个组织 |
| Organization | `parent_of` | Organization | 1:1 | 组织的上下级关系 |
| WorkOrder | `logged_by` | ActionLog | 1:N | 一个工单有多条操作记录 |

## 四、操作类型表

### 4.1 核心操作定义

| 操作 | 英文标识 | 触发对象 | 前置条件 | 后置效果 | 说明 |
|------|---------|---------|---------|---------|------|
| **创建飞行任务** | `createFlightTask` | Device | 设备状态为 IDLE | 生成 FlightTask，设备状态变为 FLYING | 规划巡查任务 |
| **完成飞行任务** | `completeFlightTask` | FlightTask | 任务状态为 IN_PROGRESS | 任务状态变为 COMPLETED，触发图斑识别 | 飞行结束，数据回传 |
| **识别图斑** | `detectPatch` | FlightTask | 任务已完成 | 生成 Patch 列表 | AI 自动识别或人工标注 |
| **核查图斑** | `reviewPatch` | Patch | 图斑状态为 PENDING_REVIEW | 图斑状态变为 CONFIRMED 或 DISMISSED | 确认是否为真实问题 |
| **立案** | `createIssue` | Patch | 图斑已确认 | 生成 Issue | 将确认的图斑转为问题 |
| **派发** | `dispatch` | Issue | 问题状态为 PENDING | 问题状态变为 DISPATCHED，生成 WorkOrder | 将问题分配给责任人 |
| **核查** | `investigate` | WorkOrder | 工单环节为 DISPATCHED | 工单环节变为 INVESTIGATING | 责任人现场核实 |
| **提交核查结果** | `submitInvestigation` | WorkOrder | 工单环节为 INVESTIGATING | 工单环节变为 RECTIFYING | 填写核查报告，进入整改 |
| **整改** | `rectify` | WorkOrder | 工单环节为 RECTIFYING | 工单环节变为 REVIEWING | 责任人完成整改并提交 |
| **复核** | `review` | WorkOrder | 工单环节为 REVIEWING | 工单环节变为 CLOSED 或退回 RECTIFYING | 核查整改结果 |
| **销号** | `close` | WorkOrder | 复核通过 | 工单状态变为 CLOSED，问题状态变为 CLOSED | 问题关闭，归档 |
| **退回** | `reject` | WorkOrder | 复核不通过 | 工单环节退回 RECTIFYING | 整改不合格，要求重新整改 |
| **转派** | `transfer` | WorkOrder | 工单环节非 CLOSED | 变更责任人 | 更换责任人或转交其他部门 |

### 4.2 操作流转规则

```
                    ┌──────────────────────────────────────────────┐
                    │              工单状态流转                      │
                    │                                              │
                    │  [已派发] ──核查──► [核查中] ──提交──► [整改中] │
                    │                                              │
                    │                         ▲                    │
                    │                    退回  │  ──整改──► [复核中]  │
                    │                         │                    │
                    │                         └──────────┘         │
                    │                                      │       │
                    │                              通过 ───┤       │
                    │                                      ▼       │
                    │                                  [已销号]     │
                    └──────────────────────────────────────────────┘
```

## 六、闭环流程详细设计

### 6.1 全流程时序

```
阶段1：巡查发现
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  调度员创建   │───►│  飞手执行    │───►│  数据回传    │
│  飞行任务    │    │  无人机巡查  │    │  AI识别图斑  │
└─────────────┘    └─────────────┘    └─────────────┘
                                              │
                                              ▼
阶段2：核查立案                                │
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  核查员现场  │◄───│  调度员分配  │◄───│  图斑列表    │
│  核实确认    │    │  核查任务    │    │  待核查      │
└─────────────┘    └─────────────┘    └─────────────┘
       │
       ▼ 确认有问题
阶段3：派发整改
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  调度员派发  │───►│  责任人接收  │───►│  现场整改    │
│  工单        │    │  工单        │    │  提交报告    │
└─────────────┘    └─────────────┘    └─────────────┘
                                              │
                                              ▼
阶段4：复核销号
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  复核员现场  │───►│  通过？      │──是─►│  销号归档   │
│  验收        │    │             │      │  统计入库   │
└─────────────┘    └─────────────┘    └─────────────┘
                          │
                          └──否──► 退回整改（回到阶段3）
```

### 6.2 各环节详细说明

#### 6.2.1 派发环节

| 项目 | 说明 |
|------|------|
| **操作人** | 调度员 |
| **输入** | 待处理问题列表 |
| **操作** | 选择问题 → 指定责任人 → 设置时限 → 派发 |
| **输出** | 生成工单，通知责任人 |
| **规则** | 1. 高严重度问题24小时内必须派发<br>2. 责任人必须属于对应辖区组织<br>3. 派发后自动发送短信/APP通知 |

#### 6.2.2 核查环节

| 项目 | 说明 |
|------|------|
| **操作人** | 核查员（可由责任人兼任） |
| **输入** | 待核查工单 |
| **操作** | 现场核实 → 拍照取证 → 填写核查报告 → 提交 |
| **输出** | 核查报告（含照片、位置、情况描述） |
| **规则** | 1. 核查时限：派发后3个工作日内<br>2. 必须上传现场照片（含水印时间戳）<br>3. 核查报告需包含问题确认/否定结论 |

#### 6.2.3 整改环节

| 项目 | 说明 |
|------|------|
| **操作人** | 整改责任人 |
| **输入** | 待整改工单 + 核查报告 |
| **操作** | 制定整改方案 → 执行整改 → 拍照取证 → 提交整改报告 |
| **输出** | 整改报告（含整改前后对比照片） |
| **规则** | 1. 整改时限根据严重程度设定：高-7天/中-15天/低-30天<br>2. 必须上传整改前后对比照片<br>3. 超期自动预警，通知调度员和领导 |

#### 6.2.4 复核环节

| 项目 | 说明 |
|------|------|
| **操作人** | 复核员 |
| **输入** | 待复核工单 + 整改报告 |
| **操作** | 现场验收 → 对比整改前后 → 判定通过/不通过 → 提交复核意见 |
| **输出** | 复核报告（通过/退回） |
| **规则** | 1. 复核时限：整改提交后2个工作日内<br>2. 复核不通过必须填写退回原因<br>3. 同一问题退回超过3次，自动升级至领导 |

#### 6.2.5 销号环节

| 项目 | 说明 |
|------|------|
| **操作人** | 复核员 / 调度员 |
| **输入** | 复核通过的工单 |
| **操作** | 确认销号 → 归档 |
| **输出** | 工单关闭，问题状态更新为已销号 |
| **规则** | 1. 销号后数据进入统计报表<br>2. 归档材料包括：图斑、问题、工单、所有操作记录、佐证材料<br>3. 销号后不可撤回（如需 reopening 需管理员操作） |

### 6.3 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 责任人无法处理 | 转派给其他责任人，记录转派原因 |
| 超期未处理 | 系统自动预警，通知上级领导和调度员 |
| 多次退回 | 超过3次退回自动升级，领导介入协调 |
| 图斑误判 | 核查阶段可排除，标记为"已排除"并记录原因 |
| 设备故障 | 飞行任务中止，设备状态变为 MAINTENANCE |

## 十、附录

### 10.1 术语表

| 术语 | 定义 |
|------|------|
| 图斑 | 遥感影像上识别出的地表变化区域，是问题发现的基础单元 |
| 销号 | 问题经过整改、复核确认后关闭的过程，表示该问题已处理完毕 |
| 闭环 | 从问题发现到最终销号的完整流程，确保每个问题都有处理结果 |
| 派发 | 将问题分配给具体责任人进行处理的操作 |
| 核查 | 对图斑或问题进行现场核实，确认其真实性和性质 |
| 整改 | 责任人对确认的问题进行处理，消除违法状态 |
| 复核 | 对整改结果进行验收，判断是否达到整改要求 |
