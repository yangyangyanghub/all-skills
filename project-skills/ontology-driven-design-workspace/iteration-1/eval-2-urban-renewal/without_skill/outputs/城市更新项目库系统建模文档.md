# 邯郸市城市更新项目库系统 — 数据模型与流转流程设计

> **版本**：v1.0  
> **日期**：2026-08-12  
> **范围**：从城市体检发现问题 → 项目储备 → 立项审批 → 年度计划 → 实施跟踪 → 竣工验收 → 后评估的全生命周期闭环管理

---

## 一、系统概述

### 1.1 业务定位

本系统是邯郸市城市更新工作的**核心业务平台**，覆盖"体检—立项—计划—实施—评估"全链条。系统以**问题为导向**，以**项目为载体**，以**年度计划为抓手**，以**评估反馈为闭环**，实现城市更新工作的全流程数字化管理。

### 1.2 核心业务链条

```
城市体检          项目储备          立项审批         年度计划
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 发现问题  │───▶│ 生成项目  │───▶│ 可行性论证│───▶│ 纳入计划  │
│ 评估定级  │    │ 方案编制  │    │ 审批立项  │    │ 资金安排  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                       │
       ┌───────────────────────────────────────────────┘
       ▼
  实施跟踪          竣工验收          后评估           反馈闭环
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 任务分解  │───▶│ 质量验收  │───▶│ 效果评估  │───▶│ 经验沉淀  │
│ 进度跟踪  │    │ 资金审计  │    │ 满意度    │    │ 问题反馈  │
│ 资金监控  │    │ 档案移交  │    │ 可持续    │    │ 下一轮体检│
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **问题驱动** | 一切项目源于体检发现的问题，确保"有的放矢" |
| **全链闭环** | 从发现到评估形成完整闭环，每个环节可追溯 |
| **空间落图** | 所有对象关联空间位置，支持 GIS 可视化分析 |
| **多源汇聚** | 整合体检数据、规划数据、项目数据、资金数据 |
| **分级管控** | 市—区—街道三级管理，权责清晰 |
| **动态调整** | 支持项目库动态更新，年度计划滚动调整 |

## 二、对象类型表（Object Types）

### 2.1 核心业务对象

#### O1 — 体检问题（InspectionIssue）

> 城市体检中发现的各类问题，是整个项目库系统的**源头输入**。

| 属性 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `id` | UUID | ✅ | 唯一标识 |
| `code` | String | ✅ | 问题编号，格式 `HD-TJ-{年份}-{序号}` |
| `title` | String | ✅ | 问题标题 |
| `category` | Enum | ✅ | 问题分类（见下方枚举） |
| `subCategory` | String | — | 子分类 |
| `severity` | Enum | ✅ | 严重程度：`紧急` / `重要` / `一般` |
| `description` | Text | ✅ | 问题详细描述 |
| `location` | GeoJSON | ✅ | 空间位置（点/面） |
| `areaId` | FK → RenewalArea | ✅ | 所属更新片区 |
| `discoveredDate` | Date | ✅ | 发现日期 |
| `discoveredBy` | FK → ResponsibleEntity | ✅ | 发现单位 |
| `discoveredPerson` | String | — | 发现人 |
| `evidence` | Attachment[] | — | 佐证材料（照片、检测报告） |
| `status` | Enum | ✅ | 状态（见状态机） |
| `relatedPolicy` | FK → PolicyBasis[] | — | 关联的政策要求 |
| `affectedPopulation` | Integer | — | 影响人口数 |
| `affectedArea` | Float | — | 影响面积（㎡） |
| `createdBy` | String | ✅ | 创建人 |
| `createdAt` | DateTime | ✅ | 创建时间 |
| `updatedAt` | DateTime | ✅ | 更新时间 |

**问题分类枚举（category）**：

| 编码 | 名称 | 说明 |
|------|------|------|
| `OLD_COMMUNITY` | 老旧小区 | 建成年代久远、设施老化、环境差 |
| `INFRASTRUCTURE` | 基础设施 | 道路、管网、排水、供热等市政设施 |
| `PUBLIC_SERVICE` | 公共服务 | 教育、医疗、养老、文化等设施不足 |
| `ECOLOGY` | 生态环境 | 绿地不足、水体污染、空气质量 |
| `HERITAGE` | 历史文化 | 历史建筑保护、文化街区活化 |
| `SAFETY` | 安全隐患 | 危房、地质灾害、消防隐患 |
| `INDUSTRY` | 产业空间 | 低效用地、老旧厂房、产业升级 |
| `TRANSPORT` | 交通系统 | 拥堵、停车难、公共交通覆盖不足 |

**状态机**：

```
待确认 ──确认──▶ 已确认 ──转化为项目──▶ 已转化
  │                │
  └──忽略──▶ 已忽略  └──暂不转化──▶ 已确认（挂起）
```

```
储备 ──前期研究──▶ 前期 ──申请立项──▶ 立项审批中 ──审批通过──▶ 已立项
  │                  │                    │
  │                  └──论证不通过──▶ 退回修改  └──审批不通过──▶ 驳回
  │                                                    │
  └──淘汰──▶ 已终止                                    └──修改重报──▶ 前期
  │
  已立项 ──纳入年度计划──▶ 已纳入计划 ──开工──▶ 在建 ──竣工──▶ 已竣工 ──后评估──▶ 已评估
                            │                    │              │
                            └──暂停──▶ 已暂停     └──验收不通过──▶ 整改中
                            └──取消──▶ 已取消
```

### 6.2 子闭环1：问题确认闭环

```
体检单位录入问题 ──▶ 区级确认 ──▶ 市级审核 ──▶ 确认入库
                      │              │
                      └──退回补充◀──┘
```

**参与角色**：体检单位 → 区级管理员 → 市级管理员  
**关键规则**：
- 问题必须有空间位置和佐证材料
- 严重程度由体检单位初判，区级确认，市级可调整
- 退回需说明理由，限期补充

### 6.3 子闭环2：立项审批闭环

```
责任单位编制可研 ──▶ 区级初审 ──▶ 市级复审 ──▶ 领导审批 ──▶ 立项批复
      │                │            │            │
      └──修改重报◀─────┘            └──退回◀─────┘
```

**参与角色**：责任单位 → 区级管理员 → 市级管理员 → 市级领导  
**关键规则**：
- 可研报告必须包含技术方案、投资估算、资金筹措、实施计划
- A 类项目（投资 > 5000万）需市级领导审批
- B/C 类项目市级管理员可审批
- 审批意见全程留痕

### 6.4 子闭环3：年度计划闭环

```
项目征集 ──▶ 需求汇总 ──▶ 资金测算 ──▶ 方案平衡 ──▶ 计划编制 ──▶ 审批 ──▶ 下达
   │                                                              │
   └──未纳入项目反馈原因◀─────────────────────────────────────────┘
```

**参与角色**：区级管理员（征集）→ 市级管理员（汇总/编制）→ 市级领导（审批）  
**关键规则**：
- 优先安排 A 类项目和民生急需项目
- 资金测算需匹配可用资金源
- 未纳入计划的项目需反馈原因，保持透明

### 6.5 子闭环4：实施跟踪闭环

```
任务分解 ──▶ 开工 ──▶ 进度填报（月度）──▶ 检查督导 ──▶ 问题协调 ──▶ 完工
                          │                              │
                          └──进度预警◀───────────────────┘
```

**参与角色**：实施单位（填报）→ 区级管理员（督导）→ 市级管理员（协调）  
**关键规则**：
- 实施单位每月填报进度和投资完成情况
- 进度偏差 > 20% 自动预警
- 阻塞问题逐级上报，市级协调

### 6.6 子闭环5：评估反馈闭环

```
评估启动 ──▶ 现场调研 ──▶ 报告编制 ──▶ 提交审核 ──▶ 审核通过 ──▶ 问题反馈 ──▶ 整改跟踪
                                │                        │
                                └──退回修改◀─────────────┘
```

**参与角色**：评估单位 → 市级/区级管理员  
**关键规则**：
- 评估发现的新问题自动创建为 InspectionIssue
- 评估结论分为：优秀（≥90）/ 良好（75-89）/ 合格（60-74）/ 不合格（<60）
- 不合格项目需制定整改方案并跟踪

## 七、关键业务规则汇总

### 7.1 编号规则

| 对象 | 编号格式 | 示例 |
|------|---------|------|
| 体检问题 | `HD-TJ-{年份}-{4位序号}` | `HD-TJ-2026-0001` |
| 更新项目 | `HD-GX-{年份}-{4位序号}` | `HD-GX-2026-0001` |
| 年度计划 | `HD-JH-{年份}` | `HD-JH-2026` |
| 实施任务 | `HD-RW-{项目序号}-{3位序号}` | `HD-RW-0001-001` |
| 评估报告 | `HD-PG-{项目序号}-{类型}-{序号}` | `HD-PG-0001-MID-001` |

### 7.2 状态流转约束

| 约束 | 规则 |
|------|------|
| 问题→项目 | 只有`已确认`状态的问题才能转化为项目 |
| 项目→计划 | 只有`已立项`状态的项目才能纳入年度计划 |
| 计划→任务 | 只有`已批准`的计划才能分解实施任务 |
| 项目终止 | `已竣工`和`已评估`状态的项目不可终止 |
| 计划完成 | 所有关联任务必须为终态（已完成/已取消）才能完成计划 |

### 7.3 审批时限

| 审批类型 | 时限 | 超时处理 |
|---------|------|---------|
| 问题确认 | 5 个工作日 | 自动提醒 |
| 立项审批 | 15 个工作日 | 自动提醒 + 上报 |
| 年度计划审批 | 20 个工作日 | 自动提醒 + 上报 |
| 延期审批 | 5 个工作日 | 自动提醒 |
| 评估审核 | 10 个工作日 | 自动提醒 |

### 7.4 预警规则

| 预警类型 | 触发条件 | 预警级别 | 通知对象 |
|---------|---------|---------|---------|
| 进度滞后 | 实际进度 < 计划进度 × 80% | 黄色 | 实施单位 + 区级管理员 |
| 进度严重滞后 | 实际进度 < 计划进度 × 60% | 红色 | 实施单位 + 区/市级管理员 |
| 投资超支 | 已完成投资 > 计划投资 × 110% | 黄色 | 责任单位 + 市级管理员 |
| 任务即将到期 | 距截止日期 ≤ 7 天且未完成 | 黄色 | 实施单位 |
| 任务已逾期 | 超过截止日期且未完成 | 红色 | 实施单位 + 区/市级管理员 |
| 审批超时 | 超过审批时限 | 黄色 | 审批人 |
