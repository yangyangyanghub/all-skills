# 县域人力资源产业园运营系统 · 本体建模文档

> **版本**：v1.0  
> **日期**：2026-08-12  
> **建模方法**：Ontology-Driven Design（运营本体建模）  
> **适用场景**：县域人力资源产业园的运营管理系统，覆盖企业入驻、招聘服务、培训、岗位外包四大业务线

---

## 一、业务背景与建模范围

### 1.1 业务背景

县域人力资源产业园是地方政府主导的就业服务平台，核心使命是：
- **聚企业**：吸引人力资源服务企业、用工企业入驻园区
- **促就业**：通过招聘、培训、外包等服务匹配劳动力供需
- **落政策**：承接就业补贴、技能培训补贴等政策落地

### 1.2 建模范围

本建模覆盖四大业务线及其支撑对象：

| 业务线 | 核心流转 | 关键角色 |
|--------|---------|---------|
| 企业入驻 | 申请 → 审核 → 签约 → 入驻 → 退驻 | 企业、园区运营方 |
| 招聘服务 | 职位发布 → 简历投递 → 面试 → 录用 → 入职 | 企业、求职者、运营方 |
| 培训服务 | 课程开设 → 报名 → 培训 → 考核 → 发证 | 培训机构、学员、运营方 |
| 岗位外包 | 需求发布 → 人员派遣 → 在岗管理 → 结算 → 续约/终止 | 用工企业、外包公司、派遣员工 |

### 1.3 建模假设

由于用户描述相对概括，以下细节基于行业通用实践推断，如有不符请反馈调整：

1. **园区运营方**：假设为政府下属的园区管理公司或人社局直属机构
2. **入驻企业类型**：包括人力资源服务公司（中介、外包、培训）和用工企业（直接在园区办公的企业）
3. **求职者来源**：本地劳动力、返乡务工人员、高校毕业生等
4. **政策补贴**：涉及就业补助资金、职业技能培训补贴等县域常见政策
5. **系统对接**：可能需要对接人社局就业信息系统、社保系统等（本文档不展开对接细节）

## 二、对象类型（Object Types）

### 2.1 核心业务对象

| 对象 | 说明 | 关键属性 | 可编辑 |
|------|------|---------|--------|
| **园区（Park）** | 人力资源产业园实体 | 园区ID、名称、地址、面积、楼层数、房间数、联系电话、运营方 | 否（基础数据） |
| **运营方（Operator）** | 园区运营管理机构 | 机构ID、名称、负责人、联系方式、管理权限范围 | 是 |
| **入驻企业（TenantEnterprise）** | 在园区注册/办公的企业 | 企业ID、统一社会信用代码、企业名称、法人、联系人、联系电话、入驻状态（待审核/已入驻/已退驻）、入驻日期、合同编号、企业类型（人力资源公司/用工企业） | 是 |
| **职位（JobPosition）** | 企业发布的招聘岗位 | 职位ID、所属企业、职位名称、职位类别、工作地点、薪资范围、学历要求、经验要求、招聘人数、职位描述、发布状态（草稿/已发布/已关闭）、发布日期、截止日期 | 是 |
| **求职者（JobSeeker）** | 找工作的人员 | 求职者ID、姓名、身份证号、性别、出生日期、联系电话、学历、专业、毕业院校、工作年限、求职状态（待业/在职-考虑机会/在职-不考虑）、期望职位、期望薪资、期望工作地点、登记日期 | 是 |
| **简历（Resume）** | 求职者的详细履历 | 简历ID、所属求职者、教育经历（数组）、工作经历（数组）、技能证书（数组）、自我评价、附件简历URL、更新时间 | 是 |
| **招聘活动（RecruitmentEvent）** | 园区组织的招聘会等活动 | 活动ID、活动名称、活动类型（线上/线下/混合）、活动时间、活动地点、参展企业列表、目标人群、报名人数、实际到场人数、活动总结 | 是 |
| **培训课程（TrainingCourse）** | 园区或培训机构开设的课程 | 课程ID、课程名称、课程类别（职业技能/创业培训/岗前培训）、培训机构、讲师、课时数、培训地点、开班日期、结班日期、培训费用、补贴标准、课程状态（待开班/进行中/已结班） | 是 |
| **培训学员（TrainingStudent）** | 参加培训的学员 | 学员ID、所属课程、学员信息（关联求职者或独立登记）、报名日期、出勤天数、考核成绩、证书编号、发证日期、补贴申领状态 | 是 |
| **外包需求（OutsourcingDemand）** | 企业发布的岗位外包需求 | 需求ID、需求企业、岗位名称、工作内容、技能要求、招聘人数、工作期限、薪资预算、结算方式（按人/月、按件、按项目）、需求状态（待匹配/已匹配/已完成/已取消） | 是 |
| **派遣员工（DispatchedWorker）** | 被派遣到外包岗位的员工 | 员工ID、所属外包公司、派遣到哪个需求、员工信息（关联求职者）、派遣开始日期、派遣结束日期、考勤记录、薪资发放记录、在岗状态（在岗/离岗） | 是 |
| **服务合同（ServiceContract）** | 园区与企业签订的服务合同 | 合同ID、合同编号、签约企业、合同类型（入驻服务/招聘服务/培训服务/外包服务）、合同金额、服务期限、签约日期、到期日期、合同状态（待签署/执行中/已到期/已终止）、附件 | 是 |
| **费用账单（FeeBill）** | 园区向企业收取的费用 | 账单ID、账单编号、关联企业、账单类型（租金/服务费/培训费/其他）、账单金额、应付日期、实付日期、支付状态（待支付/已支付/逾期）、支付方式、发票信息 | 是 |
| **政策补贴（PolicySubsidy）** | 政府提供的就业/培训补贴 | 补贴ID、补贴名称、补贴类型（就业补助/培训补贴/社保补贴/岗位补贴）、补贴标准、申请条件、申请截止日期、审批状态、发放金额、发放日期 | 是 |
| **补贴申请（SubsidyApplication）** | 企业或个人申请的补贴 | 申请ID、补贴类型、申请主体（企业/个人）、申请金额、申请材料、申请日期、审批状态（待审核/审核中/已通过/已驳回/已发放）、审批意见、发放日期 | 是 |

### 2.2 支撑对象

| 对象 | 说明 | 关键属性 | 可编辑 |
|------|------|---------|--------|
| **用户账号（UserAccount）** | 系统登录账号 | 用户ID、用户名、手机号、邮箱、密码哈希、账号状态（正常/禁用）、最后登录时间、关联角色 | 是 |
| **角色（Role）** | 系统角色定义 | 角色ID、角色名称、角色描述、权限列表、数据范围（全部/本部门/本人） | 是 |
| **审批流程（ApprovalProcess）** | 业务审批的流程定义 | 流程ID、流程名称、适用业务类型、审批节点列表、超时规则、通知规则 | 是 |
| **审批记录（ApprovalRecord）** | 具体业务的审批记录 | 记录ID、关联业务、当前节点、审批人、审批意见、审批时间、审批状态 | 否（只追加） |
| **通知消息（Notification）** | 系统发送的通知 | 消息ID、接收人、消息类型（系统通知/审批通知/业务提醒）、消息内容、发送时间、阅读状态、阅读时间 | 否（只追加） |
| **操作日志（AuditLog）** | 系统操作审计日志 | 日志ID、操作人、操作时间、操作类型、操作对象、操作前数据、操作后数据、IP地址 | 否（只追加） |

## 四、操作类型（Action Types）

### 4.1 企业入驻业务操作

| 操作 | 参数 | 验证规则 | 副作用 | 权限 | 审计 |
|------|------|---------|--------|------|------|
| **提交入驻申请** | 企业基本信息、营业执照、法人信息、入驻意向 | 企业统一社会信用代码未重复、营业执照有效 | 创建 TenantEnterprise（状态=待审核）、创建审批流程、发送通知给运营方 | 企业用户（代表企业） | 记录申请人、申请时间、提交数据 |
| **审核入驻申请** | 申请ID、审核意见（通过/驳回）、驳回原因（如驳回） | 申请状态=待审核、审核人具有审核权限 | 更新 TenantEnterprise 状态、创建审批记录、发送通知给企业 | 运营方管理员 | 记录审核人、审核时间、审核意见 |
| **签订服务合同** | 合同模板、合同金额、服务期限、签约日期 | 企业状态=已入驻、合同未过期 | 创建 ServiceContract、关联到 TenantEnterprise、发送签约通知 | 运营方管理员、企业负责人 | 记录签约双方、合同内容、签约时间 |
| **办理入驻手续** | 入驻日期、分配房间、钥匙交接确认 | 合同已签署、房间未被占用 | 更新 TenantEnterprise 入驻日期、更新房间状态、发送入驻欢迎通知 | 运营方管理员 | 记录入驻日期、分配房间、办理人 |
| **申请退驻** | 退驻原因、退驻日期、物品清单 | 企业状态=已入驻、无未结清账单 | 更新 TenantEnterprise 状态=待退驻、创建退驻审批流程 | 企业用户 | 记录申请人、退驻原因、申请时间 |
| **办理退驻手续** | 退驻确认、物品交接、费用结算 | 退驻审批通过、所有账单已结清 | 更新 TenantEnterprise 状态=已退驻、释放房间、发送退驻确认通知 | 运营方管理员 | 记录退驻日期、结算金额、办理人 |

### 4.2 招聘服务业务操作

| 操作 | 参数 | 验证规则 | 副作用 | 权限 | 审计 |
|------|------|---------|--------|------|------|
| **发布职位** | 职位信息（名称、类别、薪资、要求等） | 企业状态=已入驻、职位信息完整 | 创建 JobPosition（状态=已发布）、发送职位上线通知 | 企业用户 | 记录发布人、发布时间、职位内容 |
| **关闭职位** | 职位ID、关闭原因 | 职位状态=已发布 | 更新 JobPosition 状态=已关闭、发送职位关闭通知 | 企业用户、运营方管理员 | 记录关闭人、关闭时间、关闭原因 |
| **投递简历** | 职位ID、简历ID、求职意向 | 职位状态=已发布、求职者状态≠已就业 | 创建投递记录、发送简历通知给企业、更新求职者投递历史 | 求职者 | 记录投递时间、投递职位、简历版本 |
| **筛选简历** | 投递ID、筛选意见（邀请面试/不合适/待定） | 投递状态=待处理 | 更新投递状态、发送筛选结果通知给求职者 | 企业用户 | 记录筛选人、筛选时间、筛选意见 |
| **安排面试** | 投递ID、面试时间、面试地点、面试官 | 投递状态=待面试 | 创建面试记录、发送面试通知给求职者、更新投递状态=面试中 | 企业用户 | 记录面试时间、地点、面试官 |
| **记录面试结果** | 面试ID、面试结果（录用/不录用/待定）、面试评价 | 面试已完成 | 更新投递状态、发送面试结果通知给求职者、如录用则创建录用记录 | 企业用户 | 记录面试结果、评价内容、记录人 |
| **确认录用** | 投递ID、录用职位、入职日期、薪资 | 面试结果=录用 | 更新投递状态=已录用、发送录用通知给求职者、更新求职者状态=已就业 | 企业用户 | 记录录用职位、薪资、入职日期 |
| **组织招聘活动** | 活动信息（名称、时间、地点、类型） | 运营方权限 | 创建 RecruitmentEvent、发送活动通知给企业、开放企业报名 | 运营方管理员 | 记录活动信息、创建人、创建时间 |
| **报名参加招聘活动** | 活动ID、参展企业、参展职位列表 | 活动状态=报名中、企业状态=已入驻 | 创建活动-企业关联、发送报名确认通知 | 企业用户 | 记录报名时间、参展职位、报名人 |

| 操作 | 参数 | 验证规则 | 副作用 | 权限 | 审计 |
|------|------|---------|--------|------|------|
| **发布外包需求** | 需求信息（岗位、要求、人数、期限、预算等） | 企业状态=已入驻、需求信息完整 | 创建 OutsourcingDemand（状态=待匹配）、发送需求通知给运营方 | 企业用户 | 记录需求信息、发布人、发布时间 |
| **匹配派遣人员** | 需求ID、派遣员工列表 | 需求状态=待匹配、派遣员工状态=可派遣 | 创建需求-员工关联、更新需求状态=已匹配、发送匹配通知给企业和员工 | 运营方管理员、外包公司用户 | 记录匹配人、匹配时间、派遣员工列表 |
| **办理派遣手续** | 员工ID、派遣开始日期、工作地点、工作内容 | 需求状态=已匹配、员工状态=可派遣 | 更新派遣员工状态=在岗、更新需求状态=进行中、发送派遣通知 | 运营方管理员、外包公司用户 | 记录派遣日期、工作地点、办理人 |
| **记录考勤** | 员工ID、考勤日期、考勤状态、工作时长 | 员工状态=在岗 | 更新员工考勤记录、发送考勤确认通知 | 用工企业用户、外包公司用户 | 记录考勤日期、状态、工作时长、记录人 |
| **结算外包费用** | 需求ID、结算周期、结算金额、结算明细 | 需求状态=进行中或已完成、考勤记录完整 | 创建 FeeBill、发送账单通知给用工企业 | 外包公司用户、运营方管理员 | 记录结算周期、金额、明细、结算人 |
| **支付外包费用** | 账单ID、支付金额、支付方式、支付凭证 | 账单状态=待支付 | 更新账单状态=已支付、发送支付确认通知 | 用工企业用户 | 记录支付金额、方式、时间、支付人 |
| **结束派遣** | 员工ID、派遣结束日期、结束原因 | 员工状态=在岗 | 更新员工状态=离岗、更新需求状态（如所有员工离岗则=已完成）、发送结束通知 | 运营方管理员、外包公司用户 | 记录结束日期、原因、办理人 |

### 4.5 通用支撑操作

| 操作 | 参数 | 验证规则 | 副作用 | 权限 | 审计 |
|------|------|---------|--------|------|------|
| **创建用户账号** | 用户信息（用户名、手机号、密码）、关联角色 | 用户名未重复、手机号未重复 | 创建 UserAccount、发送账号激活通知 | 运营方管理员 | 记录创建人、创建时间、用户信息 |
| **分配角色** | 用户ID、角色ID | 用户状态=正常、角色存在 | 创建用户-角色关联、发送角色变更通知 | 运营方管理员 | 记录分配人、分配时间、角色信息 |
| **发送通知** | 接收人、消息类型、消息内容 | 接收人存在 | 创建 Notification、发送消息（站内信/短信/邮件） | 系统自动、运营方管理员 | 记录发送人、发送时间、消息内容 |

## 六、闭环流程（Business Flows）

### 6.1 企业入驻闭环

```
[企业提交入驻申请] 
    ↓
[运营方审核申请] ──驳回──→ [企业修改后重新提交]
    ↓ 通过
[签订服务合同]
    ↓
[办理入驻手续（分配房间、交接钥匙）]
    ↓
[企业正式入驻（状态=已入驻）]
    ↓
[日常运营（发布职位、报名活动、申请补贴等）]
    ↓
[企业申请退驻] ──（可选）──→ [运营方挽留沟通]
    ↓
[办理退驻手续（物品交接、费用结算）]
    ↓
[企业退驻（状态=已退驻）] ──→ [归档]
```

**闭环验证点**：
- 申请 → 审核 → 签约 → 入驻 → 退驻 → 归档，形成完整生命周期
- 每个环节都有审批记录和通知
- 退驻时必须结清所有账单

### 6.2 招聘服务闭环

```
[企业发布职位]
    ↓
[求职者投递简历]
    ↓
[企业筛选简历] ──不合适──→ [通知求职者]
    ↓ 邀请面试
[安排面试]
    ↓
[记录面试结果] ──不录用──→ [通知求职者]
    ↓ 录用
[确认录用]
    ↓
[求职者入职（状态=已就业）]
    ↓
[（可选）跟踪入职后情况] ──→ [归档]
```

**闭环验证点**：
- 发布 → 投递 → 筛选 → 面试 → 录用 → 入职，形成完整求职流程
- 每个环节都有通知，求职者可实时查看进度
- 录用后更新求职者状态，避免重复投递

### 6.3 培训服务闭环

```
[培训机构开设课程]
    ↓
[求职者报名培训]
    ↓
[培训实施（记录考勤）]
    ↓
[考核（录入成绩）] ──不合格──→ [（可选）补考或重修]
    ↓ 合格
[发放培训证书]
    ↓
[（可选）申请培训补贴]
    ↓
[运营方审核补贴] ──驳回──→ [补充材料后重新申请]
    ↓ 通过
[发放补贴] ──→ [归档]
```

**闭环验证点**：
- 开课 → 报名 → 培训 → 考核 → 发证 → 补贴，形成完整培训流程
- 考勤、成绩、证书都有记录
- 补贴申请有审批流程，确保合规

### 6.4 岗位外包闭环

```
[企业发布外包需求]
    ↓
[运营方/外包公司匹配人员]
    ↓
[办理派遣手续]
    ↓
[派遣员工在岗工作（记录考勤）]
    ↓
[定期结算外包费用]
    ↓
[企业支付费用]
    ↓
[（需求到期或完成）结束派遣]
    ↓
[派遣员工离岗] ──→ [（可选）续约或归档]
```

**闭环验证点**：
- 需求 → 匹配 → 派遣 → 考勤 → 结算 → 结束，形成完整外包流程
- 考勤记录作为结算依据
- 费用账单有支付状态跟踪

### 6.5 跨业务线联动

**场景1：培训 → 就业**
- 求职者参加培训 → 获得证书 → 投递简历 → 被录用
- 系统自动推荐：培训学员优先匹配相关职位

**场景2：外包 → 就业**
- 派遣员工在外包岗位工作 → 合同到期 → 转为用工企业正式员工
- 系统记录：派遣经历可作为求职者的工作经历

**场景3：政策补贴贯穿全流程**
- 企业入驻补贴：新入驻企业可申请租金补贴
- 招聘补贴：企业录用特定人群（应届生、就业困难人员）可申请社保补贴
- 培训补贴：求职者参加培训并获证后可申请培训补贴
- 外包补贴：外包公司吸纳就业可申请岗位补贴

| 触发条件 | 处理方式 | 结果 |

| 多业务线联动 | 在闭环流程章节专门说明跨业务线联动场景 | 已覆盖培训→就业、外包→就业、政策补贴贯穿等场景 |

## 八、后续建议

### 8.1 短期落地建议

1. **优先实现核心业务**：企业入驻 + 招聘服务，这是园区最基础的业务
2. **政策补贴模块**：与人社局确认补贴政策和审批流程后再细化
3. **数据迁移**：如有历史数据（如已入驻企业），需制定数据迁移方案

### 8.2 中期优化建议

1. **数据分析模块**：基于本体模型构建数据分析看板（如就业率、培训转化率、外包结算额）
2. **移动端适配**：求职者端优先做移动端（小程序/APP）
3. **智能推荐**：基于求职者画像和职位要求的智能匹配推荐

### 8.3 长期演进建议

1. **区域协同**：与周边县域人力资源产业园联网，实现资源共享
2. **AI 辅助**：引入 AI 辅助简历筛选、面试评估、培训效果分析
3. **生态扩展**：引入更多人力资源服务（如薪酬代发、社保代缴、劳动争议调解）
