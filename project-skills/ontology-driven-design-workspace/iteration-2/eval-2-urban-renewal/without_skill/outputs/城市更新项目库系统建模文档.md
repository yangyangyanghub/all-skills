# 邯郸市城市更新项目库系统 — 数据模型与流转流程设计文档

> **版本**：v1.0  
> **日期**：2026-08-12  
> **范围**：城市体检 → 项目立项 → 年度计划 → 实施评估 全链条  

---

## 一、系统概述

### 1.1 业务背景

邯郸市城市更新项目库系统覆盖从"城市体检发现问题"到"项目实施效果评估"的完整业务闭环。核心目标是：

- **问题可溯源**：每个项目都能追溯到体检发现的具体问题
- **流程可管控**：立项、计划、实施、评估各环节状态透明
- **资金可追踪**：从预算安排到资金使用全程可查
- **效果可评估**：实施结果与体检问题对照，形成闭环

### 1.2 核心业务链条

```
城市体检 → 问题登记 → 问题核实 → 片区划定 → 项目储备 → 项目论证 → 立项审批
    → 年度计划 → 资金安排 → 任务派发 → 实施监管 → 竣工验收 → 效果评估
    → 反馈优化（回到下一轮体检）
```

## 二、对象类型表（Object Types）

### 2.1 核心业务对象

| 对象类型 | 英文标识 | 说明 | 关键属性 | 生命周期状态 |
|---------|---------|------|---------|------------|
| **城市体检报告** | `InspectionReport` | 一次城市体检活动的成果报告 | 报告编号、体检年度、体检范围、编制单位、完成日期、报告文件 | 草稿 → 审核中 → 已发布 → 已归档 |
| **体检问题** | `InspectionIssue` | 体检中发现的具体问题 | 问题编号、问题类型、问题描述、严重程度、空间位置（GIS坐标）、所属片区、发现日期、照片附件 | 待核实 → 已核实 → 已转化 → 已关闭 |
| **更新片区** | `RenewalArea` | 划定的城市更新范围 | 片区编号、片区名称、片区类型（老旧小区/老旧厂区/老旧街区/城中村等）、总面积、涉及街道、边界（GIS多边形）、划定日期 | 草案 → 已划定 → 实施中 → 已完成 |
| **储备项目** | `ReserveProject` | 从问题转化来的项目候选 | 项目储备编号、项目名称、项目类型、拟解决的核心问题、预估投资、优先级、所属片区 | 待论证 → 论证中 → 已入库 → 已转出（立项） → 已淘汰 |
| **立项项目** | `Project` | 正式立项的城市更新项目 | 项目编号、项目名称、项目类型、建设内容、总投资、资金来源、建设周期、实施主体、立项批复文件 | 待立项 → 立项审批中 → 已立项 → 实施中 → 已竣工 → 已评估 → 已归档 |
| **年度计划** | `AnnualPlan` | 某年度的城市更新实施计划 | 计划编号、计划年度、计划总投资、项目数量、编制单位、审批日期、计划文件 | 编制中 → 审批中 → 已批复 → 执行中 → 已完成 |
| **计划项目** | `PlanProject` | 年度计划中的具体项目条目 | 年度计划项目ID、年度投资额、资金来源明细、计划开工时间、计划竣工时间、责任人 | 待启动 → 实施中 → 已完成 → 已延期 → 已取消 |
| **实施任务** | `ImplementationTask` | 项目实施过程中的具体任务 | 任务编号、任务名称、任务类型、负责单位、计划开始/结束时间、实际开始/结束时间 | 待派发 → 进行中 → 待验收 → 已完成 → 已退回 |
| **竣工验收报告** | `CompletionReport` | 项目竣工后的验收报告 | 验收编号、验收日期、验收结论、验收组成员、整改意见、验收文件 | 待验收 → 验收中 → 通过 → 需整改 → 已归档 |
| **效果评估报告** | `AssessmentReport` | 项目实施效果的后评估 | 评估编号、评估日期、评估指标得分、居民满意度、主要成效、存在问题、改进建议 | 待评估 → 评估中 → 已完成 → 已发布 |

## 四、操作类型表（Action Types）

### 4.1 体检阶段操作

| 操作类型 | 英文标识 | 说明 | 前置条件 | 后置效果 | 触发角色 |
|---------|---------|------|---------|---------|---------|
| **创建体检报告** | `createInspectionReport` | 新建一次城市体检活动 | 无 | 创建 `InspectionReport`（草稿） | 市级主管部门、技术单位 |
| **登记体检问题** | `registerIssue` | 在体检报告中登记发现的问题 | 存在已发布的体检报告 | 创建 `InspectionIssue`（待核实） | 技术单位 |
| **核实问题** | `verifyIssue` | 对登记的问题进行核实确认 | 问题状态为"待核实" | 问题状态变为"已核实" | 区级主管部门 |
| **退回问题** | `rejectIssue` | 退回不实或重复的问题 | 问题状态为"待核实" | 问题状态变为"已关闭"，备注退回原因 | 区级主管部门 |

### 4.2 项目储备阶段操作

| 操作类型 | 英文标识 | 说明 | 前置条件 | 后置效果 | 触发角色 |
|---------|---------|------|---------|---------|---------|
| **划定片区** | `delineateArea` | 划定城市更新片区 | 存在已核实的体检问题 | 创建 `RenewalArea`（草案） | 市级主管部门 |
| **问题转项目** | `convertIssueToProject` | 将核实的问题转化为储备项目 | 问题已核实且未转化 | 创建 `ReserveProject`（待论证），问题状态变为"已转化" | 区级主管部门 |
| **项目论证** | `evaluateReserveProject` | 对储备项目进行可行性论证 | 储备项目状态为"待论证" | 项目状态变为"已入库"或"已淘汰" | 市级主管部门、专家 |
| **项目立项** | `approveProject` | 审批储备项目正式立项 | 储备项目已入库 | 创建 `Project`（已立项），储备项目状态变为"已转出" | 市级主管部门 |
| **退回立项** | `rejectProjectApproval` | 退回不符合条件的立项申请 | 项目状态为"立项审批中" | 项目状态回退为"待立项" | 市级主管部门 |

### 4.4 实施阶段操作

| 操作类型 | 英文标识 | 说明 | 前置条件 | 后置效果 | 触发角色 |
|---------|---------|------|---------|---------|---------|
| **派发任务** | `assignTask` | 向实施单位派发具体任务 | 计划项目已启动 | 创建 `ImplementationTask`（待派发） | 区级主管部门 |

### 6.2 闭环机制详解

#### 闭环 1：问题发现 → 解决闭环

```
体检发现问题 → 登记入库 → 核实确认 → 转化为项目 → 项目实施 → 竣工验收 → 效果评估 → 确认问题解决 → 关闭问题
```

**闭环校验点**：
- 每个"已核实"的问题必须关联至少一个"储备项目"
- 每个"已转化"的问题必须关联一个"已立项"的项目
- 每个"已竣工"的项目必须有"效果评估报告"
- 评估报告中必须逐项对照原始问题，确认解决状态

#### 闭环 2：资金安排 → 使用闭环

```
年度计划编制 → 资金需求测算 → 资金来源安排 → 资金拨付 → 资金使用 → 资金审计 → 绩效评价
```

**闭环校验点**：
- 每个"计划项目"必须有对应的"资金安排"
- 资金到位率低于阈值时自动预警
- 资金使用必须有对应的实施任务记录

#### 闭环 3：计划 → 执行 → 评估闭环

```
年度计划批复 → 任务分解派发 → 实施进度报告 → 竣工验收 → 效果评估 → 计划执行总结 → 下一年度计划参考
```

**闭环校验点**：
- 年度计划完成率统计
- 延期项目原因分析
- 评估结果反馈到下一年度计划编制

### 6.3 状态流转规则

#### 体检问题状态机

```
待核实 ──核实通过──▶ 已核实 ──转化为项目──▶ 已转化 ──评估确认解决──▶ 已关闭
  │                    │
  └──核实退回──▶ 已关闭  └──评估确认未解决──▶ 已核实（重新进入项目转化）
```

#### 储备项目状态机

```
待论证 ──开始论证──▶ 论证中 ──论证通过──▶ 已入库 ──立项审批通过──▶ 已转出
                        │
                        └──论证不通过──▶ 已淘汰
```

#### 立项项目状态机

```
待立项 ──提交立项──▶ 立项审批中 ──审批通过──▶ 已立项 ──纳入年度计划──▶ 实施中
                        │                                              │
                        └──审批退回──▶ 待立项                           ▼
                                                              已竣工 ──发起评估──▶ 已评估 ──归档──▶ 已归档
```

#### 年度计划状态机

```
编制中 ──提交审批──▶ 审批中 ──审批通过──▶ 已批复 ──开始执行──▶ 执行中 ──年度结束──▶ 已完成
                        │
                        └──审批退回──▶ 编制中
```

### 6.4 数据完整性约束

| 约束规则 | 说明 |
|---------|------|
| **问题必须归属片区** | 每个 `InspectionIssue` 必须关联一个 `RenewalArea` |
| **问题转化唯一性** | 一个问题只能转化为一个储备项目（1:1） |
| **立项前置条件** | `Project` 的创建必须基于一个状态为"已入库"的 `ReserveProject` |
| **计划项目资金必填** | 每个 `PlanProject` 必须至少关联一个 `FundingArrangement` |
| **验收前置条件** | `CompletionReport` 的创建必须基于状态为"待验收"的 `ImplementationTask` |
| **评估对照问题** | `AssessmentReport` 必须关联至少一个 `InspectionIssue` 进行效果对照 |
| **年度唯一性** | 同一项目在同一年度只能有一个 `PlanProject` 记录 |

## 八、关键统计指标

### 8.1 体检阶段指标

| 指标名称 | 计算方式 | 说明 |
|---------|---------|------|
| 问题发现总数 | COUNT(InspectionIssue) | 累计发现的体检问题数 |
| 问题核实率 | COUNT(已核实+已转化+已关闭) / COUNT(全部问题) | 问题核实的完成比例 |
| 问题转化率 | COUNT(已转化) / COUNT(已核实) | 核实问题转化为项目的比例 |
| 问题闭环率 | COUNT(已关闭) / COUNT(已核实) | 已核实问题最终解决的比例 |

### 8.2 项目阶段指标

| 指标名称 | 计算方式 | 说明 |
|---------|---------|------|
| 储备项目数 | COUNT(ReserveProject) | 项目储备库中的项目数 |
| 立项转化率 | COUNT(Project) / COUNT(ReserveProject) | 储备项目成功立项的比例 |
| 年度计划覆盖率 | COUNT(PlanProject) / COUNT(Project) | 已立项项目纳入年度计划的比例 |
| 计划完成率 | COUNT(已完成PlanProject) / COUNT(全部PlanProject) | 年度计划项目的完成比例 |
| 资金到位率 | SUM(已到位资金) / SUM(计划资金) | 资金拨付到位的比例 |

### 8.3 实施阶段指标

| 指标名称 | 计算方式 | 说明 |
|---------|---------|------|
| 任务完成率 | COUNT(已完成Task) / COUNT(全部Task) | 实施任务的完成比例 |
| 验收通过率 | COUNT(验收通过) / COUNT(已验收) | 竣工验收一次通过率 |
| 平均实施周期 | AVG(实际竣工日期 - 计划开工日期) | 项目平均实施时长 |
| 延期率 | COUNT(延期项目) / COUNT(全部项目) | 项目延期的比例 |

### 8.4 评估阶段指标

| 指标名称 | 计算方式 | 说明 |
|---------|---------|------|
| 评估覆盖率 | COUNT(已评估Project) / COUNT(已竣工Project) | 竣工项目完成评估的比例 |
| 居民满意度 | AVG(满意度评分) | 居民对更新效果的满意度 |
| 问题解决率 | COUNT(评估确认解决的问题) / COUNT(已核实问题) | 体检问题最终解决的比例 |
