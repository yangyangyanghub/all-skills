模块四：验收标准怎么写 AI 才不跑偏

好的任务书 = 目标 + 边界 + 验收标准 + 现有参照

派活给 AI，最容易踩的坑是**任务书太模糊**。你说"帮我写个签名组件"，它给你一个能跑但不符合我们规范的东西——用了 any、没删死代码、风格和现有代码对不上。 好的任务书 = **目标 + 边界 + 验收标准 + 现有参照**。 **目标**：一句话说清要什么。 **边界**：改哪些文件，不许动哪些。 **验收标准**：什么算做完。越具体越好，比如"2 空格缩进、禁止 any、复用现有 request 封装"。 **现有参照**：指给它看项目里已有的类似实现，让它照着写，别自己发明一套。 好的派活**不是**"你帮我写个 X"，**而是**"照着这个文件的风格，在这几个文件范围内，实现 X，满足这几条标准"。
