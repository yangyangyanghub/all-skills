# 下班复盘（Daily Review）

聚合当日工作数据，生成结构化复盘，写入日报文件。让每天的工作成果可追溯、可沉淀、可复盘。

## 触发规则

| 用户说 | 触发 |
|--------|------|
| "下班" / "下班了" | 当日复盘 + 整理日报 |
| "复盘" / "总结今天" / "今天干了什么" | 当日复盘 |
| "生成日报" / "写日报" | 整理当日日报 |
| "本周复盘" / "周报" | 周复盘（聚合本周日报） |
| "项目复盘" | 项目级复盘（需指定项目） |

## 数据源聚合

复盘自动聚合以下数据源：

| 数据源 | 获取方式 | 用途 |
|--------|---------|------|
| **git 提交** | `git log --since="今天 00:00" --oneline` | 当日代码/文档改动 |
| **新建文档** | 扫描 `myk/`、`daily-report/` 当日新建的 .md | 工作产出 |
| **修改文档** | `git log` + 文件 mtime | 工作活动 |
| **当日待办** | 读取 `daily-report/.tdlist.md` 和 `kanban.md` | 待办完成情况 |
| **当日流水** | 读取 `daily-report/.today.md` | 手动记录的当日工作 |
| **会话记录** | 从 opencode 会话存储或 `.memory/` 提取 | AI 协作摘要 |
| **昨日计划** | 读取昨日日报的「明日计划」 | 对比计划完成度 |

## 复盘流程

```
用户说"下班"
    ↓
1. 收集数据源（git/文档/待办/流水）
    ↓
2. 交叉核对：昨日计划 vs 今日完成
    ↓
3. 生成复盘草稿（结构见下方模板）
    ↓
🔴 CHECKPOINT：展示草稿，等用户确认后再写入
    ↓
4. 写入 daily-report/YYYY-MM-DD.md（追加或新建）
    ↓
🔴 CHECKPOINT：确认已写入后，再清空 .today.md
    ↓
5. 清空 .today.md（当日流水归档）
    ↓
6. 更新 kanban.md（待办状态流转）
    ↓
7. 汇报：今日完成 X 项，明日计划 Y 项
```

## 🔴 失败模式与兜底处理

| 触发条件 | 一线修复 | 仍失败时的兜底 |
|---------|---------|--------------|
| 不在 git 仓库（`git rev-parse` 失败） | 跳过 git 数据源，用文件 mtime + .today.md | 只输出基于文档和流水的手动复盘 |
| 当日无 git 提交 | 从 .today.md + 新建/修改文档提取工作 | 标注"今日无提交"，不编造提交内容 |
| `.today.md` 为空或不存在 | 从 git + 待办 + 昨日计划生成复盘 | 询问用户今日做了什么，或生成"今日无记录"占位 |
| 昨日日报不存在（无法对比计划） | 跳过计划对比，直接复盘当日 | 在「明日计划」中标注无基准 |
| 用户要求周复盘但本周日报缺失 | 聚合现有日报，缺失日期标注"无记录" | 询问是否只复盘已有数据 |
| 用户要求项目复盘但未指定项目 | 追问具体项目名 | 列出近期活跃项目让用户选择 |
| 清空 .today.md 前用户反悔 | 不清空，保留流水 | 询问是否归档到日报后再清空 |
| 日报文件已存在（重复触发） | 读取现有内容，追加或合并 | 询问用户覆盖 / 追加 / 跳过 |

## 🛑 Do not do 黑名单

- 不要把 git commit message 原样罗列——要归类提炼成"完成的事"
- 不要在没有数据时编造工作内容或量化数字
- 不要跳过用户确认直接清空 `.today.md`（不可逆操作）
- 不要把复盘写成流水账——要成果导向（完成了什么有价值产出）
- 不要忽略阻塞和风险——问题诚实是复盘的核心价值
- 周复盘不要只复制 5 份日报——要聚合趋势和遗留问题
- 不要修改 git 历史、提交或推送——复盘只读，输出到日报文件

## 复盘输出模板

写入日报时，按以下结构组织（与 AGENTS.md 日报规范一致）：

```markdown
# Metainfo

* Title:YYYY-MM-DD 工作日报
* Author:WY
* Date:YYYY-MM-DD ddd
* Tags:
	* #工作日志
	* #生活记录

---

## 今日内容

（按时间或项目分组，来自 .today.md + git 记录）
- HH:MM 工作项一
  - 细节/结果
- 项目二：完成什么，产出什么

---

## AI工具应用情况

（依据今日 AI 协作内容自动总结）
- 用了哪些 AI 工具/技能：如 deep-research、image-service
- 解决了什么问题
- 产出了什么

---

## 今日小结

- 亮点：今日最值得记录的 2-3 件事
- 问题：遇到的阻塞、待解决的
- 改进：明日要怎么改进

---

## 明日计划

- [ ] 从今日遗留 + 待办看板提取
```

## git 提交聚合

当日 git 提交转成可读内容：

```bash
# 当日提交
git log --since="2026-08-14 00:00" --oneline

# 详细
git log --since="2026-08-14 00:00" --stat --pretty="format:%h %s"
```

按提交主题归类（feat/fix/docs/refactor 等），提炼当日完成的"事"。

## 周复盘模板

用户说"本周复盘"时，聚合本周日报生成周复盘：

```markdown
# Metainfo

* Title:YYYY-WNN 周复盘
* Author:WY
* Date:YYYY-MM-DD ddd
* Tags:
	* #工作日志
	* #周复盘

---

## 本周完成

- （聚合本周每日日报的「今日内容」，按项目归类）

## 本周趋势

- 主要投入方向：X、Y、Z
- 项目进展：哪些项目有实质推进
- 遗留问题：本周未闭环的事项

## 效率洞察

- 峰值日：周X（完成最多的一天）
- 低效日：周Y（原因分析）

## 下周计划

- [ ] 本周遗留 + 新出现 + 长期任务
```

## 复盘要点

1. **成果导向**：不是流水账，是"今天完成了什么有价值的产出"
2. **量化优先**：能数字化的数字化（X 个文件、X 次提交、X 个功能）
3. **问题诚实**：阻塞、风险、未完成都要写，不粉饰
4. **计划衔接**：明日计划 = 今日遗留 + 新出现 + 长期任务
5. **AI 总结**：AI工具应用情况体现 AI 协作价值

## 与 AGENTS.md 下班流程配合

本技能是 AGENTS.md「三、每日工作流程 → 下班任务」的执行工具：

```
下班任务（原）：
1. 读 .today.md → 整理日报
2. 清空 .today.md
3. 更新 kanban.md
4. Wiki 维护

下班任务（增强后）：
1. 触发复盘（本技能）→ 聚合 git/文档/待办
2. 写入 daily-report/YYYY-MM-DD.md
3. 清空 .today.md
4. 更新 kanban.md
5. Wiki 维护
```
