# 自然资源监管领域模板

> 适用于：自然资源低空监管、土地违法监测、耕地保护、批后监管、违建房监管
> 来源：某县自然资源低空智能监管体系项目经验沉淀

---

## 领域核心认知

自然资源监管不是"把无人机放到地图上"，而是**"时空数据底座 + 套合监管系统 + 卫星遥感 + 低空巡查 + 业务闭环"**的县域自然资源监管体系。

监管真正要回答的问题：
- 变化发生在哪里？占了什么地类？
- 是否压占永久基本农田、生态保护红线、城镇开发边界？
- 是否有审批、是否超审批、是否少批多占？
- 责任主体是谁，归哪个乡镇、村、宗地或权利人？
- 后续如何核查、整改、复核、归档？

> 关键论断：空间套合比 AI 模型更重要。AI 只做"辅助发现线索"，属性研判靠套合监管。

## 对象类型（建议起点）

| 对象 | 说明 | 关键属性 | 可编辑 |
|------|------|---------|--------|
| 设备（无人机） | 一机一档、一机一码 | 主编号、外部 ID 映射（民航登记/厂商序列号/公安备案号）、在线状态 | 否（来源系统） |
| 任务 | 巡查/核查任务 | 任务编号、类型、执行设备、航线、状态 | 部分（执行状态） |
| 成果资产 | 照片/视频/航迹/识别结果 | 关联任务、关联设备、采集时间、坐标 | 否 |
| 图斑/线索 | 变化发现 | 位置、地类、面积、影像证据、AI 置信度 | 部分 |
| 问题台账 | 认定后的监管问题 | 问题类型、涉及对象、责任主体、状态 | 是（流转） |
| 地块/宗地 | 权属单元 | 行政区、村界、宗地号、权利人 | 否 |

### 设备编码原则（邯郸实践）

平台主编号只标识设备身份，**不承载**单位、任务、乡镇或临时载荷；外部 ID 作为映射字段维护：

```text
HD-UAV-{区县行政区划代码}-{飞行器类别码}-{四位流水号}
```

## 链接类型（建议起点）

| 链接 | 两端对象 | 关系语义（两侧） | 基数 |
|------|---------|----------------|------|
| 执行 | 任务 ↔ 设备 | 任务使用设备 / 设备执行任务 | N:1 |
| 产出 | 任务 ↔ 成果 | 任务产出成果 / 成果来自任务 | 1:N |
| 发现 | 成果 ↔ 图斑 | 成果包含图斑 / 图斑来自成果 | 1:N |
| 认定 | 图斑 ↔ 问题 | 图斑转为问题 / 问题源于图斑 | N:1 |
| 归属 | 问题 ↔ 地块/宗地 | 问题位于地块 / 地块存在问题 | N:1 |
| 套合 | 图斑 ↔ 管理数据（地类/规划/红线/审批/权属） | 图斑套合判断属性 | M:N |

**套合对象表**（判断用）：

| 套合对象 | 套合目的 | 输出判断 |
|---------|---------|---------|
| 地类图斑 | 判断占用地类 | 耕地/建设用地/林地/园地/未利用地 |
| 永久基本农田 | 判断是否触碰底线 | 是否占用永久基本农田 |
| 国土空间规划 | 判断是否符合规划用途 | 是否符合规划管控要求 |
| 城镇开发边界 | 判断建设管控范围 | 集中建设区/边界外 |
| 生态保护红线 | 判断生态约束 | 是否压占生态保护红线 |
| 审批红线 | 判断合法审批依据 | 未批先建/超范围/少批多占 |
| 权属/宗地 | 判断责任主体 | 关联乡镇/村/单位/权利人 |

## 操作类型（建议起点）—— 问题闭环是核心

```
影像采集 → 智能识别 → 疑似图斑 → 自动套合 → 属性研判 → 人工核查 → 整改处置 → 低空复核 → 台账归档
```

| 操作 | 参数 | 验证规则 | 副作用 | 权限 | 审计 |
|------|------|---------|--------|------|------|
| 派发 | 问题 ID、处置单位、时限 | 问题已认定且未派发 | 创建整改任务、通知处置单位 | 监管中心 | 记录派发人/时间 |
| 认领 | 任务 ID、处置人 | 任务已派发且未认领 | 任务状态→进行中 | 处置单位 | 记录认领人 |
| 整改上报 | 任务 ID、整改照片、说明 | 有整改动作 | 待复核状态 | 处置单位 | 记录上报内容 |
| 复核 | 任务 ID、复核影像 | 必须有整改上报记录 | 通过→销号 / 不通过→退回整改 | 监管中心 | 记录复核人/结论 |
| 销号归档 | 问题 ID | 复核通过 | 问题→已归档，生成台账 | 监管中心 | 记录归档时间/结论 |
| 变更 | 对象 ID、变更内容 | 权限校验 | 写入变更记录 | 按角色 | 完整变更日志 |

**六条主线（平台建设重点）**：设备底账、实时态势、任务管理、成果资产、空间套合、问题闭环——缺一不可，只做 AI 识别不做处置闭环是最大坑。

## 场景模板（某县实践 5 类）

| 场景 | 发现方式 | 套合判断 | 输出成果 |
|------|---------|---------|---------|
| 耕地保护监管 | 卫星变化/低空巡查/田长制线索 | 占耕/占永农/非农化非粮化 | 疑似图斑、面积统计、影像证据 |
| 违法用地监管 | 新增变化图斑/举报 | 审批/超范围/符合规划 | 未批先建/少批多占清单 |
| 设施农用地监管 | 低空影像/备案数据 | 超备案/变用途/硬化 | 问题台账、前后对比图 |
| 建设项目批后监管 | 红线叠加影像/进度巡查 | 按范围建设/超红线/闲置 | 批后监管清单、进度影像 |
| 违建房监管 | 低空巡查/变化检测 | 地类/规划/审批/权属 | 疑似违建点位、拆后复核成果 |

---

## 表达边界（写方案时遵守）

- 不把低空巡查讲成主角，主角是自然资源监管体系
- 不承诺 AI 自动判定违法，只表达为辅助发现线索和辅助研判属性
- 场景必须贴合地方实际（如某县没有矿山就不设矿山监管）
- 不把展示型大屏作为优先建设重点，设备底账和问题闭环更关键
