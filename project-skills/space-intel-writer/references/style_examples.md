## 1. 开头范例

### 痛点场景型

适合技术教程、案例拆解。

> 你是不是遇到过这样的情况：手里有一批 Shapefile，要统一转成 GeoJSON。一个个打开 QGIS 导出，半小时过去，只处理了几个文件。今天这篇就用 GeoPandas 把这个流程自动化。

### 数据/变化冲击型

适合行业快报、趋势分析。

> 最近自然资源数据相关政策更新比较密集。对 GIS 开发者来说，这不是新闻摘要，而是会直接影响数据接入、成果交付和系统设计的一组约束。

### 项目复盘型

适合真实项目和方法论文章。

> 最近整理学区划片数据时，我遇到一个很典型的问题：两张表里都有小区字段，但名称、编码、范围都对不上。这个问题看起来是 Excel 清洗，其实背后是空间数据治理。

### 空间智能破题型

适合 GeoAI、GeoAgent、自然语言 GIS 文章。

> 很多人以为自然语言 GIS 就是「对着地图聊天」。但真正值得关注的不是聊天框，而是系统能不能把一句话拆成空间查询、空间分析和结果审查。

## 3. 术语解释修改对比

### 错误写法

> 使用 GeoPandas 进行空间连接，然后输出结果。

问题：假设读者都懂 GeoPandas 和空间连接。

### 推荐写法

> 使用 GeoPandas（Python 地理数据处理库）进行空间连接。空间连接可以理解为「按地理位置合并两份数据」，比如把小区点位和学校服务范围匹配起来。

### 错误写法

> GeoAgent 可以自动完成 GIS 操作。

问题：太泛，没解释智能体到底做了什么。

### 推荐写法

> GeoAgent（自然语言 GIS 智能体）负责把用户的一句话拆成 GIS 操作序列。例如「显示 3 公里内的学校」会被拆成地址定位、缓冲区分析、空间筛选和地图渲染几个步骤。

## 4. 步骤写法修改对比

### 错误写法

> 安装好 Python 环境，配置一下依赖，然后运行脚本就行。

问题：跳步，对新手不友好。

### 推荐写法

```bash
python -m venv .venv
.venv\Scripts\activate
pip install geopandas pyogrio
python convert_shp_to_geojson.py
```

> 这里容易卡在 `geopandas` 安装。如果 Windows 下安装失败，优先使用 conda 环境，或者改用 `pyogrio` 读取数据。

## 7. SEO/GEO 关键词嵌入正反例

关键词优化的目标是让文章更容易被搜索和引用，不是把文章写成关键词清单。

### 关键词堆砌反例

> 自然语言 GIS 是 AI GIS 的重要方向，自然语言 GIS 可以帮助 GIS 用户使用自然语言 GIS 完成 AI GIS 空间分析，GeoAgent 也是自然语言 GIS 和 AI GIS 的重要技术。

问题：

- 重复机械，读者体验差
- 没有解释概念，也没有具体场景
- 像搜索引擎垃圾内容
- 没有体现「从地理信息到空间智能」的判断

### 自然嵌入正例

> 过去做空间分析，往往需要在 QGIS、ArcGIS 或 WebGIS 系统里反复选择工具、配置参数、检查图层。现在，自然语言 GIS 和 GeoAgent 正在改变这个流程：用户只需要提出问题，系统就可以理解空间对象、空间关系，并自动完成缓冲区分析、叠加分析、制图和报告生成。

优点：

- 主关键词自然出现
- 覆盖 QGIS、ArcGIS、WebGIS 等工具词
- 有空间对象、空间关系等语义词
- 有缓冲区分析、叠加分析、制图、报告生成等任务词
- 读起来是正常文章，不像关键词堆砌

### 标题优化对比

| 不推荐 | 推荐 | 原因 |
|---|---|---|
| AI GIS 自然语言 GIS GeoAgent 空间分析自动化教程 | 自然语言 GIS 正在重构空间分析：从 AI 问答到 GeoAgent 工作流 | 保留核心关键词，但变成可阅读的判断 |
| 空间智能 GIS WebGIS 遥感 AI 大模型应用 | 从地图查询到空间推理：空间智能到底改变了什么 | 从词语罗列改成能力变化 |
| GeoPandas Shapefile GeoJSON Python GIS 教程 | 用 GeoPandas 批量转换 Shapefile：从数据清洗到 GeoJSON 输出 | 明确工具、任务和结果 |

### GEO 友好问答段落

适合插入文章中段或结尾，帮助 AI 搜索摘录。

```markdown
### 自然语言 GIS 适合解决什么问题？

自然语言 GIS 适合解决重复性强、规则明确、流程可拆解的空间分析任务，例如缓冲区分析、叠加分析、用地适宜性评价、遥感变化检测结果查询、自动制图和报告生成。它不适合完全依赖专家判断、数据质量不明或责任边界不清的复杂决策。
```

优点：

- 问题清楚
- 答案完整
- 有适用场景
- 有边界条件
- 方便 AI 搜索引用

### 开头优化对比

**普通开头**：

> 近年来，随着人工智能技术不断发展，AI GIS 受到了越来越多关注。

问题：空泛，没有关键词场景，也没有读者痛点。

**优化后**：

> 过去做空间分析，GIS 工程师需要在 QGIS、ArcGIS 或 WebGIS 系统里反复配置图层、选择工具、检查参数。自然语言 GIS 的变化在于，它把「用户点菜单」变成「系统理解任务」：先识别空间对象和空间关系，再调用合适工具完成查询、分析、制图和报告生成。

优点：开头自然嵌入主关键词、工具词、痛点词和空间智能主线。

## 8. 转场与扣主线句

好的技术文章也需要节奏。每一段背景、表格、案例之后，用一句话拉回主线。

可直接使用：

- 回到这篇文章真正要解决的问题。
- 对 GIS 开发者来说，真正要关注的是这三点。
- 这也是为什么我建议先做最小闭环。
- 所以这个工具不是能不能用，而是适合谁用。
- 如果把它放回「从地理信息到空间智能」这条线上，它解决的是空间行动这一层。
- 它不是让地图更好看，而是让空间关系更容易被理解和复用。

避免：

- 接下来让我们深入探讨。
- 值得注意的是。
- 综上所述。

## 9. 结尾范例

### 技术教程结尾

> 今天我们用 GeoPandas 完成了 Shapefile 到 GeoJSON 的批量转换。这个流程看起来简单，但它解决的是 GIS 项目里最常见的数据预处理问题。
>
> 如果你手里也有一批矢量数据，可以先用这套脚本跑一遍。下期我们继续讲坐标系转换，尤其是 WGS84、CGCS2000 和投影坐标之间最容易踩的坑。

### 工具测评结尾

> 如果你追求低成本和可控性，QGIS 更适合入门和自动化；如果你需要完整商业生态和成熟工具链，ArcGIS Pro 依然更稳。
>
> 所以这不是谁替代谁的问题，而是场景选择问题。你现在主要用哪套 GIS 工具？评论区可以说说你的理由。

### 空间智能文章结尾

> 自然语言 GIS 的价值，不是让地图多一个聊天框，而是让空间任务从「专家手动操作」变成「系统理解、拆解、执行和审查」。
>
> 这才是从地理信息走向空间智能的关键一步。下一篇，我准备继续拆 GeoAgent 的两条工程路线：函数调用和代码生成，到底该怎么选。

## 10. AI 腔段落改写、短句库与禁用表达

### AI 腔原文 → 空间智研社改写版 → 修改说明

**AI 腔原文**：

> 随着技术不断发展，AI 与 GIS 正在深度融合，并赋能千行百业。值得注意的是，空间智能生态闭环正在加速形成，未来已来。综上所述，相关从业者应积极拥抱这一趋势。

**空间智研社改写版**：

> AI GIS 真正改变的不是口号，而是项目流程。过去做一轮用地筛选，工程师要先找数据、配图层、跑缓冲区、做叠加分析，再人工检查结果。现在可以把这些动作拆成一条可审查的任务链：识别地块和限制条件，调用空间分析工具，输出候选范围，再把数据缺口和风险点列出来。它能帮人少做重复操作，但不能替人承担规划判断。

**修改说明**：

- 把抽象趋势改成具体任务：用地筛选、缓冲区、叠加分析。
- 把「AI 改变行业」改成「AI 改变流程」，更贴近空间智研社主线。
- 保留边界：能减少重复操作，不能替代专业判断。

### 短句库

- 开头：如果你做过一次完整的空间分析，就知道麻烦往往不在模型，而在数据和流程。
- 开头：这篇不聊概念热不热，只看它能不能解决 GIS 项目里的真实问题。
- 主线转场：把它放回「从地理信息到空间智能」这条线，关键不是工具更炫，而是空间关系能不能被理解和复用。
- 主线转场：到这里，问题就从「怎么操作」变成了「系统能不能自己拆任务」。
- 证据边界：这个判断只基于当前公开资料和可复现流程，不能直接外推到所有项目。
- 证据边界：如果数据源、坐标系或业务规则换了，结论需要重新验证。
- 风险提醒：最容易踩坑的地方，是把演示效果当成生产能力。
- 风险提醒：空间智能不是跳过专业审查，而是把审查节点显性化。
- 结尾互动：你在项目里遇到过哪类空间分析最耗时间？评论区可以丢一个场景。
- 结尾互动：下一篇可以继续拆工具链，也可以做一个实战脚本，你更想看哪个？

### 禁用表达清单

- 赋能
- 深度融合
- 千行百业
- 生态闭环
- 未来已来
- 值得注意的是
- 综上所述
- 随着技术不断发展
- 释放巨大潜能
- 全面重塑行业格局
- 打造全新范式
- 实现降本增效
- 开启智慧新时代
- 具有重要意义
- 持续迭代升级
- 反直觉（修饰观点和判断时禁；只能用在「这个结论确实反直觉」这类对结论本身的客观陈述）
- 完全同构
- 物理意义上的
- 恰恰（全部替换为「正好」）
- 这是一个
- 这对于
- 画几条线（作为「设边界」的隐喻）
- 正名 + 期待（中英文混 + 符号）

## 11. 公众号排版规范

排版服务阅读节奏，不为了显得复杂而堆格式。

| 项目 | 建议 |
|---|---|
| 篇幅 | 普通公众号文章 1500-3000 字，深度技术文章可到 4000-6000 字 |
| 段落 | 单段尽量 200-300 字以内，长段拆成短段 |
| 表格 | 控制在 3-5 列，字段太多时拆成多个表 |
| 代码块 | 必须标注语言，关键行用中文注释说明为什么这样写 |
| 图片 | 用 `[截图：说明]` 或 `[示意图：说明]` 标注位置和用途 |
| emoji | 默认不用；确需强调时每篇不超过 3 个 |

技术文章里的代码示例要能复制运行。版本、依赖、数据假设不确定时，先写版本说明或「待验证」，不要假装已经实测。

Obsidian 内部草稿可以使用 callout，但正式公众号发布前要确认平台是否支持：

```markdown
> [!note] 版本说明
> 文中操作基于 QGIS 3.34。其他版本界面可能略有差异。
```

## 12. 去 AI 味方法论 — 修改清单

成稿或改稿完成后，**必须逐条过以下 6 类检查**。这是交付前最后一道门禁，不是可选的。

### 一、删重复啰嗦

**症状**：同一层意思用两个短句各说一遍，像怕读者看不懂。

**改法**：合并为一句，补上因果或删掉后半句。

| 改前（啰嗦） | 改后（精简） |
|---|---|
| 这部分工作远程做不了，远程看代码改不了。 | 这部分工作没法远程 — 代码在客户内网，数据出不了环境，人必须到场。 |
| 一次能跑通和能稳定跑通 100 次，是两件完全不同的事。 | 能跑通一次和能稳定跑通 100 次，是两件完全不同的事。 |
| 不是政策在追新词，而是产业到了这个阶段。 | 不是政策在追新词，是产业到了这个阶段。 |

### 二、反问句式改陈述句

**症状**：用反问句制造气势，读起来像演讲不是文章。

**改法**：直接陈述。

| 改前（反问腔） | 改后（陈述） |
|---|---|
| 远程开发？数据出不了内网。远程 debug？服务器不在公网。 | 数据出不了内网，服务器不在公网 — 远程开发和 debug 都做不了。 |
| 为什么 Harness 这个词被写进政策？ | （删除自问自答，直接给判断） |

### 三、AI腔词汇替换

| AI腔 | 替换为 |
|---|---|
| 画的是一张 | 就是 |
| 把（它/这个）拆开看，意思就出来了 | 拆开看就明白了 |
| 它研究的是 | 它管的是 |
| 原因有三 | 三个原因 |
| 翻译一下 | 说白了 |
| 完全同构 | 本质一样 |
| 物理意义上的嵌入 | 人直接嵌进去 |
| 恰恰 | 正好 |
| 反直觉（修饰判断） | 听着反直觉 / 看着反直觉 |
| 一蹴而就 | 一劳永逸 / 一步到位 |
| 分桶之后 | 分完桶 |
| 正名 + 期待 | 正名，也带着期待 |
| 值得每个团队认真看一遍 | 每个团队都该读一遍 |
| 在这个过程当中 | 在这过程中 |
| 对一个（GIS工程师/团队）来说 | 对（GIS工程师/团队）来说 |

### 四、啰嗦从句精简

**症状**：修饰语太多，读起来气短。

**改法**：砍定语、砍量词。

| 改前 | 改后 |
|---|---|
| 对一个本来就存在的工作的重新定义和重新定价 | 对本来就存在的工作重新定义、重新定价 |
| 对企业业务流程的理解深度 | 对企业业务的理解深度 |
| 这一节很重要，避免文章被误读 | 几个边界先划清楚，免得误读 |
| 一个反直觉但关键的事实 | 有个事实可能反直觉 |
| 这个判断很反直觉，但它是 FDE 在 2026 年被资本重金投入的根本理由 | 听着反直觉，但这就是 FDE 在 2026 年被资本重金投入的根本原因 |

### 五、删除无效 meta-commentary

**症状**：文章里评论文章，像在教读者怎么读。

**改法**：直接进入正题。

| 改前 | 改后 |
|---|---|
| 写到这里要画几条线。 | 删除，直接从下一句开始。 |
| 这一节很重要，避免文章被误读。 | 几个边界先划清楚，免得误读。 |
| 不喊口号，给能落地的。 | 不喊口号，说点能落地的。 |

### 六、量词"一个"滥用检查

**重点排查**：正文中「一个FDE」「一个GIS工程师」「一个低空巡查项目」这类表达，多数情况下「一个」是多余的。

| 改前 | 改后 |
|---|---|
| 一个 FDE 进了这种客户，应该做什么？ | FDE 进入这类客户后，具体该做什么？ |
| 一个 GIS 工程师 | GIS 工程师（除非强调"单个"含义） |
| 对一个 GIS 工程师来说 | 对 GIS 工程师来说 |

### 执行规则
