# 院文件总入口路由

> **职责单一**：识别交付物类型 → 路由到子技能。**不写正文、不抽变量、不查合同**。

## 一、院文件交付物分类表（必查）

收到任何院内文件请求时，**先问"这是什么类型的交付物"**，再路由：

| 交付物类型 | 触发词举例 | 子技能（已实现） | 子技能（规划中） |
|---|---|---|---|
| 资金支付 / 合同款拨付 / 大额资金议事申请 | 支付、付款、拨款、议事申请、资金请拨、合同费、服务费、技术开发费 | **yuandangwen-zhifu** | — |
| **会议通知 / 培训通知 / 视频会议通知 / 现场会通知** | 会议通知、培训通知、视频会、座谈会、研讨会、推进会、"开个会""发个通知""出个公文" | **yuandangwen-tongzhi** | — |
| 会议纪要 / 议定事项清单 | 会议纪要、记要、台账、议定事项 | 规划中 | yuandangwen-jiyao |
| 调研报告 / 考察报告 / 预可研 | 调研、考察、预可研、可行性研究 | 规划中 | yuandangwen-diaoyan |
| 立项申请 / 项目可研 / 设计任务书 | 立项、任务书、可研、设计方案 | 规划中 | yuandangwen-lixiang |
| 向上级汇报材料 / 工作汇报 | 汇报、汇报材料、年度总结、工作情况 | 规划中 | yuandangwen-huibao |

## 二、路由判断流程

```
1. 用户提出院文件需求
2. 匹配"院文件特征"（甲方/乙方、项目名、院内/空间智研、办公室/财务/议事等关键词）
3. 如不匹配 → 不走本 skill（可能是对外文件、PPT、代码、公众号文章等）
4. 匹配成功 → 按"交付物类型"匹配触发词
5. 命中已实现子技能 → 转交子技能
6. 命中规划中子技能 → 告知用户"该类型尚未实现子 skill，是否走临时通用方案"
7. 完全不匹配 → 询问用户
```

## 三、必须询问的关键问题（在路由前完成）

无论路由到哪个子技能，下列问题**必问**（影响子技能是否能产出合格文件）：

1. **文件类型是什么**（如"支付申请""会议纪要"）？——决定走哪个子技能
2. **对应的合同/项目依据是什么**（合同文件路径、项目名称）？——子技能需要从原始材料抽变量
3. **走哪一级审批**（院领导/议事会议/财务部门）？——影响子技能生成的格式细节
4. **输出格式要求**（Markdown 给院办 word 模板套 / 直接生成 .docx / 仅起草文字）？——决定子技能的最终输出形式
