# yuandangwen-tongzhi · 会议通知公文

> 邯郸市自然资源和规划局及局属单位的会议通知起草与格式转换。
> 入口路由见 `../SKILL.md`。

## 何时使用本 skill

- 用户起草**会议通知**（含培训会议、视频会议、现场会等）
- 用户起草**培训通知**（含线上/线下培训）
- 用户起草**座谈会、研讨会、推进会**通知
- 用户说"开个会""发个通知""出份公文"，且对象是市/县自然资源局
- 已有 Markdown 草稿，需要转成符合本院公文格式的 Word（**禁止写"文件"红头/文号占位**）

## 何时**不**使用

- ❌ 售前方案（用 `pre-sales-solution`）
- ❌ 客户对外合同/投标文件
- ❌ 公众号文章（用 `space-intel-writer` 或 `khazix-writer`）
- ❌ 院内部文件（用 `yuandangwen-zhifu` 资金支付 或未来子技能）
- ❌ 汇报材料/议定事项（用其他子技能）
- ❌ 任何**不带"会议"性质**的公文（请示、报告、情况说明等）

## 起草工作流（3 步）

### 第 1 步：问关键 4 项（不超过 2 轮）

按 `references/必备要素清单.md` 的标准话术，**一次问清**：

1. 会议主送哪些单位？（**只列业务相关单位**，不堆通用主送语）
2. 参会人员限定到哪一层？
3. 联系人是谁？（姓名 + 电话，**必须由用户提供**，邮箱可选）
4. 视频会议吗？联调联系人是否另定一人？

> 🔴 **联系人铁律**：姓名/电话/邮箱**只能来自用户**。AI 绝不编造、绝不写 `【XXX】` 占位符，也绝不从历史文件照搬（必须向用户确认本次用谁）。缺联系人字段就停下问，**用户给多少写多少**——用户没提联调第二人，就只写已提供的那个。

**够了就开干**，不挨个追问。详见 `references/必备要素清单.md` 第四节。

### 第 2 步：起草 Markdown

按 `references/人工范本_会议通知.md` 的结构起草，**对照范本逐段写**：

| 段 | 写法 | 字体（最终 Word） |
|---|---|---|
| 1 | 邯郸市自然资源和规划局 | 黑体 22 居中 |
| 2 | 关于……的通知 | 黑体 22 居中 |
| 3 | 主送 | 仿宋 16 顶格 |
| 4 | 引言段 | 仿宋 16 首行缩进 |
| 5 | 一、二、三、四、五 | 黑体 16 |
| 6 | 普通正文 | 仿宋 16 |
| 7 | 会议内容（一）（二） | **楷体 16** |
| 8 | 有关要求（一）（二）（三） | 仿宋 16 |
| 9 | 联系人 | 仿宋 16 顶格 | 模板：`联 系 人： 武洋：18131026037`（**"联 系 人"中间带一个空格**，冒号后也带一个空格） |
| 10 | 落款 | 仿宋 16 右对齐 | 邯郸市自然资源和规划局 + 2026年9月7日 |

**绝对禁止**：
- ❌ 红头"文件"+ 文号占位 + 红色分隔线
- ❌ "局机关有关科室，局属有关单位"这种通用主送语
- ❌ "附件"段、"印发说明"段
- ❌ Markdown `**` 字面量残留到 Word（脚本会剥，但要确认脚本跑了）

### 第 3 步：Markdown → Word 转换

```bash
python <skill_dir>/scripts/md2docx.py <markdown_file>
```

脚本会：
- 剥 `## ` markdown 标题标记
- 过滤 `---` 分割线
- 全文统一处理 `**xxx**` 标记（剥字符 + 黑体 16）
- 按段位自动应用字体

**字体自检清单**（Word 转完后必须 verify）：
- [ ] 标题 2 行是黑体 22 居中
- [ ] 一级章节 5 个是黑体 16
- [ ] 会议内容（一）（二）是**楷体 16**
- [ ] 有关要求条款是**仿宋 16**（不是楷体）
- [ ] 没有任何 `**` 字符残留
- [ ] 没有"特此通知"重复出现
- [ ] 没有"附件"段、没有"印发"段

## 本次复盘（2026-09-07 9.8 视频会通知）

AI 实际犯过的 5 个错（已沉淀进 references）：

1. **因果倒置**——把"省厅来人"理解成"市局自办"
2. **堆通用主送语**——加了"局机关有关科室，局属有关单位"
3. **加红头/文号**——生成外行公文红头
4. **时间矛盾**——同一时间点既开线上会又下现场
5. **Markdown 字面量残留**——`**业务探讨**` 出现在 Word 里

详见 `references/必备要素清单.md` 第六节。

## 配套脚本

`scripts/md2docx.py` — Markdown → Word 转换器，已处理：

- 标题区 2 行（黑体 22 居中）
- 主送（仿宋 16 顶格）
- 一级章节（黑体 16）
- 会议内容 vs 有关要求字体区分（楷体 vs 仿宋）
- 联系人（顶格）
- 落款（右对齐）
- 全文 `**xxx**` 标记处理

依赖：`python-docx`（`pip install python-docx`）
