# 资金支付与请示报告子技能

> 专门处理院内资金支付类公文：**填好的 .docx 大额资金支付议事申请单**。
> 输出：基于院内固定 docx 模板自动填入情况说明内容 + 签字栏留空（手签）。

## 一、本技能处理什么

**核心交付物**：一份填好的 `.docx` 文件 —— 邯郸市规划设计院《大额资金支付议事申请单》

**文件结构**（8 行 × 6 列的单一表格）：

| 行 | 内容 |
|---|---|
| R0 | 「邯郸市规划设计院」（标题，加粗居中） |
| R1 | 「大额资金支付议事申请单」（副标题） |
| R2-R4 | **事项说明**主填写区：5 段情况说明 + 落款日期 |
| R5 | **签字栏**：说明人 / 部门负责人 / 部门主管院长（手签） |
| R6 | 管理部门审核（签章） |
| R7 | 备注 |

> 🔴 **关键变化（v2.0）**：本 skill 早期版本（v1.0）生成 Markdown 草稿 + 范本由 AI 自由发挥。**现 v2.0 改为**：**填入院固定 docx 模板**，保持院格式 100% 还原，仅内容由 AI 根据要素填入。**不再输出 Markdown 草稿**。

## 二、两步法（核心流程）

### 第 1 步：要素抽取（必做）

读取用户提供的材料（合同 doc/docx、情况说明范本、聊天记录等），按 **references/zhifu-variables-checklist.md** 逐项核对缺失变量，**主动询问**未提供的项。

**最低必须 10 项**（任一缺失必问）：
1. **项目名称**
2. **合同/服务名称**
3. **申请支付金额**（人民币大写 + 数字）
4. **付款方式**（**必问，从 3 种模式里选**）——见下方"付款方式三选一"
5. **合同对方单位**
6. **对方开户行 + 账号**
7. **对方联系人 + 联系电话**
8. **合同期限/服务期**
9. **支付依据**（合同文件名 + 编号）
10. **签字日期**（如不提供，按落盘当日）

**可选项**（缺失时 AI 主动建议）：
- 项目背景（自动从合同"项目目标"段抽取）
- 技术/服务内容摘要（自动从合同"建设内容"或"服务范围"段抽取）
- 议事会议级别（院党组会 / 院长办公会 / 院务会）

#### 付款方式三选一（必问）

> 🔴 **不能默认**。即使合同是 30/40/30 分期，AI 也要问"你这次是付哪一期？还是一次性？"，因为实际申请可能跟合同原条款不同。

**询问话术**（直接复制可用）：

```
这笔付款属于哪种情况？
  1. 一次性付清（合同本来就约定一次性）
  2. 合同分期付（按合同原定 X/Y/Z 期，本次付第 N 期）
  3. 合同变更后一次性付（原本分期，但经协商变更为一次性，需写明理由）

（如选 2 需告知第几期；如选 3 需告知变更理由）
```

**三种模式的 docx 付款方式段写法**：

| 模式 | 付款方式段写法 |
|---|---|
| ① 一次性付清 | `本次申请一次性支付全部合作费用人民币 X 万元。` |
| ② 合同分期付（第 N 期） | `按照《合同名》第 N 条约定，本次申请支付第 N 期合作费用人民币 X 万元（占合同总金额的 X%），即原合同总金额的 X%。` |
| ③ 合同变更后一次性付 | `经甲乙双方协商，本次将原合同约定的 X/Y/Z 分期付款变更为一次性支付全部合作费用人民币 X 万元，原合同其他条款不变。（变更理由 1-2 句）` |

### 第 2 步：模板填充

**核心动作**：读取院 docx 模板 → 找到 R2-R4 主事项说明 cell → 清空 → 写入新内容 → 保存。

**关键代码路径**（完整代码见 `assets/templates/支付申请_院内模板/_template-structure.md`）：

```python
from docx import Document
doc = Document(template_path)  # 院 docx 模板
for t in doc.tables:
    for row in t.rows:
        for cell in row.cells:
            if len(cell.text.strip()) > 100:  # 找到主事项说明 cell
                for p in cell.paragraphs:
                    p._element.getparent().remove(p._element)
                lines = new_text.split(chr(10))
                for i, line in enumerate(lines):
                    p = cell.add_paragraph()
                    if i == 0:
                        run = p.add_run(line)
                        run.bold = True
                    else:
                        p.add_run(line)
                break
doc.save(output_path)
```

**主事项说明的写入格式**（5 段 + 落款）：

```
支付<项目名>费用的情况说明
一、项目背景
<从合同"项目目标"段抽取 100-200 字>
二、合同费用
<合同总金额 + 构成>
三、付款方式
本次申请一次性支付全部合作费用人民币<金额>万元。
<如有特殊情况才写理由>
2026年9月7日
```

**输出文件路径**：

```
<项目根目录>/<项目名>/支付申请/邯郸市规划设计院-大额资金支付议事申请单-<项目名>.docx
```

## 三、关键细节

### 3.1 付款方式段（按 3 种模式生成）

**模式 ① 一次性付清**：
```
三、付款方式
本次申请一次性支付全部合作费用人民币48万元。
```

**模式 ② 合同分期付（第 N 期）**：
```
三、付款方式
按照《技术开发合同》第四条"研究开发经费、报酬及其支付或结算方式"约定，原合同项下合作费用分X期支付。本次申请支付第N期合作费用人民币X万元，占合同总金额的X%。
```

**模式 ③ 合同变更后一次性付**：
```
三、付款方式
经甲乙双方协商，本次将原合同约定的X期分期付款变更为一次性支付全部合作费用人民币48万元，原合同其他条款不变。（变更理由）
```

### 3.2 段落结构

| 段落 | 加粗 | 内容长度建议 |
|---|---|---|
| 第 1 段（标题） | **是** | 固定：`支付<项目名>费用的情况说明` |
| 第 2 段（一、项目背景 + 内容） | 否 | 项目背景 100-200 字 |
| 第 3 段（二、合同费用 + 内容） | 否 | 2-3 句：金额 + 构成 |
| 第 4 段（三、付款方式 + 内容） | 否 | 1-2 句 |
| 第 5 段（落款日期） | 否 | 固定：`YYYY 年 M 月 D 日` |

### 3.3 签字栏保持空白

R5/R6/R7 行**不填任何文字**，由相关人员手签 + 盖院章。

### 3.4 不动模板结构

- 表格行列数：8 行 × 6 列（不增不减）
- 标题行/副标题行：模板已设加粗居中，**不要改**
- 签字栏布局：模板已设好，**不要改**

## 四、必问与不必问的边界

**主动问**（必须问，否则生成不准确）：
- 金额（不能猜）
- **付款方式（3 选 1）**（不能默认一次性）
- 合同对方与账号（不能猜）

**不必问**（AI 自行抽取/生成）：
- 项目背景：从合同"项目目标"段直接抄
- 技术/服务内容摘要：从合同"建设内容"段归纳 50-200 字
- 文件存放路径：默认 `<项目根>/<项目名>/支付申请/`
- 签字日期：默认用落盘当日

**询问策略**（不啰嗦）：
- **第一轮必问**：付款方式（3 选 1）+ 金额 + 对方账号（3 个问题一次性问完）
- 第二轮（如必要）：项目名、合同名
- 不要列 10 个变量挨个问

## 五点五、失败模式与恢复（必读）

> 🔴 **本节是 dim3 失败模式编码的承载**——遇到下列情况必须按本表处理，不能硬跑。

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| **模板文件不存在**（`assets/templates/支付申请_院内模板/*.docx` 缺失） | 检查 `assets/templates/支付申请_院内模板/` 目录是否被打包进 .skill；`unzip -l yuandangwen.skill` 验证 | 改用 Markdown 草稿 + 明确告知"模板缺失，请提供 docx 模板路径或允许我先交付 Markdown 草稿" |
| **python-docx 库未装** | `pip install python-docx>=1.0` | 改用纯文本输出 + 给出完整 5 段情况说明，由用户手工套模板 |
| **合同 doc 是 WPS 旧格式（OLE2，magic bytes `D0CF11E0`）** | 用 `olefile` 库按 UTF-16LE + 强制中文重解码；扫描所有可读汉字段 | 只抽取合同"项目目标"段、关键金额、付款条款段；其他字段主动询问用户补 |
| **合同 doc 是加密 Word 文档**（olefile 读出乱码或 password-protected） | 提示用户提供解密的 docx 版本 | 放弃自动抽取，进入"全要素询问"模式——10 项必填变量全部主动问 |
| **用户拒绝提供 10 项必填中的任何一项**（最常见是合同对方开户行账号） | 第一次拒绝：提示"该项缺失会影响 docx 填写完整性"；第二次拒绝：允许用 `【待补：开户行账号】` 占位，输出到 docx 后由用户手工补 | 整张表填不上 → 不出 docx，输出 Markdown 草稿，标注哪些字段待补 |
| **付款方式用户选择 ② 但没说第几期** | 追问"按合同第几条？占总金额百分之多少？" | 默认按 30% 估算，docx 里写"首期（30%）"占位 |
| **付款方式用户选择 ③ 但没说变更理由** | 追问"为什么变更为一次性？院方与对方是协商一致还是有其他情况？" | 写"经甲乙双方协商"通用模板，理由栏留 `【待补：变更理由】` |
| **docx 模板被用户修改过**（表格行数变成 7 行或 9 行） | 重新读取模板结构，更新 `_template-structure.md` | 报错给用户"模板结构不符，请使用 skill 自带的 `assets/templates/支付申请_院内模板/` 模板" |
| **生成的 docx 路径已存在同名文件** | 默认覆盖，并在 log 提示"已覆盖" | 询问用户是覆盖、追加日期后缀、还是取消 |
| **workspace 中已有同名项目支付申请 docx**（重复执行） | 提示"已有 YYYY-MM-DD 的同名 docx，是否覆盖？" | 加日期后缀如 `...单-<项目名>-v2.docx` |

### 五点五.1 失败模式识别 checklist（执行前自查）

AI 接到支付申请任务时，**先跑一遍这个 checklist**：

- [ ] 模板文件可达？→ 不可达走"模板文件不存在"分支
- [ ] python-docx 可导入？→ 不可导入走"库未装"分支
- [ ] 合同/输入材料存在且可读？→ 不可读走"加密/格式错误"分支
- [ ] 10 项必填变量已齐？→ 缺哪项问哪项
- [ ] 付款方式 3 选 1 用户已选？→ 没选追问；选 ② 问第几期；选 ③ 问理由
- [ ] 输出路径无冲突？→ 有冲突按"路径已存在"分支处理

**全部 PASS 才进入正式生成**。任一项不通过，按对应分支处理，**不要硬跑全流程**。
