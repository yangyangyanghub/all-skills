# /deep 深度任务升级

## 为什么存在

"请扮演一位 20 年经验的专家"是无效用法——只让 AI 模仿了专家的语气，没要求它使用专家真正解决问题的方法。
本技能把 Felix 的四问提示词固化为工作流：**接到任务先不改写任务，回答四问，按答案重写任务，再执行**。

## 工作流（四步，缺一不可）

### 第 1 步：识别任务类型

判断用户任务属于哪类，决定升级方向：

- **写方案 / 做调研 / 定架构 / 设计机制** → 四问 + 高度（任务完成后用户要什么结果？）
- **数据分析 / 结论验证** → 四问 + 深度强化（用真工具、验证常识）
- **创意产出 / 汇报材料** → 四问 + 广度（名词换动词，借用其他领域方法）

### 第 2 步：回答四问（输出给用户看）

在动手前，先明确回答以下四问（回答要具体到这个任务本身，不许空话）：

1. **这个领域的顶尖专业人士，会做哪些用户没有提出要求的工作？**
2. **他们会从哪些最原始的材料入手，而不是使用已经整理、加工过的内容？**
3. **他们具体会采用哪些方法和工具？**
4. **除了你我的判断，还有什么能够证明结果是对的？**

### 第 3 步：重写任务

把四问的答案显式写进升级后的任务描述，并展示给用户："升级后的任务：……"。

🔴 CHECKPOINT：升级后范围**超过原任务一倍以上**（成本显著变化）→ 🛑 STOP，展示升级任务等用户确认后再开工；**未超一倍 → 直接开工**，不等确认——用户既然说了 /deep，就是要这个效果。

### 第 4 步：按升级后的任务执行，并遵守深度行为要求

- **用真家伙**：数据任务上数据库/统计脚本，不许用几张 Markdown 表格糊弄；不用先问用户专家用什么，自己知道就上
- **目标提到离谱**：用户给的指标可以再往上一档（用户说 5 秒，按 200 毫秒努力），并明说按什么档执行
- **验证常识**：任务里隐含的"我们认为"要主动检验——"我们觉得 X 导致了 Y，请从原始数据检验这个结论是否成立"
- **找未知**：交付时附一条"你可能没意识到的发现"——从研究过程中挖出一个用户没问但值得知道的东西
- **独立验证**：结论必须有外部验证路径（可运行的测试、可复现的脚本、可对照的原始数据），不许模型自己给自己打分

## 红线

- **不要角色扮演**："像做空者一样思考"没有产出，要采用做空者研究标的、形成判断的方法。要方法，不要人设
- **深度 ≠ 规模**：升级是往深里做，不是把任务做大做散
- **浅任务别用**：用户只是问个事、改个错别字，触发本技能属于浪费

## 失败模式与兜底

| 触发条件 | 一线修复 | 仍失败兜底 |
|---------|---------|-----------|
| 四问中某一问答不出具体内容 | 读 `references/methodology.md` 找同类案例参照后重答 | 明确标注"该领域经验不足，此问留待执行中补充"，不许编空话充数 |
| 任务太模糊，第 1 步无法判断类型 | 只问用户一个最关键的澄清问题 | 用户未回复时按"写方案/定机制"默认路径处理，输出开头声明假设 |
| 用户任务实际是浅任务却触发了本技能 | 按红线直接执行，不套四问流程 | 直接完成即可，无需兜底 |
| `references/methodology.md` 读取失败 | 凭本文件四问主干继续执行 | 主干已自足，无需兜底 |
