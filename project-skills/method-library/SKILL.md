# 思维方法库

在用户提问时，将问题路由到合适的思维方法，按该方法的框架组织回答。这是通用回答方法库，任何技能都可复用。

## 核心原则

1. **推荐而非强制**：提问时先推荐 1-3 种方法，用户确认后使用；未确认则默认回答
2. **单次生效**：方法只影响下一次回答，完成后自动恢复默认
3. **显式指定优先**：用户说"用X方法回答"时，直接按该方法输出，不再询问
4. **方法路由表**：根据问题类型推荐方法（见下表）

## 方法路由表

| 问题类型 | 推荐方法 | 说明 |
|---------|---------|------|
| 方案对比 / 技术选型 | 决策矩阵 | 多维度加权评分，量化对比 |
| 汇报 / 总结 / 方案 | 金字塔原理 | 结论先行，自上而下论证 |
| 分类 / 拆解 / 分析 | MECE | 相互独立，完全穷尽 |
| 技术选型 / 架构决策 | RFC/ADR | 背景-决策-后果，可追溯 |
| 成本 / 本质分析 | 第一性原理 | 拆解到基本事实，从底层推导 |
| 风险评估 / 战略制定 | 情景规划 | 多情景推演，各有应对 |
| 复杂系统 / 多因素交互 | 系统思维 | 反馈回路，涌现行为 |
| 假设验证 / 实验设计 | 科学方法 | 假设-实验-验证-结论 |
| 快速决策 / 应急响应 | OODA | 观察-定向-决策-行动 |
| 产品需求 / 用户洞察 | JTBD | 用户"雇佣"产品完成什么任务 |
| 问题定义 / 需求分析 | 5W1H | Who/What/When/Where/Why/How |
| 战略分析 | SWOT | 优势/劣势/机会/威胁 |
| 多角度审视 | 六顶思考帽 | 事实/感觉/风险/创新/流程/创意 |
| 用户流程 / 转化分析 | 漏斗模型 | 各环节转化率，找流失点 |
| 优先级排序 | 四象限 | 重要-紧急矩阵 |

## 方法选择流程

```
用户提问
    ↓
1. 判断问题类型（匹配路由表）
    ↓
2. 推荐 1-3 种方法（按匹配度排序）
    ↓
3a. 用户选择 → 按该方法组织回答
3b. 用户未选择 → 默认回答
3c. 用户显式指定 → 直接按该方法回答
```

## 🔴 失败模式与兜底处理

| 触发条件 | 一线修复 | 仍失败时的兜底 |
|---------|---------|--------------|
| 问题类型匹配不到路由表任何方法 | 用默认回答，不强行套方法 | 询问用户是否想用特定方法 |
| 问题同时匹配多个方法（如"对比+成本"） | 推荐最匹配的 1 个，说明其他可选 | 让用户选 |
| 用户拒绝推荐的所有方法 | 恢复默认回答 | 问用户是否有偏好的方法 |
| 用户指定了不存在的/方法库没有的方法 | 说明没有该方法，给出最接近的替代 | 按用户描述自建临时框架 |
| 方法模板与问题场景不匹配 | 按方法核心思想裁剪模板 | 用默认回答结构 |
| 用户闲聊/问候（无实质问题） | 不推荐方法，正常闲聊 | 不套用方法 |

## 🛑 Do not do 黑名单

- 不要在用户只是闲聊、问候、表达情绪时强推思维方法——方法只用于实质问题
- 不要同时叠加多个方法组织一次回答——一次回答只用一种方法，避免结构混乱
- 不要对简单问题过度框架化——"今天天气如何"不需要决策矩阵
- 不要在用户明确拒绝方法后仍坚持用方法回答——尊重用户默认偏好
- 不要把方法模板生搬硬套到不适用场景——模板是骨架，不是枷锁
- 不要因为用了方法就堆砌表格/格式——方法服务于内容，不是内容服务于格式
- 不要混淆 method-library（思维方法）与其他技能的方法库（如 ICAP 的学习方法库）

## 输出格式约定

按方法回答时，在回答开头标注方法名，例如：

> **方法**：决策矩阵

然后按该方法的模板组织内容。回答结束后，方法自动失效，下次回答恢复默认。

## 方法模板

### 1. 金字塔原理（Pyramid Principle）

适用：汇报、总结、方案、说服性表达

```markdown
## 结论
[一句话核心结论]

## 论据一
[分论点]
- [支撑事实/数据]

## 论据二
[分论点]
- [支撑事实/数据]

## 论据三
[分论点]
- [支撑事实/数据]

## 建议行动
[基于结论的行动建议]
```

关键规则：
- 结论先行，论点后置
- 每一层论点都是下一层的概括
- 同层论点之间 MECE

### 2. 决策矩阵（Decision Matrix）

适用：方案对比、技术选型、多选项决策

```markdown
## 决策问题
[要决策什么]

## 评估维度（加权）
| 维度 | 权重 | 说明 |
|------|------|------|
| 维度A | 30% | 描述 |
| 维度B | 25% | 描述 |
| ... | ... | ... |

## 方案评分
| 方案 | 维度A(30%) | 维度B(25%) | ... | 加权总分 |
|------|-----------|-----------|-----|---------|
| 方案1 | 8 | 7 | ... | 7.5 |
| 方案2 | 6 | 9 | ... | 7.8 |

## 结论
[得分最高的方案 + 理由 + 注意事项]
```

### 3. MECE 拆解

适用：分类、拆解、分析、结构化思考

```markdown
## 分析对象
[要拆解什么]

## 拆解维度
### 维度一
- 类1
- 类2
- ...

### 维度二
- 类1
- 类2
- ...

## 完整性检查
- [ ] 相互独立（无重叠）
- [ ] 完全穷尽（无遗漏）
```

### 4. RFC/ADR（架构决策记录）

适用：技术选型、架构决策、需要可追溯的决策

```markdown
## 背景
[决策上下文：要解决什么问题，有哪些约束]

## 决策
[最终选择 + 一句话理由]

## 备选方案
### 方案A
- 优点：...
- 缺点：...
- 为什么放弃：...

### 方案B
- 优点：...
- 缺点：...
- 为什么放弃：...

## 后果
### 正面
- ...

### 负面
- ...

## 影响范围
[哪些系统/团队/流程受影响]
```

### 5. 第一性原理（First Principles）

适用：成本分析、技术选型、打破常规思考

```markdown
## 问题
[要分析什么]

## 拆解到基本事实
1. [事实1：不可再拆的底层事实]
2. [事实2]
3. [事实3]

## 从底层推导
[基于事实的推理链，不受现有方案约束]

## 结论
[推导出的新方案/新认知，对比现有方案]
```

### 6. 情景规划（Scenario Planning）

适用：风险评估、战略制定、未来不确定性

```markdown
## 关键不确定性
[影响结果的核心变量]

## 情景推演
### 乐观情景
- 假设：...
- 结果：...
- 应对：...

### 基准情景
- 假设：...
- 结果：...
- 应对：...

### 悲观情景
- 假设：...
- 结果：...
- 应对：...

## 韧性策略
[在所有情景下都成立的行动]
```

### 7. 系统思维（Systems Thinking）

适用：复杂系统、多因素交互、反馈分析

```markdown
## 系统边界
[系统的范围和外延]

## 要素与关系
| 要素 | 与其他要素的关系 | 类型（正/负反馈） |
|------|----------------|------------------|
| A | A→B | 正反馈 |
| B | B→C | 负反馈 |
| ... | ... | ... |

## 关键反馈回路
- 回路1：A→B→A（增强/平衡）
- 回路2：...

## 涌现行为
[系统整体呈现的、单个要素不具备的行为]

## 干预点
[杠杆点：在哪里做最小干预产生最大变化]
```

### 8. 科学方法（Scientific Method）

适用：假设验证、实验设计、A/B测试

```markdown
## 研究问题
[要验证什么]

## 假设
[H0 零假设 / H1 备择假设]

## 实验设计
- 变量：...
- 对照组：...
- 实验组：...
- 样本量：...
- 衡量指标：...

## 预期结果
[如果假设成立，会看到什么]

## 验证结论
[基于结果支持/拒绝假设]
```

### 9. OODA 循环

适用：快速决策、应急响应、竞争博弈

```markdown
## 观察（Observe）
[当前态势：事实、数据、环境]

## 定向（Orient）
[对态势的判断：基于经验/理论/上下文]

## 决策（Decide）
[要采取的行动方案]

## 行动（Act）
[具体执行步骤]

## 复盘
[行动后的观察，进入下一轮 OODA]
```

### 10. JTBD（Jobs To Be Done）

适用：产品需求、用户洞察、功能设计

```markdown
## 用户
[目标用户]

## 待完成的工作（Job）
[用户在什么场景下"雇佣"产品完成什么任务]

## 当前做法
[用户现在怎么完成（替代品）]

## 痛点
[用户为什么不满意]

## 理想方案
[如何更好地完成这个任务]
```

### 11. 5W1H

适用：问题定义、需求分析、任务澄清

```markdown
- **What**（是什么）：[对象/任务]
- **Why**（为什么）：[目的/动机]
- **Who**（谁）：[涉及角色]
- **When**（何时）：[时间/节点]
- **Where**（何地）：[地点/场景]
- **How**（如何）：[方法/流程]
```

### 12. SWOT

适用：战略分析、项目立项、竞争分析

```markdown
| | 有利 | 不利 |
|------|------|------|
| **内部** | S 优势 | W 劣势 |
| **外部** | O 机会 | T 威胁 |

## SO 策略（优势+机会）
- ...

## WO 策略（劣势+机会）
- ...

## ST 策略（优势+威胁）
- ...

## WT 策略（劣势+威胁）
- ...
```

### 13. 六顶思考帽（Six Thinking Hats）

适用：多角度审视、会议讨论、全面分析

```markdown
## 白帽（事实）
[客观数据、已知信息]

## 红帽（感觉）
[直觉、情绪、第一反应]

## 黑帽（风险）
[可能的问题、失败点]

## 黄帽（价值）
[潜在收益、亮点]

## 绿帽（创新）
[新想法、替代方案]

## 蓝帽（流程）
[思考过程控制、总结]
```

### 14. 漏斗模型（Funnel）

适用：用户流程、转化分析、销售流程

```markdown
## 转化漏斗
| 阶段 | 数量 | 转化率 | 流失原因 |
|------|------|--------|---------|
| 阶段1 | N | - | - |
| 阶段2 | N | X% | 原因 |
| 阶段3 | N | Y% | 原因 |

## 最大流失点
[转化率最低的环节]

## 优化建议
[针对最大流失点的改进措施]
```

### 15. 四象限（Eisenhower Matrix）

适用：优先级排序、任务管理、资源分配

```markdown
## 四象限
| | 紧急 | 不紧急 |
|------|------|--------|
| **重要** | Q1：立即做 | Q2：计划做 |
| **不重要** | Q3：委派/减少 | Q4：不做 |

## 当前事项归类
- Q1（立即做）：...
- Q2（计划做）：...
- Q3（委派）：...
- Q4（放弃）：...

## 时间分配建议
[重要不紧急（Q2）应占多数时间]
```
