# CAD 图纸 → 3D 数字孪生

把建筑 CAD 图纸（DXF）自动转成 Three.js 3D 数字孪生原型。核心原则：

> **能用图纸原始参数的绝不推算；每个几何结论都要有可执行的验证手段。**

## 适用场景

- 拿到建筑 DXF 图纸，要做 3D 展示 / 数字孪生 / 沙盘
- 多楼层、多项目批量生成（同套流程换输入即可）
- 3D 场景需要与 CAD 精确对齐（房间名/位置/构件不能错）

## 工作流（6 步）

1. **图纸体检**：确认编码（国内常见 GBK / `$DWGCODEPAGE=ANSI_936`）、版本（`$ACADVER`）、图层清单、实体类型统计、主图范围（避免图块/大样混入）
2. **图层 → 构件映射**：按下方映射表识别；不确定的图层先统计实体类型再判断
3. **提取**：用 `scripts/extract_dxf.py`（参数化：原点、镜像模式、图层名）
   🔴 CHECKPOINT：提取后**人工目检各 JSON 计数**（墙/门/窗/柱/楼梯/家具数量与图纸相符、不为 0）
4. **坐标系归一**：mm→m、原点平移、**z 轴镜像**（详见 `references/coordinate-and-pitfalls.md`）
5. **场景生成**：按提取数据建 Three.js 场景——墙用 InstancedMesh（性能）、房间用 Shape 地面、门窗家具用独立 mesh（可拾取）
6. **验证**：跑验证清单 + **完整性质检**（`scripts/completeness_check.py`）+ 生成 2D 核对图（`scripts/render_check.py`）
   🔴 CHECKPOINT · 🛑 STOP：**交付前逐条过验证清单 + 目检 2D 核对图，全绿才交付**

## 图层 → 构件映射（天正 CAD 标准）

| 图层 | 构件 | 关键点 |
|---|---|---|
| WALL / PUB_WALL | 墙线 | 含窗间墙墩（实体，保留）；含窗框线（短段，需剔除） |
| WINDOW | 窗（3 种表达） | ①块 INSERT ②WALL+SURFACE 成对平行线 ③本层轮廓线——三种都要提取；`extract_dxf.py` 当前只提①块，②③需另行补齐 |
| $DorLib2D$* | 门块 | 宽度=XSCALE；单/双开按宽度（≥1.2m 双开） |
| COLUMN | 结构柱 | 直接按插入点渲染方柱 |
| STAIR | 楼梯 | 踏步线间距突变处 = 平台；踏步区≠整个楼梯间 |
| SPACE | 房间面积标注 | "房间"+面积数字成对 TEXT，是精确面积来源 |
| PUB_TEXT | 房间功能名/设备名 | 全部读取（别只看前 N 条——房间名常在后段） |
| ZP-活动家具 / fur | 家具 | 闭合轮廓的质心=位置、bbox=尺寸；按尺寸分类渲染 |
| LATRINE / LVTRY | 洁具/厕位 | 辅助判断房间功能 |

## 四个关键技术点

1. **XSCALE = 实际尺寸**：天正图块（INSERT）的组码 **41（XSCALE）就是构件实际尺寸（mm）**——窗宽/门宽直接 `|XSCALE|/1000`，不要用墙线缺口推算或固定默认值
2. **方向 = 墙端点分布**：门/窗朝向**不要依赖块插入角 rot**（语义因块库而异，极易反）——用"构件附近 1.6m 内墙端点沿哪个轴分布"判定：沿 x 分布 → 构件沿 x，反之为 z
3. **房间 = flood-fill**：房间边界用"墙线+幕墙带+门洞补丁栅格化 → 外部灌水 → 内部连通域 → Moore 边界跟踪"提取，比"找闭合多段线"可靠（施工图墙线在门窗洞处是断的）。**没提到闭合边界的房间别"估算成方框"**——估算框往往只覆盖房间一角，导致点击/高亮不全（见坑 8）。（本目录无现成脚本，参考实现见 `projects/smart-office-4f/scripts/extract-dxf.mjs`）
4. **名字/面积 = 文字**：SPACE（面积）+ PUB_TEXT（功能名）按位置匹配给房间命名；未覆盖的空白区域 = 过道（内部除房间外的连通域）

## 验证清单（交付前必跑 · 🔴 全绿才交付）

- [ ] **完整性质检**：跑 `scripts/completeness_check.py`——① 图层普查里每个实体图层有"建/不建"的明确结论；② 墙/柱/窗/门四类的**「漏」和「多」都为 0**（详见下节）
- [ ] 房间中心到最近墙线距离 ≤ 3~5m（贴墙）
- [ ] **房间多边形贴合**：每个房间多边形**每条边**到最近墙/窗线的最大距离 ≤ ~1.2m（真实房间基准 max 0.7–1.1m）；超标 = 多边形没贴真实边界，**点击/高亮只会覆盖房间一部分**（"估算"多边形最易犯）。配 **3D 逐间点击**确认高亮覆盖整间
- [ ] 柱/楼梯到墙线距离 ≤ 1~3m
- [ ] 房间两两无重叠（采样法检测）
- [ ] 门/窗方向与墙向一致率 > 90%（用墙端点判据算）
- [ ] 生成 2D 核对图目检：房间名/门窗朝向是否沿墙
- [ ] 家具在房间内比例（60%+，其余在走廊合理）
- [ ] 旧数据残留 grep（旧色值/旧坐标）

## 完整性质检（双向全覆盖：墙 / 柱 / 窗 / 门）

> 上面"验证清单"查的是**对不对**（贴墙/朝向/贴合）；本节查**全不全 + 准不准**，而且**两类错都要查**：**漏**（图纸有、模型没有 = 缺构件）和 **多**（模型有、图纸没有 = 假构件）。`render_check.py` 只画"我们的数据"，两类错都看不出来，必须**拿模型数据和图纸原始实体双向对账**。

跑 `scripts/completeness_check.py <图纸.dxf> <提取数据目录>`，输出：

> **🔴 基准铁律**：`<提取数据目录>` 必须是**你模型的最终构件数据**，**不是技能提取器自己的输出**——拿技能提取器现跑一份当基准 = 自证，无效。用自研（更全）提取器时喂它的输出；且**坐标系必须与图纸一致**（同一 `--origin`/镜像/范围），否则对账几何全错（症状：几乎全部报"漏"，脚本会报警）。

1. **图层普查** —— DXF 所有图层 + 实体数（找"应建模却没建"的图层）
2. **构件双向对账** —— **墙 / 柱 / 窗 / 门** 四类逐项：
   - **漏** = 图纸有、模型没有 → 缺构件
   - **多** = 模型有、图纸没有 → 假构件（如**把墙错建成窗**）
   - 窗的「多」用**强窗（块 + WINDOW 层线）**判定：只靠 SURFACE 线支撑的幕墙段 = **可疑假窗**

**判据**：墙/柱/窗/门 四类的「漏」和「多」**都应为 0**（或逐条确认是刻意取舍）。

> 教训：曾踩两处 QC 盲区——① 只查「漏」不查「多」，**把墙错建成窗**（假构件）没发现；② 把 SURFACE 层线（可能只是**墙面**）当窗，误加了假窗。所以构件必须**双向**查，窗的「多」必须用**强窗判据**。

## 坑清单（实战血泪）

1. **z 轴镜像**：DXF 的 y 向上、Three.js 的 z 朝屏幕外——CAD 的 y 直接当 z 用会上下镜像；正确做法 `z = ZMAX - y`（镜像），且**必须用俯视图与 CAD 截图对齐验证**
2. **镜像 ≠ 旋转**：同时镜像两个轴 = 旋转 180°（手性保持，正确）；只镜像一个轴 = 镜像（手性颠倒，建筑左右反）。改坐标前**先数镜像次数奇偶**
3. **多数据源必须同步变换**：房间/墙/门/窗/柱/家具的坐标变换要**一起做**——漏掉一个数据源就整体错位（本文档作者曾因此错位 10m）
4. **rot 语义别猜**：块插入角与实际朝向的关系因软件/块库而异——**一律用几何判据**（墙端点分布 / 门洞缺口）代替
5. **墙线含窗框线**：WALL 图层的短段可能是窗的框架线（要与窗数据配对后剔除），但**窗间墙墩要保留**（那是实体墙）
6. **窗有三种表达**：只找窗块（INSERT）会漏——施工图还常用"墙/面成对平行线"和"轮廓线"表达窗
7. **自检标准要对齐视觉**：自定义的"一致率"可能自欺（本文档作者曾用错误指标"验证通过"3 次）——最终判据是 **2D 核对图**（人能直接看）与**真实浏览器截图**
8. **房间多边形不准 → 点击只亮一块**：房间地面/拾取网格**直接用房间多边形生成**——多边形错，点击高亮就错。**没提取到闭合边界、只能"估算"成方框的房间最易翻车**（实战：某房估算框 3.4m 宽，实际墙+窗围合 8.3m 宽 → 点击只亮左 1/3）。**判定**：算"多边形每条边到最近墙/窗线的最大距离"，正常 ≤1.2m，超标即没贴合。**修法**：用墙+窗围合的真实边界（内墙面）重设多边形，再跑 2D 核对图 + 3D 点击验证。（边界若是 WALL 图层之外的隔断，指标会误报，需目检确认）

## 失败对照表（症状 → 一线修复 → 兜底）

跑流程遇到下列任一症状，按「触发条件 → 一线修复 → 仍失败兜底」三段处理（对应坑编号）。

| 触发条件（症状） | 一线修复 | 仍失败兜底 |
|---|---|---|
| 提取后某类构件数 = 0（如门 0 扇） | 核对图层名/块名大小写与变体（门块 `$DorLib2D$*`、窗块 `WIN*`）——完整性质检②会标"提取=0" | 读 DXF 该图层实体逐个打印块名/图层；确认图纸确无此构件则记"本图无"，**不静默** |
| 俯视图上下颠倒 | 确认 `--mirror z`（坑 1） | 四角标记手性判定（坑 2） |
| 用户说"左右反了" | **先数镜像次数奇偶**（坑 2） | 偶数→对；奇数→再补一次镜像 |
| 门/窗朝向与墙不一致 | 弃用块 rot，改"墙端点分布"判据（坑 4） | 改用门洞缺口几何判据 |
| 点击房间只亮一块 | 房间多边形没贴真实边界（坑 8） | 算"边到墙/窗最大距离"，超标 → 用墙+窗真实边界重设多边形 |
| 核对图构件"飞"到图外 / 整体错位 | 某数据源漏做坐标变换（坑 3） | 贴墙自检（房间中心到墙距离）定位错位源，逐数据源比对 |
| 怀疑漏墙/漏门/漏窗 | 跑完整性质检③漏墙对账 + ①图层普查 | 逐条确认未覆盖段；每个有实体的图层给"建/不建"结论 |
| 完整性质检②"提取偏少" | 先判是否正常过滤（短段 <0.15m / 非闭合 / 超尺寸） | 逐条核对被过滤项，确认合法 |
| 完整性质检③"几乎全部未覆盖" | 基准数据与图纸坐标系没对齐（origin/镜像/范围不一致） | 对齐坐标；并确认喂的是**模型**数据、非技能提取器输出 |
| 窗"数量够"但实际漏窗 | ②只是计数，查不出位置缺口——跑 ④ 漏窗对账 | 逐段补上未覆盖的窗（块/WINDOW线/SURFACE 三种表达都要算） |

> 红线：**任何"提取=0"或"漏墙>0"都不能带病交付**——要么修，要么明确记"本图无此构件 / 该图层不需要"，绝不静默跳过。

## 文件

- `scripts/extract_dxf.py` —— 通用 DXF 提取器（参数化）
- `scripts/completeness_check.py` —— **完整性质检**（图层普查 + 计数对账 + 漏墙对账，防漏/防多构件）
- `scripts/render_check.py` —— 2D 核对图生成（房间/门窗朝向）
- `references/drawing-conventions.md` —— **建筑制图规范要点 → 建模映射**（先懂画法再建模：楼梯/门窗/墙体/标注/读图顺序）
- `references/coordinate-and-pitfalls.md` —— 坐标系详解 + 坑详解 + 验证方法
