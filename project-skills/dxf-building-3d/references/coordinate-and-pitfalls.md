# 坐标系与坑详解（DXF → Three.js）

## 一、标准坐标变换链

DXF：x 向右（东）、y 向上（北），单位常为 mm。
Three.js：x 向右、y 向上（高度）、z 朝屏幕外。

```
① mm → m:        x/1000
② 原点平移:       - ORIGIN（把图纸坐标挪到场景原点附近，避免大数精度问题）
③ z 轴镜像:       z = YMAX_m - y_m      ← 关键，别漏
```

**为什么必须镜像**：CAD 的 y 直接当 Three.js 的 z，会导致 CAD 北（y 大）映射到 z 大（俯视屏幕下方）→ **上下颠倒**。镜像后 CAD 北 → z 小 → 屏幕上方 ✓。

**验证方法**：场景俯视图与 CAD 截图并排，逐轴比对（x 对应 x、CAD 的 y 对应场景 z）。

## 二、镜像 vs 旋转（最容易翻车）

| 镜像次数 | 手性（det） | 效果 |
|---|---|---|
| 0（偶数） | 保持 | 原样 |
| 1（奇数） | **颠倒** | 建筑左右/前后镜像（用户会说"左右反了"） |
| 2（偶数） | 保持 | 旋转 180° |

**血泪规则**：用户说"左右反了"时，**先数已做镜像次数的奇偶**——再补一次镜像会让偶数变奇数（**反而变镜像**）。两次"修反"的教训就是这么来的。

**手性判定（可执行验证）**：
1. 在场景四角放彩色编号标记（1红/2绿/3蓝/4黄），材质 `toneMapped=false`（避免色调映射改色）
2. 截图后用像素分析定位标记
3. 判据：数据空间叉积 `(角2-角1)×(角4-角1)` 与屏幕空间叉积 **同号 = 非镜像 ✓**，反号 = 镜像 ✗

## 三、三道验证防线（交付前必过）

### 1. 贴墙自检（数据层）
- 房间中心 → 最近墙线距离：应 ≤ 3~5m
- 柱/楼梯 → 墙线：≤ 1~3m
- 超限 = 某数据源坐标系不一致（最常见：某源漏做变换）

### 2. 分布对齐自检（数据层）
- 多套数据的坐标**中位数应接近**（墙 z 中位 ≈ 房间 z 中位 ≈ 家具 z 中位）
- 差 10m 量级 = 有数据源镜像次数不同（曾出现"墙与房间错位 10m"）

### 3. 2D 核对图（视觉层，最终判据）
- `render_check.py` 生成平面图（墙/窗/门朝向叠加）
- **人能直接看**"构件是否沿墙"——自定义的"一致率"指标可能自欺（曾用错误指标"验证通过"3 次）

## 四、八条坑展开

1. **z 轴镜像**：见第一节。DXF y 直接当 z = 上下颠倒。
2. **镜像 vs 旋转**：见第二节。改坐标前先数镜像奇偶。
3. **多数据源同步**：房间/墙/门/窗/柱/家具的变换必须**一起做**——漏一个就整体错位。新增数据源时，**用贴墙自检立刻验证**。
4. **rot 语义别猜**：块插入角 rot 与真实朝向的关系因块库而异（天正 $DorLib2D$ 的 rot 语义与直觉相反）。**一律用几何判据**：构件附近墙端点沿哪个轴分布 → 构件沿哪个轴。
5. **墙线含窗框线**：WALL 图层的短段有两类——窗的框架线（应与窗数据配对剔除）和**窗间墙墩**（实体墙，保留）。判定：与 SURFACE 成对线平行邻近的 = 窗框线。
6. **窗有多表达**：①块 INSERT ②WALL+SURFACE 成对平行线 ③WINDOW 图层轮廓线——只找①会漏一半。宽度统一取 XSCALE。
7. **自检要对齐视觉**：数据自检只能验证"自洽"，不能验证"与图纸一致"——与图纸的一致性靠**俯视截图对比**和 **2D 核对图**。
8. **房间多边形不准 → 点击只亮一块**：房间地面/拾取网格**直接由房间多边形生成**，多边形错则点击高亮只覆盖一部分。施工图中**未能提取到闭合边界、改用手工"估算"方框的房间**是高危区（实战：某房估算框 3.4m 宽，实际墙+窗围合 8.3m 宽 → 点击只亮左 1/3）。**可执行判定**：算"多边形每条边到最近墙/窗线的最大距离"，真实房间基准 max 约 0.7–1.1m，超标即未贴合。**修法**：改用墙+窗围合的真实边界（内墙面）重设多边形，跑 2D 核对图 + 3D 逐间点击验证。**注意**：若该边实际是 WALL 图层之外的隔断（隔墙/幕墙），指标会误报，须目检确认。

## 五、环境坑（工程侧）

- **单文件产物**：`vite-plugin-singlefile` 打包后双击即可（无需服务器）；file:// 下 ES module 有 CORS 限制，生产用内联产物
- **浏览器缓存**：改了代码用户看旧版 → UI 加**构建版本号**（vite `define` 注入时间戳）
- **无头截图**：Windows 上 Edge headless 不稳，用 **playwright-core + `channel:'msedge'`** 更可靠
- **看图排查**：截图后用支持视觉的模型 `read` 图片（配合 URL 参数控制相机 `?cam=x,y,z,tx,ty,tz` 拍近景）
