## 二、增益分布很清晰

| 增益 | 任务类型 | 说明 |
|---|---|---|
| **+3（满分差）** | 反直觉归因、结构化流程 | 概念图定位、总平翻车归因、交付说明、模型选型、分析图两步法 |
| **+1** | 行业常识 | 施工图不能位图交付、改造要保结构、窗外白要补参考 |

**结论：skill 的价值集中在"反直觉判断"和"结构化交付"，不在"行业常识"。**

常识题无 skill 也能拿到 2/3——它知道"改造要小心"、"位图不能当施工图"，但**说不出为什么、也说不出怎么做**。

## 三、三个真实差异（读答案读出来的）

1. **归因深度**：无 skill 说"手绘信息不足会脑补"（对但不中要害），有 skill 说"换视角必然重排布局"（结构性原因，可据此选方案）
2. **事实准确性**：无 skill 编造了不存在的 `wanx-v2.1 + strength` 接口；有 skill 给的是本机实测过的模型与参数
3. **交付纪律**：无 skill 的"交付说明"是"标注示意图、说明用途"；有 skill 的是"三档状态 + 三查 + 证据 + 差异说明"

## 四、评分规则改了 4 处（全部如实记录）

| # | 断言 | 改动 | 方向 | 理由 |
|---|---|---|---|---|
| 1 | 分析图 ref2 同结构 | 补"互相平均""布局平均" | 放宽 | 答案写"避免两套布局互相平均"，语义已满足 |
| 2 | 带 ref 分辨率上限 | 改为「2048/2K/4K」且「上限/拿不到」两族同时满足 | **收紧** | 无 skill 写"导出底图至少 2048px"被误判命中——那是底图分辨率 |
| 3 | 排错归因 | 不再预设"单参考"，改测"是否指到可控环节" | 放宽 | 有 skill 的答案按两步法归因到"氛围稿 prompt 没写窗外"，比预设前提更准 |
| 4 | 概念图不能当方案图 | 接受"不得"等否定词变体 | 放宽 | 答案写"不得当方案图交付"，原规则只认"不能" |
| 5 | 评分器实现 | 去掉"断言文本必须与 metadata 完全相等" | 容错 | 规则文本以 grade.py 为准，metadata 允许漂移 |

第 2 条是唯一收紧的——它去掉了误给的 pass，让无 skill 的真实水平显现。

## 五、评分暴露的 2 个真缺陷（已修 + 重跑验证）

| 缺陷 | 修法 | 重跑结果 |
|---|---|---|
| 有 skill 的答案没提"带参考图拿不到 4K"（写在 reference 深处没被转述） | 写进 SKILL.md 第七节流程表 | 3/4 → **4/4** |
| 概念图"不能当方案图/不能对图纸"只写在 drawing-01，**不在红线里** | 升为第六条红线第 7 条 | 2/3 → **3/3** |

**两次都是"信息在 reference 里但没在最显眼的位置"——这说明 skill 的瓶颈不在内容，在层级。**

## 六、可信度

| 项 | 情况 |
|---|---|
| 样本 | 9 任务 × 2 配置，18 次运行 |
| 评分者 | 关键词族脚本（非独立人工 grader） |
| 任务类型 | 全是判断/建议，**没有测"真的出图"** |
| 结论强度 | 方向性证据。100% vs 37% 差距大，但 n=9、评分器粗 |

**可以说**：这 9 类最典型提问上，有 skill 的答案归因更准、事实更准、交付纪律更严、篇幅更短。
**不能说**：这个 skill 让出图质量提升了多少——那需要另一套以图片为产出的对照实验。
