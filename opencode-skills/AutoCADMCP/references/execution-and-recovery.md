# 分批执行、逐笔展示与恢复

AutoCADMCP 的 `draw_entities` 用简写文本一次绘制多类图元。落图可整图一次，也可分批；无论哪种，都按相同语义展开（`plan_to_shorthand.py`）与默认顺序。

## 批次设计

一个批次只画一个图层中的一类图元，例如“一圈新墙”或“一组门弧”。每批预先记录：

- 批次编号和名称；
- 图层；
- 对象 `id`；
- 展开后的预期简写行数（来自 `plan_to_shorthand.py` 的统计）；
- 开始前存档点；
- 成功数、失败数和最后成功 `id`。

整图一次落图时，把 `plan_to_shorthand.py` 生成的完整简写文本作为 `draw_entities` 的 `entities` 参数；返回里 `created` 应等于 `total`，逐条核对失败实体。

## 默认顺序

通用 `entities` 按数组顺序展开，计划应按主轮廓、构件细节、文字标注排列。以下是室内语义计划的顺序，不要求其他图种补齐墙体、门窗或家具阶段。

1. 墙体填充；
2. 墙体轮廓；
3. 洞口；
4. 窗和推拉门；
5. 门扇和开启弧；
6. 固定家具；
7. 活动家具；
8. 洁具和设备；
9. 房间名称与面积；
10. 标注、说明和指北针。

先填充再轮廓可避免填充遮盖轮廓。落图前已在预览中确定完整视域；当前 MCP 无视口工具时，用 `manage_session zoom_extents` 缩放到全图，不承诺锁定视口。

## 阶段保存

每完成一个大阶段后用 `manage_files save` 保存；室内图可按墙体、门窗、家具设备、文字标注划分，其他图种按实际构件划分。建议使用递增文件名：

```text
project_01_walls.dwg
project_02_openings.dwg
project_03_furniture.dwg
project_final.dwg
```

用户只要单个最终文件时，也应至少在关键阶段覆盖保存到目标文件并在日志中记录时点。

## 失败处理

1. 首次失败立即停止当前批次。
2. 记录失败对象、参数、错误文本、该批已成功对象和最近存档。
3. 不自动重发整批，避免重复图元。
4. 删除/回滚能力有限：可对已记录 handle 用 `manage_entities delete` 删除，或让用户在 CAD 中 Ctrl+Z / 清理本任务专属图层；用户确认后从最后稳定 `id` 继续。
5. 不删除用户既有图层。增量绘图必须使用项目专属新图层，以便人工恢复。

## 逐笔展示

“实时绘制”是展示层，不是重新设计：

- 先完成 `plan.json`、校验和预览（文档级闸门）；
- 从空白或用户确认的目标文档开始；
- 按默认顺序逐批调用 `draw_entities`（每批一小段简写）并在阶段边界简报；
- 不通过打开完成图、显隐图层或播放录像冒充逐笔绘制；
- 图元数量很大时，降低说明频率或只展示关键批次，但不省略实际必要图元；
- 用户随时可在批次边界暂停检查。

## 核对日志

建议维护：

```json
{
  "batch": "B03_doors",
  "layer": "A-DOOR",
  "expected_lines": 8,
  "created": 8,
  "failed": 0,
  "last_success_id": "door_d04",
  "saved_to": "C:/output/project_02_openings.dwg"
}
```

最终把各批日志汇总后与计划预期行数对比，并用 `export_data(scope="all", format="json")` 补充图层、实体类型与文字样式统计；必要时用 `manage_session screenshot` 目视复核关键区域。
