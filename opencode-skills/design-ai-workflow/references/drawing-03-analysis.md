# 分析图

> 定位：中期深化阶段的主力图种，用来讲清"为什么这样布局"。
> **关键分工**：分析**逻辑**由人定、矢量叠加；分析**表现**（Sasaki 风、肌理、轴测、爆炸）可以交给图像模型重绘。
> 素材来源：培训 PPT（李建杰）的策略分析页 + 9 篇公众号提示词配方（见 [style/recipes/](style/recipes/_index.md)）。

## 一、先分清"逻辑"和"表现"

| 层 | 谁做 | 为什么 |
|---|---|---|
| **逻辑**：谁靠近谁、视线从哪到哪、流线怎么走、分区依据 | **人 + 矢量** | AI 会把拓扑画错：箭头反向、流线断开、图例对不上色块 |
| **表现**：轴测体量怎么渲、肌理怎么分层、爆炸图怎么炸 | **AI 可以** | 这些是"重绘"不是"判断"，配方稳定可复现 |

我早前写过"分析图不该交给图像模型"，**那句只对逻辑层成立，对表现层是过度保守**。9 篇配方证明表现层 AI 出得很稳。

## 三、六步法（逻辑层）

```
① 建三维底图   场地模型，含地形/水体/建筑/植被；材质简洁，不要过度渲染
② 定分析视角   鸟瞰 30~45 度俯角；一页一个视角
③ 定分析主题   生态循环 / 功能分区 / 交通流线 / 视线分析 / 日照
               一页一个主题，不叠两个
④ 叠分析图元   色块（半透明，不遮底图）/ 箭头（曲线更自然）/ 图标（圆底+符号）/ 标注（引线指向）
⑤ 加图例       页面边缘（底部或右下角）；颜色与图标必须与图中一致
⑥ 查信息层次   底图 → 分析层 → 标注层，三层分明
```

## 四、分析图元的规范

| 图元 | 规格 | 禁忌 |
|---|---|---|
| 色块 | 半透明 60~80%，不遮挡底图细节 | 高饱和不透明色块会把底图压死 |
| 箭头 | 曲线箭头表示流线/视线，直线表示轴向 | 箭头互相穿越、方向矛盾 |
| 图标 | 统一圆形底 + 白色符号，尺寸一致 | 混用三种以上图标风格 |
| 标注 | 中英文对照，引线指向目标，字号统一 | 引线交叉、字号大小不一 |
| 图例 | 右下角或底部，色块/图标与图内一一对应 | 图例有、图里找不到对应元素 |

## 五、五种常见分析图

| 类型 | 底图 | 主要图元 | 说明什么 |
|---|---|---|---|
| 功能分区 | 三维鸟瞰 | 5~7 个半透明色块 + 分区名 + 图标 | 哪里做什么 |
| 交通流线 | 三维鸟瞰或轴测 | 曲线箭头（车/人/货分流）+ 出入口标注 | 怎么进来怎么出去 |
| 视线/对景 | 三维鸟瞰 | 虚线 + 视线通廊 + 对景点 | 看什么、被什么挡 |
| 生态/水文 | 三维鸟瞰 | 水流箭头 + 汇水区色块 + 红线 | 水从哪来到哪去 |
| 日照/微气候 | 三维鸟瞰 | 阴影分析 + 风玫瑰 + 分区色 | 光影与通风 |

## 六、红线

1. **逻辑层不得交给图像模型。** 拓扑会错，图例会对不上。
2. **一页只讲一个主题。** 分区+流线+视线堆在一页 = 甲方看不懂。
3. **图例必须与图内元素一一对应。** 对不上就是不专业。
4. **能耗/数据类分析只能出意向图。** AI 画的热力图数值是编的，不能当数据结论。
5. 分析图的"结论句"必须写在图上，不能只放在口头汇报里——甲方只看图。
