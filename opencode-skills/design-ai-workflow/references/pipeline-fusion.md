# 双参考两段式管线（已实测跑通）

> 2026-10-29 实测：结构保真不降，图面质量显著提升，零幻觉构件。产物 `07-interior-fused.png`。

## 一、为什么必须两段

单模型直出有两个死结：

| 死结 | 原因 | 单模型表现 |
|---|---|---|
| 材质与细节发空 | 只有结构参考时，模型没有质感依据 | 窗外全白、图面空、细节少 |
| 换模型救不了 | 换成图面更强的模型就不能吃参考图 | `qwen-image-3.0-pro` 拒绝 `--ref` |

**两段式把两个能力拆给两个模型**：一个负责"好看"，一个负责"照结构"。

## 三、两段命令

```powershell
$S = "C:\Users\HP\.config\opencode\skills\baoyu-image-gen\scripts\main.ts"

# 第一段：氛围稿（纯文生图，只求材质/光线/细节，不管结构）
bun $S --provider dashscope --model qwen-image-3.0-pro `
  --prompt $MoodPrompt --image mood.png --ar 16:9 --quality 2k
```

## 四、两个 prompt 的写法（关键）

### 氛围稿 prompt（第一段）

**只描述空间与风格，不描述"参考图"**——因为这里没有参考图。

```
<空间描述：视角、主要界面、开口位置、家具数量与类型>
风格：<风格名>，<色板>，<家具语言>
材质：<材质清单>
光线：<主光方向>，色温 <K>，<补光方式>
避免：<该风格的负向清单>；任何文字、水印、logo、边框
要求：写实建筑室内/外观表现图，客户交付级画质，高细节
```

空间描述必须来自**实际看图**（`ViewImage` / `read`），不许用 cv2/OCR "分析"。

### 融合 prompt（第二段）

必须**显式分工两张参考图**，否则模型会把氛围稿的构图也抄进来：

```
参考图 1 是空间结构的唯一依据：墙体、窗洞、开口位置、开间比例、层高、家具占位轮廓
必须与参考图 1 完全一致，不得增删墙体或改变格局。
参考图 2 是材质与氛围的唯一依据：严格参照其家具材质、布艺与皮革质感、木纹、
灯光色温与光晕、细节密度与生活感，以及窗外实景内容；参考图 2 的构图与结构一律忽略。

风格：<风格名>
光线：<一句话>
避免：任何文字、水印、logo、边框；不得新增参考图 1 中不存在的墙面构件
要求：写实建筑表现图，客户交付级画质
```

三句话是这套方法的核心：**"唯一依据"×2 + "构图一律忽略"**。

## 五、参数与成本

| 项 | 值 |
|---|---|
| 每张终稿 | 2 次调用（氛围稿 + 融合），约 2~3 分钟 |
| 输出尺寸 | 16:9 → 2720×1536；4:3 → 2352×1776 |
| 4K | 带 ref 拿不到。需要 4K 就后期放大，或改用纯文生图（无结构保真） |
| 参考图体积 | 单张控制在 ≤1.5 MB；2400 px JPG q90 足够。原始 PNG 可达 18 MB，base64 不稳 |

## 六、常见失败与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| 窗外仍全白 | 氛围稿里也没写窗外内容 | 氛围稿 prompt 明确写"窗外为虚化的城市建筑与绿树" |
| 多出参考图里没有的构件 | 融合 prompt 没写"不得新增" | 加"不得新增参考图 1 中不存在的墙面构件" |
| 结构被改坏 | 两张 ref 语境冲突 / 氛围稿构图太强 | 强化"参考图 2 的构图与结构一律忽略"；或减少 ref2 权重（改用更接近同视角的氛围稿） |
| `DataInspectionFailed` 内容审核 | 实景照片含可辨认招牌/人群 | 改 prompt 去掉人物与文字要求；仍失败则裁切或模糊招牌 |
| qwen 报 ref 不支持 | 用了 qwen 系列带 `--ref` | 换 `wan2.7-image-pro` |
| 尺寸报错 | 带 ref 时超过 2048² | 降 `--quality 2k`，不要传 4K `--size` |

## 七、模型不是靠"感觉"选的，靠查表

先跑脚本，再出图：

```powershell
python scripts\select_model.py --task render --base 1 --mood 1
```

它按输入条件（有没有几何控制图、有没有氛围稿、几张参考图、要不要 mask、要不要 4K）返回确定的 `provider / model / 参考图分工`，并把冲突提前讲清楚。

理由：这些条件全部可枚举，**交给 LLM 判断只会不稳定**。表的每一行都来自实测，改了模型能力就改表，改完能回归。

`bl advisor recommend`（百炼 CLI 的模型顾问）只用于**表外场景**——出现表里没有的新模型或新任务时问一次，然后把结论写回表里。

## 八、ref2 必须与 ref1 结构兼容（硬约束，不是注意事项）

2026-10-29 做了对照实验，同一张底图、同一段 prompt，只换 ref2：

| 实验 | ref2 用什么 | 结构保真 | 图面元素（网格/指北针/模块） |
|---|---|---|---|
| 单参考 | — | ✅ 保住 | ❌ 全无 |
| 纯文生图 | 不用 ref | ❌ 全丢（变成棋盘格） | ✅ 有 |
| 双参考 | qwen 画的**另一套场地** | ❌ 全丢（两套布局被平均） | ✅ 有 |
| **双参考** | **本底图第一轮产物（同结构）** | ✅ **保住** | ✅ **4/5 达成** |

结论：**ref2 只要与 ref1 的结构不一致，融合就会把两套布局平均掉**——比单参考更糟。

写融合 prompt 时必须显式加一句：

> 参考图 2 必须来自同一底图的第一轮产物（结构一致），不得使用其它场地的参考图，否则布局会被平均。

### 分析图的两段式（与效果图同构）

```
底图
 ↓ ① 单参考 wan2.7（recipe 原始 prompt）→ 结构稿（结构对，图面朴素）
 ↓ ② 双参考 [ref1=原底图, ref2=该结构稿] + fusion_block → 定稿
```

这和室内的「氛围稿 → 融合」是同一个模式，已在两个不同场景验证成功。
`compose_prompt.py --fuse` 就是给第 ② 步用的。

## 九、ref2 能带什么、不能带什么（按污染风险排序）

2026-10-29 批量回归里 `render-facade-ref` 只拿到 1/4——ref2 用了实景照片，结果模型把照片里的建筑、花坛、绿地全抄进了成图，构图被污染。这是同类事故第三次（前两次是总平融合与分析图融合）。

由此得出 ref2 的选用排序，**从上到下风险递增**：

| ref2 用什么 | 污染风险 | 适用 |
|---|---|---|
| **纯色卡 / 色板** | 极低 | 只迁移色调（`render-facade-ref` 必须用这个） |
| **局部材质特写** | 低 | 迁移质感（石材、木纹、布艺） |
| **同底图、同视角的第一轮产物** | 低 | 迁移图面语言（分析图两段式的第 ② 步） |
| 同视角但不同场地的图 | 中 | 意象参考，需在 prompt 里写死"内容一律忽略" |
| **其它视角 / 其它场地的完整图** | **高** | ❌ 不要用，结构必被平均或抄袭 |

**硬规矩**：ref2 只能携带"质感与图面语言"，不能携带任何空间结构或构图信息。判断方法很简单——**把 ref2 遮住一半再看，如果那半张图里有建筑/场地/布局，它就会污染结果。**
