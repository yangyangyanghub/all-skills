# 能力边界与设备降级

> 两个不同的事，放一起因为都属于"别硬上"。
> 做法来源：建筑学长 `新户型稳定性测试.md` 的"首轮范围" + `SystemPrompt.md` 的"设备评估与降级"。

## 一、首轮范围：第一次跑就跑最小路径

| 维度 | 首轮只做 | 后续再做 | 不假装支持 |
|---|---|---|---|
| 输入格式 | 单张 PNG/JPG/WebP ≤15 MB | PDF（要先栅格化） | DWG/DXF 直接上传 |
| 风格 | 一种预设风格跑通 | 多风格切换 | 自定义风格进精细路径 |
| 图纸 | 一张图出到底 | 多图批量 | 全套图纸一次生成 |
| 底图 | 清晰、完整、有可辨尺寸 | 模糊、倾斜、遮挡 | 缺几何信息硬出 |

**规矩：首轮跑通之前，不许对外说"支持 X"。** 跑通了再说，而且要带版本号。

## 二、先例：一个真实的能力边界声明长什么样

> 培训 PPT 自己承认：**"通过三张图+三控制方式，能在除施工图外的剩余四类图纸中发挥重要的辅助应用"**——它把施工图排除在外。
> 但同一份 PPT 的 slide 28 又给了施工图 prompt。这两条是矛盾的。
> 我们的处理：施工图这一节改走 CAD 落图（见 [drawing-05-construction.md](drawing-05-construction.md)），位图施工图明确降级为"图面示意"。

**所以写边界时要检查：文档里有没有自相矛盾的承诺。**

## 三、设备降级 L0~L3（涉及本地模型/大显存/大磁盘时）

本机实测：**RTX 3060 Laptop 6 GB VRAM**、C 盘剩 5.3 GB、E 盘剩 871 GB。

| 等级 | 条件 | 策略 | 出图质量 |
|---|---|---|---|
| **L0** | VRAM ≥12 GB 或走云端 API | 全流程：SDXL/Flux 本地 + 双参考融合 | 客户级 |
| **L1** | VRAM 6~8 GB | SD1.5 + ControlNet；或只用云端 API 出图 | 可用，细节弱 |
| **L2** | VRAM <6 GB / 无 GPU | 纯云端 API，不做本地推理 | 取决于 API（本机属此档的上半：6 GB 可跑 SD1.5，但性价比不如 API） |
| **L3** | 无网络 + 无模型缓存 | 只做确定性处理：裁切/抠图/拼版/加标注 | 无 AI 出图 |

**本机定位：L1 偏 L2。** 出图主力是 DashScope API，本地只做确定性处理。

配套检查（动手前跑一遍）：

| 项 | 阈值 | 本机实测 |
|---|---|---|
| 磁盘剩余（模型+临时文件） | ≥ 模型大小 ×2 + 500 MB | E 盘 871 GB ✅ |
| 可用内存 | ≥ 模型大小 ×2~3 | — |
| VRAM | 见上表 | 6 GB |
| 网络可达 API | — | ✅ |

**原则**：评估不通过就降级，不硬上；下载 >100 MB 的模型前告知用户大小和存放位置；缓存复用优先。

## 四、每类产出的边界话术

| 产出 | 可以说 | 不可以说 |
|---|---|---|
| 白模 + 双参考效果图 | "视觉交付，几何对得上白模" | "尺寸准确，可量" |
| 彩平 → 鸟瞰 | "方向示意，布局已漂移" | "按方案出图" |
| 实景 → 改造 | "改造意向，结构可能被改" | "改造方案" |
| CAD 落图 | "几何与图层可核，规范未全自动校验" | "符合规范" |
| 位图施工图 | "图面排版示意" | "施工图" |

## 五、不知道就说不知道

- 甲方问尺寸 → 效果图的线不是施工线，不能量
- 问造价 → 不在能力内
- 问规范合规 → 只有 CAD 通用校验，无专业校验器
- 问"像不像这个项目" → 看照片相似度必须人判，脚本判不了
