# 反推描述词：从参考图反推风格 prompt

> 解决的缺口：8 个预设风格覆盖了常见需求，但**甲方给一张图说"按这个感觉"** 时没有词表。
> 对应原 App 的 E 类端点 `/ai/infer_description`（AI 反推描述词）与 `/ai/color_thief`（图片颜色提取）。

## 一、什么时候用

| 场景 | 用不用 |
|---|---|
| 甲方给参考图，说"就这个感觉" | ✅ 反推成结构化描述词 |
| 想做色彩板（palette）但要准 | ✅ 先提取色板再写风格 |
| 已有 8 风格之一 | ❌ 直接用 [index.md](index.md)，别绕 |
| 参考图是别人家的效果图 | ⚠️ 反推风格可以，**不要照抄构图与家具** |

## 二、反推流程（四步，必须看完图再写）

```
① 看：用可用的视觉模型读图（当前走 Google gemini-3-flash-preview），
      禁止用 cv2/OCR 去"分析"图像内容
② 拆：按 18 字段的结构拆解，不写散文
③ 配：提取 4 色板（主/辅/中/点），标注 HEX
④ 写：落成与 style/*.md 同构的条目，另存为 style/custom-<名字>.md
```

**读图模型要指定，且必须做抗幻觉验证**：
TP 白名单里 `qwen3.8-flash` / `qwen3.8-max` 实测能读图；`deepseek-v4.1` 返回 200 但会编（详见 [../known-issues.md](../known-issues.md) 第七节）。

实测读图质量（`viz/vl-probe.md`）：CAD 平面读出 10 个房间名（含"卫生间"两处）与 `7.20m²` 面积；
街景读出 POS / 拉卡拉 / 和平交易厅 / 大量电动车 / 架空电线。够写风格描述，但不能当几何依据。

## 三、拆解清单（对着图逐项填，缺的写"未见"）

| 字段 | 看什么 | 示例 |
|---|---|---|
| 标签 | 一眼能记住的三个词 | 胡桃木 · 哑光 · 低饱和 |
| 类别 | modern / natural | natural |
| 色板 | 取主色（大面积）、辅色（家具）、中间色（过渡）、点缀色 | `#e8e0d0 #76513a #bb8455 #303431` |
| 三个面 | 墙 / 地 / 顶 各一句 | 暖白哑光乳胶漆 / 温暖木纹地板 / 简洁暖白顶面 |
| 六个家具角色 | 沙发 / 椅 / 桌 / 柜 / 床 / 灯 各一句形态描述 | 低矮圆润软包，独立坐垫和靠背 |
| 材质 | 3~6 种，从具体到抽象 | 胡桃木、亚麻、焦糖皮革、少量哑黑金属 |
| 光 | 主光方向 + 色温 + 补光 | 柔和暖光为主，局部台灯，3000K |
| **负向** | **这张图刻意没做什么** | 不用全屋浅木；不用大面积金色与镜面 |

**负向清单是最容易漏也最重要的一项。** 看图时问自己：这张图如果换个人做，最容易做错成什么？那就是负向。

## 四、色板怎么取准

| 方法 | 做法 |
|---|---|
| 目测 | 只适合粗略；不要用它填 HEX |
| 取色脚本 | 用 Pillow 取区域众数色，比目测准 |
| 甲方品牌色 | 直接用品牌规范里的 HEX |

取到 HEX 后至少核对一次：把 4 个色块并排贴到图上，看是否像。

## 五、输出格式

新建 `style/custom-<slug>.md`，直接套用现有结构：

```markdown
# <风格名>（`custom-<slug>`）

| 项 | 值 |
|---|---|
| 标签 | … |
| 类别 | … |
| 色板 | 主 `#…` / 辅 `#…` / 中 `#…` / 点 `#…` |
| 光 | … |

**总述**：一句话。

## 三个面
（表：墙/地/顶）

## 六个家具角色
（表：沙发/椅/桌/柜/床/灯）

## 材质与配色
- 材质：…
- 家具色板：…

## 负向清单（写 prompt 时必带）
- …

## 来源
- 参考图：<路径>，反推时间 <日期>，反推人 <你>
```

**必须在"来源"里写清楚是反推的。** 反推 ≠ 甲方确认过的风格。

## 六、三条红线

1. **反推的是风格，不是方案。** 不要把参考图的布局、家具位置搬进本项目。
2. **反推结果必须标"未确认"**，交给甲方确认后才能当正式风格用。
3. **不许把别人的效果图当 `--ref` 直接融合。** 版权风险 + 构图污染。只取描述词，不取像素。
