# 验收与交付声明

> 核心原则：**看画面，不看返回值。**
> `success: true`、实体数量正确、文件已生成，都不说明位置、大小、比例对。

## 一、三查（每张图必做）

| # | 查什么 | 怎么查 | 不过怎么办 |
|---|---|---|---|
| 1 | **数主要元素** | 底图几个水体/几栋建筑/几处开口？成图逐一对照 | 重生成，或 [zoning-mask.md](zoning-mask.md) 局部修 |
| 2 | **数楼层/层数** | 改造与外观必查，模型最爱改这个 | 重生成；改不动就走合成法 |
| 3 | **对路网/开口** | 主干走向、连接关系、门窗洞口位置 | 重生成 |

三项任一不过 → **降级为意向图**，不得按可交付承诺。

## 二、按图种的验收清单

### 效果图

- [ ] 墙体、窗洞、开口位置与白模一致
- [ ] 家具落在白模占位轮廓上
- [ ] 无参考图中不存在的构件
- [ ] 窗外有景（不是全白）
- [ ] 无文字、水印、logo、边框
- [ ] 三查通过

### 总平面图

- [ ] 水体数量一致
- [ ] 建筑栋数一致
- [ ] 路网走向一致
- [ ] 图层分区可辨（绿地/水体/铺装/建筑）
- [ ] 无标注、图例、指北针残留

### 改造图

- [ ] mask 外像素未变（合成法可直接比对）
- [ ] 层数、体量、开间与原照片一致
- [ ] 接缝放大 200% 无硬边
- [ ] 合成区与保留区白平衡一致

### 施工图

- [ ] `validate_plan` 无 errors
- [ ] 预览图实看过，轮廓/布局/文字/尺寸自洽
- [ ] 有原图时 `_reference_review.json` 的 `status=passed`
- [ ] `export_data` 的实体数与图层数和计划对得上
- [ ] **每个图元的 Layer 是否正确**（图层不存在会静默落到 0 层）
- [ ] 已声明哪些专业规范未自动校验

## 三、交付声明怎么写

交付时必须附一段声明，模板：

```text
本批图共 N 张，交付定位如下：
- 可交付：<文件名>（依据：白模控制，三查通过）
- 仅意向：<文件名>（原因：<底图为彩平/实景，布局存在漂移>）
未自动校验项：<结构/水电/暖通等>
推断项：<从图推断的尺寸/层数等，未获确认>
```

不写声明 = 甲方默认全当可交付，后面全是返工。

## 四、失败案例库

> 以下都是本机实测翻车，最有参考价值。

| # | 场景 | 现象 | 根因 | 正确做法 |
|---|---|---|---|---|
| 1 | 手绘彩平 → 鸟瞰 | 水体 1 个变 2 个，建筑落位偏移 | 二维高密度输入，模型重排布局 | 逐区域描述 + 分区涂鸦 + 三查 |
| 2 | 街景实景 → 改造 | 层数体量全改，高层消失，画成重建 | 整图重绘无硬约束 | 涂鸦 + 生成后合成（mask 外不动） |
| 3 | 白模 → 室内效果图 | 窗外全白、多一块装饰板 | 单参考无质感依据、缺"不得新增"约束 | 双参考两段式 + 负向清单 |
| 4 | 白模 → 外观效果图 | 实墙被换成整面玻璃幕墙 | 未锁定立面材质 | prompt 明确"实墙保持为 X 材质" |
| 5 | 实景照片出图 | `DataInspectionFailed` 内容审核拦截 | 画面含可辨认招牌/人群 | 去掉人物与文字要求；仍失败则裁切/模糊招牌 |
| 6 | CAD 落图 | 图元全部落到 0 层，但 `success=true` | 目标图层不存在，静默回退 | 先建图层 → 画 → 用 `export_data` 核对 Layer |

## 五、什么时候必须停下来问用户

1. 没有几何控制图，但用户要求"可交付"
2. 三查连续两轮不过
3. 用户要拿效果图量尺寸
4. 施工图涉及结构/水电/暖通
5. 交付定位需要从"可交付"降级为"仅意向"

这五种情况不要自己拍板往下走。
