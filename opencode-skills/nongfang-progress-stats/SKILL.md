# 农房整治卷宗整改进展统计

把每天上报的**批次级明细表**汇总成**县区级报表**。真正容易出错的不是加减法，是口径：两套表的"完成""未缴"定义不一样，算错一次就会和上级台账对不上。所有口径已在 2026-10-29 的真实数据上逐格复现过人工表，直接跑脚本，不要手工重算。

## 一条命令

```bash
python "<skill>/scripts/update_stats.py" --dir "<业务目录>"
```

`<skill>` 是本技能目录，`<业务目录>` 是放 xlsx 的文件夹（例：`E:\2026卫片执法专项\20260212乱占耕地建房\进展\20261030`）。脚本自己找文件：

| 找什么 | 规则 |
|---|---|
| 来源明细表 | 文件名同时含 `NF` 和 `整改`，按文件名里的日期（如 `10.30`）取最新 |
| 报表模板 | 文件名含 `农房整治` 和 `统计表`，且不带 `_YYYYMMDD` 后缀 |
| 当日基线 | `<业务目录>\.nongfang_baseline.json` |
| 输出 | 模板同目录，`农房整治工作卷宗整改进展统计表_YYYYMMDD.xlsx` |

先跑 `--dry-run` 看数字对不对，确认后再去掉它写文件。

这条命令出的是**合并成一张**的报表（20 个县区）。如果要的是日报用的**两张拆分表**（未完成 / 已完成），用下一节的 `split_tables.py`，不要拿这里的结果手拆。

## 口径

这两套表的差异是全部坑的来源。**逐条照做，不要凭"看起来应该"改**：

| 报表列 | 算法 | 说明 |
|---|---|---|
| 卷宗总任务-批次 | 明细行数 | 一行 = 一个批次（不是项目名去重） |
| 卷宗总任务-图斑 | Σ 图斑数量（D 列） | |
| 累计完成-批次 | 满足"完成"的批次数 | 见下 |
| 累计完成-图斑 | 满足"完成"批次的图斑之和 | |
| 剩余任务 | 总数 − 累计 | |
| **未缴费** | **总图斑 − Σ实缴（F 列）** | 用户明确要求：以实缴为准 |
| 已缴费 | 剩余图斑 − 未缴费 | |
| 当日批次 | 本次累计批次 − 上次累计批次 | 上次值来自基线文件 |

**"完成"的判据**：`实缴 == 图斑数量`（该批次图斑全部缴清）。**只看实缴，不看备注列**——备注是人工写的，不可靠。28 号表里就有两处矛盾：武安市一行"图斑15/实缴14"却标了"已全部完成"，另一行"图斑11/实缴11"没标。按实缴算即可，不要拿备注去校正或报警。同理，未缴一律用 `总图斑 − Σ实缴`，不读来源表的"未缴"列。

**为什么不能直接加来源表的"未缴"列**：那一列是手填的，不是公式。2026-10-29 永年区有 5 行（第 40/43/44/47/49 行）填的比"图斑−实缴"大，合计虚高 6（1101 vs 1095），而人工报表写的是 1095。所以只能从"图斑数量"和"实缴"自己算。

**"已缴费"不是实缴本身**：实缴里含已完成批次的缴费，报表的"已缴费"只算剩余任务那部分，等于 `Σ实缴 − 累计图斑`（完成批次的实缴 = 图斑）。换一种写法还是同一条原则——**未缴 = 剩余图斑 − 已缴费**，这里的"总数"是剩余图斑，不是总图斑；两种算法结果一致（`图斑 − 实缴`）。例：磁县实缴 60、累计图斑 31 → 已缴费 29，未缴 2，29+2=31 正好是剩余图斑；直接把 60 写进去，29+2≠31 立刻露馅。

**为什么日均增量要用基线**：报表的"当日批次"是与上一次报数比出来的，不是表内能算出来的量。脚本每次运行后把各县区的累计值写进基线文件，下次运行做差。删掉基线文件不会算错，只会退回"本次 − 模板现有值"的口径。

## 输出

- 复制模板 → 填 C..K 列 → 更新 A1 标题为「（M月D日）」→ 另存新文件。**模板本身不动**，格式、合并单元格、列宽、行高、字体全部保留。
- 版式：数据区（第 5–25 行 A–L 列）统一 14 号字、行高 19.8、A4 横向、水平居中、缩到一页。这几个值在脚本顶部 `REPORT_FONT_SIZE` / `REPORT_ROW_HEIGHT` / `REPORT_MARGIN_INCH` 里，要改字号只动这里，别去改模板。
- 同时导出同名 PDF：优先走 Excel COM，失败退回 LibreOffice；两者都不可用时只告警，xlsx 照样是好的，不要因此重跑。
- 数值 0 写空，与原表习惯一致（如全完成的县区剩余列留空）。
- 基线文件同步更新。
- 历史文件按天堆在同一目录，不覆盖。

## 出日报

统计表做完，接着一句"出今天的日报"：

```bash
python "<skill>/scripts/make_daily_report.py" --dir "<业务目录>" --restored "<批次>,<图斑>"
```

产出两个文件：

- `农房整治工作卷宗整改工作日报MM.DD最终稿.doc` —— **只有正文 2 页**，不含附表
- `农房整治工作卷宗整改工作日报MM.DD最终稿.pdf` —— 正文 + 两页附表合并，共 4 页

| PDF 页 | 纸张 | 内容 | 来源 |
|---|---|---|---|
| 1–2 | A4 纵向 | 标题、期号、发文机关、四段情况、附注、联系人、报发、印发 | 日报 doc |
| 3 | A3 横向 | 附件1 省系统进度统计表（三层表头 19 列） | 通报 xls |
| 4 | A4 横向 | 附件2 农房整治卷宗整改进展统计表 | 统计表 xlsx |

附件由 Excel/Word 各自导出 PDF 后用 PyMuPDF 拼接，所以正文 doc 里没有表格，改文字也不会碰坏附表格式。

**它需要什么**

- 当天的统计表 xlsx（先跑 `update_stats.py`；"当日批次"那一段直接用它）
- 目录里**当天和前一天的**"通报"xls，文件名含 `通报` 和 `M.D`。脚本按日期自动配对，用来算"今日新增拆除 X 个地块、新增补办 Y 个图斑"
- `--restored 14,386`：恢复被扣减卷宗的批次和图斑。这个数在省系统表里没有对应列，是业务口径，必须由人给；不给就写【待填】

**格式要点**（照最终稿，别自己发挥）

- 正文仿宋_GB2312 16 磅、首行缩进 2 字、固定行距 26 磅
- `一、二、三、` 这些小标题用楷体，"截至目前"那段全仿宋
- 剩余任务段里的县名加粗，按批次整改率升序；零进展的县并成一句"均无进展"
- 整改率较高的取前 4、较低的取最低 3 个，**但按从高到低念**（27.94 / 26.17 / 18.36），不是升序
- 期号存在 `.nongfang_report.json`，每次自动 +1

同行并列时（几个县都是当日 1 个批次、或整改率相同）脚本的排列和人工稿可能有出入，那是人工微调，不影响数字。

## 一张明细表拆成两张统计表

日报要的是两张拆分表：`（未完成M.D）` 和 `（已完成）`。它们不是两份独立台账，**都从同一张 NF 明细表来**：

```bash
python "<skill>/scripts/split_tables.py" --dir "<业务目录>" [--adjust 永年区=4]
```

先 `--dry-run` 看拆分和合计，再写文件。

**拆分规则**：逐县汇总明细 → 剩余批次 = 0 的县进「已完成」表，> 0 的进「未完成」表。县区总数恒定（例：13 + 7 = 20），谁整改完就从左边挪到右边，脚本会自动增减行，不用手改模板。

**今日进展从上一期明细做差，不靠母版**：脚本自动找目录里日期早于当天、日期最大的那份 NF（`--nf-prev` 可指定），算「当日批次 = 今日累计批次 − 昨日累计批次」「今日收缴 = 今日 Σ实缴 − 昨日 Σ实缴」，并在控制台打印当日收缴的分县明细。`--adjust` 的补记只加在今天这一侧，所以补的 4 个会算进今日收缴。找不到上一期明细时才退回用母版累计值做差，并告警。

**各列从哪来**（这是两张表唯一容易混淆的地方）：

| 列 | 未完成表 | 已完成表 |
|---|---|---|
| 批次 / 图斑 / 累计 / 剩余 / 已缴 / 未缴 | 全部由明细汇总算出 | 该表没有这些列，只在 P 列留该县的卷宗图斑数 |
| 图斑总个数、已整改、未整改、整改比例 | — | 当日省系统通报（`图斑总个数`=第1列、`整改总个数`=第24列） |
| 拆除类 总数 / 已整改 / 未整改 / 今日进展 | — | 通报第 12、13 列；今日进展 = 与前一日的差 |
| 拟补办 总数 | — | `未整改 − 拆除未整改`（算术推导，通报里没有现成列） |
| 拟补办 已缴费 / 今日进展 | — | **不在明细里**：默认沿用母版，或用 `--fees 台账.xlsx`（县区/已缴费/今日进展）。今日进展 = 今天已缴费 − 昨天已缴费，但**已缴费这个基准数**在明细和通报里都没有，所以才要台账；这是拟补办卷宗的开垦费口径，不等于明细里的实缴——冀南新区实缴 35 而这里写 43；邱县实缴 100、拟补办总数只有 79，套实缴会算出未缴 −21 |

**补记实缴**：县区报上来但还没落进明细的缴费，用 `--adjust 永年区=4` 补，可重复。脚本把它加进实缴后重算未缴，并在输出里打印 `补记实缴：永年区+4`，便于事后对账。不要直接改明细表原件。

**母版与输出**：`--unfinished-master` / `--finished-master` 指定版式母版（默认取目录里最新的同名表），`--out-unfinished` / `--out-finished` 指定输出。默认输出就是母版本体（同一天重跑覆盖），跨天时把前一天的表留作母版、输出写新日期文件。行顺序、县区显示名、合并单元格、列宽、字体都从母版继承。

**会提示但不拦**：通报卷宗图斑与明细图斑不一致（说明两份材料不是同一天）、已完成表某县在通报里查不到、已缴费列沿用母版。

## 校验与告警

**会直接拒绝生成（退出码 2）的情况**——这些都会产出错数，不能算出来给你看：

| 情况 | 为什么必须拦 |
|---|---|
| 图斑数 / 实缴数填空、写成 `--`、写成非数字 | 当 0 用会让总数悄悄变少，报表上看不出来 |
| 某批次实缴 > 图斑数 | 未缴费会算出负数 |
| 来源表合计行 ≠ 明细求和 | 说明有明细行没读进来，或合计行是旧的 |
| 表内县区之和 ≠ 全市合计 | 来源表的县区名在模板里找不到对应行，数据落不了表 |
| 省系统表与统计表的图斑总数对不上 | 两份材料不是同一天，日报会自相矛盾 |

确认后要强行通过，分别加 `--allow-dirty` / `--allow-mismatch`。

**只提示不拦的**：任务口径变化（总批次/图斑比上期变了）、来源表"未缴"列与实缴口径不一致（属正常）、累计值比上次小（数据回退，当日按 0）。

跑完把**告警原文**告诉用户，不要自己判断"应该没事"。

## 自检与追溯

- **写完回读**：xlsx 存盘后重新打开，逐格核对合计行、每个县区的总批次和累计图斑、以及数据区字号。对不上直接退出码 3——不信任"保存成功"等于"写对了"。
- **审计日志**：每次运行往 `.nongfang_history.jsonl` 追加一行，记录时间、用了哪个来源文件、生成了什么、关键数字、告警条数。出问题可以直接翻。
- **恢复被扣减卷宗会沿用上期**：不传 `--restored` 时，脚本从更早一期日报的 PDF 里读"恢复被扣减卷宗 X 个批次涉及 Y 个图斑"。找不到才留【待填】。

## 重复运行是安全的

- **基线按日期存快照**（保留 40 天）。同一天跑十次，"当日批次"都用同一个"上一个不同日期"的基准算出同一个结果，不会第二次就变成 0。
- **统计表同日覆盖**同名文件，不会堆出 `_1743` 这种副本。
- **期号同日不变**，跨天才 +1。

改完来源表发现算错了，直接重跑就行，不需要清理任何文件。

## 收尾时向用户报告

- 一行合计：总批次/图斑、累计、剩余、已缴/未缴、当日新增批次
- 完成率（批次、图斑两个口径）
- 当日有新增的县区
- 输出文件完整路径
- 所有告警

## 参数（update_stats.py）

| 参数 | 用途 |
|---|---|
| `--dir` | 业务目录，一个参数搞定全部路径 |
| `--source` / `--template` | 手工指定某个文件，覆盖自动发现 |
| `--out-dir` | 输出到别处 |
| `--date YYYY-MM-DD` | 覆盖从文件名推断的数据日期 |
| `--baseline` | 指定基线文件 |
| `--dry-run` | 只算不写 |
| `--no-pdf` | 只出 xlsx，不导 PDF |
| `--allow-dirty` | 图斑/实缴填空写错时仍按 0 继续（默认拒绝生成） |
| `--reset-baseline` | 忽略历史快照，用模板值当日基线（换月、重报时用） |
| `--allow-mismatch` | 两源图斑数不一致时仍继续（仅日报脚本） |

- **报错"表结构可能变了"**：来源表列位置被调整过。先打开表确认 D=图斑数量、F=实缴、B=县区、O=备注仍在原位，再改脚本顶部常量。不要临时改口径凑数。
- **某县区当天没数据**：脚本会保留模板行但置空，并告警。这种情况要问用户是不是漏报了，不要直接发布。
- **新增了县区**：脚本告警「模板中无对应行」，需要在模板里加一行（保持 A 列序号、B 列县区名、其余格式照抄上一行）。
- **控制台中文乱码**：先 `chcp 65001`，或把输出重定向到文件再用 UTF-8 读。

`split_tables.py` 的参数写在上面「一张明细表拆成两张统计表」一节里，两者不共用。

更细的数据核对过程见 `references/口径核对.md`。
