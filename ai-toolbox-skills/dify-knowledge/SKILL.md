# Dify 知识库检索 Skill

从 Dify 知识库检索文档片段，并基于检索结果完成两类任务：

1. **简单问答**：直接回答具体问题。
2. **长文生成**：生成方案、技术设计书、调研报告、实施方案、技术总结等结构化文档。

## 使用前检查

先检查以下环境变量是否已配置；未配置时，不要盲目发起检索，先告知用户缺失项。

- `DIFY_API_BASE_URL`：Dify 服务地址，例如 `http://127.0.0.1/v1`
- `DIFY_API_KEY`：以 `dataset-` 开头的 API Key
- `DIFY_DATASET_POLICY`：知识库 1（政策标准）ID
- `DIFY_DATASET_INTERNAL`：知识库 2（院规章制度）ID

可选能力：

- 若需要额外生成 `.docx` 文件，环境中还应具备 Python 和 `python-docx`
- 若上述依赖不存在，默认只输出 Markdown，不要因为 `.docx` 缺失而让整个任务失败

## 安全要求

- 不要在回答中泄露 `DIFY_API_KEY` 的实际值。
- 不要把 API Key、dataset ID、个人用户名、固定下载路径写死到输出文档中。
- 不要假设当前机器一定是 macOS；默认按当前系统决定保存路径。
- 若服务不可用、鉴权失败或结果为空，要明确告知用户原因，不要伪造内容。

## 知识库分类

- **知识库 1（政策标准）**：`DIFY_DATASET_POLICY`
  - 内容：国家标准（GB）、行业标准（CH/T）、政策法规、乡村振兴用地政策等外部标准规范

- **知识库 2（院规章制度）**：`DIFY_DATASET_INTERNAL`
  - 内容：企业内部管理制度、质量管理规定、技术规范、生产经营管理等院级规章制度

## API 调用

### 检索命令示例

```bash
# 知识库 1（政策标准）检索
curl -s -X POST "${DIFY_API_BASE_URL}/datasets/${DIFY_DATASET_POLICY}/retrieve" \
  -H "Authorization: Bearer ${DIFY_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "用户问题",
    "retrieval_model": {
      "search_method": "semantic_search",
      "top_k": 5,
      "score_threshold_enabled": true,
      "score_threshold": 0.15
    }
  }' \
  --connect-timeout 10 \
  --max-time 60

# 知识库 2（院规章制度）检索
curl -s -X POST "${DIFY_API_BASE_URL}/datasets/${DIFY_DATASET_INTERNAL}/retrieve" \
  -H "Authorization: Bearer ${DIFY_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "用户问题",
    "retrieval_model": {
      "search_method": "semantic_search",
      "top_k": 5,
      "score_threshold_enabled": true,
      "score_threshold": 0.15
    }
  }' \
  --connect-timeout 10 \
  --max-time 60
```

### 返回格式

正常响应通常包含 `records` 数组；每条记录至少关注：

- `segment.content`：检索到的正文片段
- `score`：相关性分数

如果返回错误对象或 `records` 不存在，视为失败，不进入正常生成流程。

## 默认参数

- `top_k = 5`
- `score_threshold = 0.15`
- 简单问答：按 score 排序后优先使用高分片段
- 长文生成：聚合时优先使用高分片段；若某一章没有足够支撑内容，明确标注“内容不足”

## 工作流程

### 第一步：判断任务模式

收到用户请求后，先判断是简单问答还是长文生成。

| 模式 | 识别特征 | 示例 |
|------|---------|------|
| **简单问答** | 问题具体、期望简短回答 | “婚假几天？”、“GB/T 18315 的高程精度是多少？” |
| **长文生成** | 涉及多方面、需要结构化文档 | “帮我写一份技术设计书”、“基于知识库生成调研报告” |

长文生成高频触发词：`写一份`、`生成`、`编制`、`撰写`、`调研报告`、`技术设计书`、`技术方案`、`实施方案`、`技术总结`、`工作方案`

### 第二步：选择知识库

#### 简单问答

根据问题内容判断查询哪个知识库：

| 问题类型 | 典型关键词 | 优先查询 |
|---------|-----------|---------|
| 院内部管理 | 公司制度、质量管理、技术规定、生产制度、绩效考核、岗位职责、报销、请假 | 知识库 2 |
| 技术规范标准 | 国标 GB、行业标准 CH/T、规范、规程、测绘规范 | 知识库 1 |
| 用地政策 | 土地审批、用地政策、征收、农用地转用、乡村振兴用地 | 知识库 1 |
| 测绘技术 | 航测、遥感、控制测量、地形图、RTK、GPS | 知识库 1 |
| 管理制度 | 员工手册、考核、资质、认证、ISO | 知识库 2 |
| 不明确/综合 | 两个库关键词都有，或无明确指向 | 两个库都查 |

#### 长文生成

- 默认仅查询 **知识库 1（政策标准）**
- 如果用户明确要求写“院内制度、内部管理办法、考核制度、报销制度、岗位职责”等内部制度长文，可改为查询 **知识库 2**
- 如果主题同时涉及外部标准与内部制度，先向用户确认文档侧重点；若用户未明确，优先选择最贴近文档主题的一个库，不要盲目双库混写

### 模式一：简单问答

1. 选择对应知识库（或两个都查）
2. 发起检索请求
3. 过滤低分内容，按 score 排序
4. 用高分片段直接回答，并标注来源知识库
5. 若检索为空或分数普遍偏低，明确说明“知识库未命中足够可靠的内容”

### 模式二：长文生成

#### 第零步：确认字数目标

开始检索前，先与用户确认目标字数。

| 档位 | 建议字数 | 说明 |
|------|---------|------|
| 简要版 | 1500~3000 字 | 适用于内部汇报、快速参考 |
| 标准版 | 5000~8000 字 | 适用于正式方案、常规设计书 |
| 详尽版 | 10000~20000 字 | 适用于完整技术设计书、深度调研报告 |

若用户未指定字数，询问：

> 这份文档你希望大概多长？可选简要版（1500~3000 字）、标准版（5000~8000 字）、详尽版（10000 字以上），也可以直接告诉我目标字数。

用户确认后，再进入检索阶段；不要跳过这一步。

#### 第一轮：主题拆解

把主题拆成 3 个检索 query，尽量覆盖：

- 是什么
- 怎么做
- 标准/依据/成果要求

可根据文档类型增加维度：

- 院规章制度类：管理制度 / 考核要求
- 技术设计书类：技术规范 / 质量要求

检索前向用户同步：

> 正在拆解主题并构建 3 个检索词。

#### 第二轮：逐个检索

对 3 个 query 依次检索：

1. 向目标知识库发送检索请求
2. 收集返回记录
3. 去重
4. 保留 `score >= 0.15` 的片段

每个 query 完成后同步进度，例如：

- 已完成第 1 个检索词，找到 X 条相关片段
- 已完成第 2 个检索词，找到 X 条相关片段
- 已完成第 3 个检索词，找到 X 条相关片段

全部完成后同步：

> 检索完成，共收集到 X 条相关内容，正在整理文档结构。

#### 第三轮：内容聚合与结构推断

##### 步骤 1：内容聚类

- 按主题相近程度分组片段
- 每组提炼一个核心议题，作为候选章节

##### 步骤 2：推断文档结构

按文档类型选择最接近的框架，再根据内容聚类结果微调：

- 院规章制度：总则 → 管理职责 → 工作流程 → 考核要求 → 附则
- 技术设计书：背景与依据 → 技术路线 → 作业流程 → 质量保障 → 成果要求
- 调研报告：调研背景 → 现状分析 → 问题梳理 → 对策建议
- 技术方案：项目概述 → 技术路线 → 实施计划 → 保障措施

若某章节缺乏足够内容支撑，明确写明：

> 本节内容知识库暂无足够收录，建议补充 XXX 方面资料。

判断“内容不足”的参考标准：

- 该章节没有任何 `score >= 0.15` 的可用片段；或
- 只有 1 条片段且信息明显不足以支撑成段表达

结构确定后向用户同步：

> 文档结构已确定，共 X 章，正在撰写内容。

##### 步骤 3：内容填充

- 每章优先选取 score 最高的 2~3 条片段
- 对碎片化内容做适度整合，保证段落连贯
- 不要编造知识库中没有的事实
- 根据字数目标调整详略：
  - 简要版：4~5 个核心章节，每节 200~400 字
  - 标准版：完整章节结构，每节 500~1000 字
  - 详尽版：详细展开，每节约 1500~3000 字

#### 第四步：文档输出与保存

先生成 Markdown；若环境满足条件，再额外生成 `.docx`。

##### Markdown

- 默认必须生成 `.md`

##### Word（可选增强）

仅在以下条件都满足时再生成 `.docx`：

1. 当前环境存在 Python
2. 已安装 `python-docx`
3. 用户确实需要 Word 文件

若条件不满足，明确告知：

> 当前环境未检测到可用的 Word 生成依赖，已先输出 Markdown 版本。

##### Word 文档格式化

使用 `scripts/docx_formatter.py` 脚本生成符合 CH/T 1004-2005《测绘技术设计规定》规范的 Word 文档：

```bash
# 基本用法
python <技能目录>/scripts/docx_formatter.py input.md output.docx

# 完整参数
python <技能目录>/scripts/docx_formatter.py input.md output.docx \
  --title "技术设计书标题" \
  --subtitle "副标题" \
  --project "项目名称" \
  --author "编制单位" \
  --date "2024年12月"
```

脚本功能：
- 规范的封面设计（项目名称、标题、编制单位、日期）
- 自动目录生成
- 符合测绘规范的字体字号（标题黑体、正文宋体）
- A4 页面设置（21cm × 29.7cm）
- 1.5 倍行距
- 表格样式（表头加粗、灰色背景）
- 页眉页脚（文档标题 + 页码）

##### 保存路径

- Windows：优先保存到 `C:/Users/<当前用户名>/Downloads/`
- macOS：优先保存到 `/Users/<当前用户名>/Downloads/`

`<当前用户名>` 应按当前系统动态获取，不要写死具体用户名。

##### 文档开头说明

- 明确列出数据来源（来自哪个知识库）
- 标注知识库覆盖度（哪些章节内容充实、哪些需要补充）
- 说明文档性质（草稿 / 参考稿 / 正式稿）

## 错误处理

### 配置缺失

若缺少任何必需环境变量：

- 不发起检索
- 直接告知缺失的变量名
- 引导用户参考 `USAGE.md` 配置环境变量

### 鉴权失败 / 权限不足

常见表现：HTTP 401 / 403

- 提示用户检查 `DIFY_API_KEY`
- 不继续生成内容

### 知识库不存在

常见表现：HTTP 404

- 提示用户检查 `DIFY_DATASET_POLICY` 或 `DIFY_DATASET_INTERNAL`
- 不继续生成内容

### 服务不可用 / 超时

常见表现：超时、HTTP 5xx、连接失败

- 告知用户 Dify 服务异常
- 可以建议稍后重试
- 不要伪造检索结果

### 空结果或低质量结果

- 若 `records` 为空：直接说明知识库未命中相关内容
- 若结果存在但分数普遍偏低：可输出“检索摘要”或“草稿框架”，但要明确说明可靠性有限

## 注意事项

- 若需要本地部署环境，请优先使用环境变量，而不是把配置写入技能正文
- `top_k` 与 `score_threshold` 是默认值；若召回噪声过大，可谨慎调高阈值
- 长文生成时，优先保证内容真实可追溯，再追求篇幅完整
- 文档仅作知识库辅助草稿，最终正式稿仍需人工复核
- Windows 环境优先参考同目录下的 `USAGE.md`
